## 4. Implementation details

### 4.1 ลบ ID ที่ยังค้างในหน้าจอ
- หัว drawer ใช้ชื่อ: "Edit Charming Iconic Glow" (ไม่ใช่ "Edit CH") · "New phase · New Campaign Test1"
- ลบข้อความ "ID will be …" ทุกที่
- ชื่อ Phase ในตาราง / timeline / dropdown / หัวกลุ่ม Deals แสดง `Phase 1 · Launch` (ไม่มี "NC-P1", "PH-P3", "AC-P1" ต่อท้าย)
- Combobox Campaign แสดงชื่ออย่างเดียว (ไม่มี "NC · ")
- ตรวจด้วยการค้น regex `\b[A-Z]{2,4}-P\d+\b|\b[A-Z]{2,3} · ` ใน DOM ที่ render (ยกเว้นไฟล์ export) — ต้องไม่เจอ

### 4.2 New Phase แบบระบุจำนวน + Running number (Phase Planner)
**ขั้นตอนใน Planner** (แทนการกด + Add phase ทีละแถวเป็นวิธีหลัก)
1. **Campaign period** (ช่วยวางแผน — ไม่บังคับ): Start / End
2. **Number of phases:** ช่องตัวเลข 1–12 พร้อม − / + · ใส่ 3 → สร้าง 3 แถวทันที
   - เพิ่มจำนวน → เพิ่มแถวท้าย · ลดจำนวน → ลบแถวท้ายที่ยังว่าง/ยังไม่มีโพสต์ · ถ้าแถวที่ต้องลบมีโพสต์ → Error "Phase 3 has posts — can't remove"
   - ถ้ามี Campaign period: แบ่งวันให้เท่ากันอัตโนมัติ (ต่อกันไม่ทับ ไม่เว้น) · ปุ่ม `Split dates evenly` ใช้กดซ้ำได้หลังแก้ period
3. **Budget allocation:** ตารางแถวละ Phase: `Phase` · `Label` (optional) · `Start` · `End` · `Days` · `%` · `Amount`
   - presets: `Even` (หารเท่ากัน · เศษให้แถวสุดท้าย) · `Launch-heavy 20 / 65 / 15` (แสดงเมื่อ 3 Phase) · `Custom`
   - แก้ % แล้ว Amount คำนวณจากงบ Campaign (และกลับกันถ้าโหมด ฿) · Budget bar + Over budget confirm ตาม CR-05
4. Validation / Impact preview / Save ตาม CR-05 §4.4

**Running number**
- ชื่อที่แสดง = `Phase {seq}` + ` · {label}` ถ้ามี label · `seq` = ลำดับตาม `start_date` (ถ้าวันเริ่มเท่ากันใช้ end_date แล้วใช้ลำดับที่สร้าง)
- ในตาราง Planner เรียงแถวตาม start ทันทีที่แก้วันที่ (แถวกระโดดไปตำแหน่งใหม่พร้อม highlight 1 วินาที) และ seq เปลี่ยนตาม
- ผู้ใช้ไม่พิมพ์ชื่อ "Phase n" เอง — พิมพ์ได้เฉพาะ Label
- เพิ่ม Phase ภายหลังที่ start อยู่ก่อน Phase เดิม → Phase เดิมเลื่อนเลขให้อัตโนมัติ (แจ้งใน Impact preview: "Phase 2 will become Phase 3")
- export CSV: `phase_name` = ชื่อที่แสดง, `phase_seq`, `phase_label`

### 4.3 Campaign Products
**Product catalog — Settings › Products** (admin + KOL Manager)
- ตาราง: TR code · Product name · Variant · Used in campaigns · Active
- `+ Add product` · แก้ / ปิด active (ลบไม่ได้ถ้าถูกใช้) · **Import CSV** (คอลัมน์ `tr_code, product_name, variant` — ใช้ไฟล์ export จาก TRCLOUD) พร้อม preview: new / update name / duplicate
- tr_code ห้ามซ้ำ · product_name บังคับ

**Campaign › Products** (ใน Phase Planner ส่วน Campaign และใน Campaign drawer)
- Multi-select combobox ค้นจาก TR code หรือชื่อ · แสดง "TR code · Product name · Variant"
- ไม่เจอ → `+ New product` (กรอก TR code + ชื่อ แล้วเพิ่มเข้า catalog และ Campaign ทันที)
- **New campaign: ต้องมีสินค้าอย่างน้อย 1 รายการ (Error)**
- Campaign เดิมที่ยังไม่มีสินค้า: Warning chip "No products" ในตาราง Campaign & Phase + คิว **"Campaign without products"** ใน Dashboard › Operations
- เอาสินค้าออกจาก Campaign ไม่ได้ถ้ามี deal เลือกสินค้านั้นอยู่ (tooltip บอกจำนวน deal)

**Deal › Products** (section Deal info แทนช่อง TR codes เดิม)
- เลือกได้เฉพาะสินค้าของ Campaign ของ deal · แต่ละรายการมี `qty` (default 1) · แสดงเป็นรายการ "Product name · Variant × qty"
- ไม่บังคับใน CR นี้ (Info "No products selected" เมื่อถึง Brief)
- Template view / export แบบ Template: คอลัมน์ `TR Code` = รายการ tr_code คั่นด้วยขึ้นบรรทัด (ตาม Template เดิม) · Export Deals CSV เพิ่ม `products` (tr_code×qty)
- Dashboard › By campaign › Summary: บรรทัดเล็กใต้ Posts card "Products: n items · m units planned" (ไม่ต้องมีกราฟ)

### 4.4 KOL Performance (ดูว่า KOL ลงงานตรงเวลาไหม)
**นิยาม** — `rules.kolPerformance(kolId, data, settings)` ใช้เฉพาะ deal ที่ไม่ Cancel

| Metric | สูตร |
|---|---|
| **On-time rate** | โพสต์ที่ `post_date ≤ expected_post_date + grace` ÷ โพสต์ที่มีทั้ง post_date และ expected_post_date (grace = 1 วัน ตั้งได้) |
| **Avg delay** | ค่าเฉลี่ย (post_date − expected_post_date) ของโพสต์ที่ช้า (วัน) |
| **Late posts** | จำนวนโพสต์ที่ช้าเกิน grace |
| **Overdue now** | โพสต์ที่ expected_post_date เลยแล้ว แต่ยังไม่มี post_date |
| **Avg draft rounds** | ค่าเฉลี่ย `draft_rounds` ของ deal ที่ Complete |
| **Completion** | deal Complete ÷ deal ทั้งหมด (ไม่นับ List) |
| **Avg views / post · ER · CPV** | จากโพสต์ที่มี views (นิยามเดียวกับ CR-03) |

**Reliability badge** (ใช้ On-time rate)
- `Reliable` ≥ 90% · `Watch` 70–89% · `Late` < 70% · `Not enough data` ถ้าโพสต์ที่วัดได้ < 2 (ตั้งได้)
- สี chip: Reliable เขียวจาง · Watch เหลืองจาง · Late แดงจาง · Not enough data เทาขอบ — ต้องมีข้อความกำกับเสมอ (ห้ามใช้สีอย่างเดียว)

**แสดงผล**
- KOL Master table: เพิ่มคอลัมน์ `On-time` (badge + % เช่น "Reliable · 100%") และ `Last worked` (§4.5) · sort ได้
- KOL drawer: section ใหม่ **Performance** (อยู่ก่อน History): ตัวเลขตามตาราง metric + ตารางย่อยโพสต์ที่ช้า (Campaign › Phase · platform icon · expected · posted · +n days)
- ⓘ popover อธิบายสูตรและ grace
- Deals › Add to phase / New deal: ตอนเลือก KOL แสดง badge reliability ข้างชื่อ (ช่วยตัดสินใจ)
- Settings › KOL performance: grace days · minimum posts

### 4.5 Last worked filter
- `rules.lastWorked(kolId)` = วันที่ล่าสุดของ (post_date ของโพสต์ใน deal ที่ไม่ Cancel) · ถ้าไม่มีโพสต์ที่มีวันที่ ใช้ expected_post_date ล่าสุด · ถ้าไม่มี deal ที่ไม่ Cancel = Never
- KOL Master › toolbar เพิ่ม dropdown **Last worked**: All · Last 3 months · 3–6 months · 6–12 months · Over 1 year · Never worked
  - ช่วงนับจาก today (3 months = 91 วัน · 6 months = 182 วัน · 12 months = 365 วัน)
- คอลัมน์ Last worked: วันที่ dd/mm/yyyy + ข้อความเทา "12 days ago" · Never = "—"
- Bulk shortlist (CR-02) ใช้ร่วมกับ filter นี้ได้ (เช่น เลือก KOL ที่ไม่ได้ใช้ 6–12 เดือนมา shortlist ใหม่)

### 4.7 Pipeline — Drag & drop เพื่อ Move stage
- ลากการ์ดไปวางที่คอลัมน์ขั้นอื่น = เรียก Move stage (CR-02 §4.2) ไปยังขั้นนั้น
  - ขั้นถัดไปตามแผน (ไปข้างหน้า 1 ขั้น · ไม่ต้องใส่ note): ย้ายทันที + เติม date_field เป็นวันนี้ + toast "Moved to Approve Draft 1 · Undo" (Undo 5 วินาที)
  - กรณีที่ต้องกรอกเพิ่ม (ถอยหลัง → note · ไป Cancel → reason · ไป Confirm QT ขึ้นไปโดยยังไม่มี pillar → pillar · ข้ามหลายขั้น → ยืนยัน · ไป Draft เกินแผน → "+ Add draft round") → เปิด Move stage dialog ที่กรอกขั้นปลายทางไว้แล้ว · กด Cancel ใน dialog = การ์ดกลับที่เดิม
  - ไป **Post** ทั้งที่โพสต์ยังไม่ครบ → drop ไม่ได้ (คอลัมน์ขึ้นกรอบแดง + tooltip "1 post missing link/date")
- ขณะลาก: คอลัมน์ที่วางได้ = กรอบเส้นประสี primary · วางไม่ได้ = จาง + ไอคอนห้าม · คอลัมน์ที่ยุบอยู่ (0 deal) ขยายชั่วคราวเมื่อการ์ดลากผ่าน
- สิทธิ์: ลากได้เฉพาะ role ที่ Move stage ได้ (Viewer ลากไม่ได้ · cursor ปกติ)
- คีย์บอร์ด / มือถือ: เมนู ⋯ บนการ์ด → "Move to…" (รายการขั้นตามแผน)
- **ไม่มีการลากเปลี่ยน Phase** (Phase มาจากวันที่โพสต์ — CR-03)
