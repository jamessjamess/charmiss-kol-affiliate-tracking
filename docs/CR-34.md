# CR-34 — Partner Grade · Benchmarks · Partners dashboard

ใช้กติกาถาวรใน CLAUDE.md · คะแนนทุกที่มาจาก `rules.gradeEngine` ตัวเดียว

## 1. คำศัพท์
| คำ | ความหมาย |
|---|---|
| **Tier** | ขนาดผู้ติดตาม Mega / Macro / Mid-tier / Micro / Nano (เดิม · ไม่เปลี่ยน) |
| **Grade** | คุณภาพผลงาน **A Excellent · B Good · C Needs improvement · D Do not rehire** (ใหม่) |
| Suggested grade | เกรดที่ระบบคำนวณ |
| Confirmed grade | เกรดที่คนยืนยันแล้ว (ใช้แสดงทุกที่) |

## 2. เดิม → ใหม่
- คอลัมน์ "Performance" ใน KOL Master ("Reliable · 100%" = ตรงเวลา) → **Grade** (on-time ย้ายไปอยู่ใน tooltip / คะแนน Operation)
- Metrics D+7 (CR-11) มีแค่ Views / Likes / Comments / Saves / Shares → + **Reach · Impressions · Clicks** + **ที่มาของตัวเลข** (Auto / Import / Manual)
- Campaign ไม่มีเป้าวัดผล → **Benchmarks ต่อ Pillar** ใน Phase Planner
- ไม่มีที่บันทึกปัญหาการทำงาน → **Incident** ใน Deal modal
- ไม่มีภาพรวมคุณภาพ KOL → **Dashboard › Partners**

## 3. Spec

### 3.1 Benchmarks (Campaign › Phase Planner · ส่วนใหม่ "Benchmarks")
| Pillar | ช่อง | ตัวอย่าง (Charming Iconic Glow) |
|---|---|---|
| Awareness | **CPM benchmark (฿ per 1,000 reach)** | ฿15 |
| Consideration | **Consideration rate benchmark (%)** · Cost per consideration (คำนวณ = CPM ÷ (1,000 × rate) · แก้ทับได้) | 1% → ฿1.50 |
| Conversion | **ROAS target** | 3.0 |
| Affiliate | **ROAS target** (ใช้ตอน partner = Affiliate) | — |
| Campaign KPI | **% of clips beating benchmark** (เป้า · default 20%) | 20% |
- ไม่บังคับตอนสร้าง · Campaign ที่ไม่มี benchmark → ใช้ค่า default ใน Settings › Grades · ไม่มีทั้งคู่ = คิดเฉพาะคะแนน Operation
- Consideration actions = **Likes + Comments + Shares + Saves** (default · เลือกเพิ่ม Clicks / Profile visits ได้ใน Settings)

### 3.2 Metrics ต่อโพสต์ (Deal modal › Shipments & posts › Post)
- ช่อง: Reach · Impressions · Views · Likes · Comments · Shares · Saves · Clicks · (Conversion / Affiliate) Sales ฿ · ROAS
- **ที่มา** ต่อชุดตัวเลข: `Auto` · `Import` · `Manual` + วันที่เก็บ · ป้ายเล็กข้างตัวเลข
- รอบเก็บ: **D+7** (หลัก) · D+30 (optional)
- **Import CSV** (Deals › ⋯ › Import metrics): คอลัมน์ Post link หรือ Deal ID · ตัวเลขข้างบน · ตรวจซ้ำ / จับคู่ไม่ได้ → รายงานแถวที่ข้าม · ใช้กับไฟล์จาก TikTok One / Ads Manager / Spark Ads ที่จัดคอลัมน์แล้ว (มี template ให้ดาวน์โหลด)
- **Import ยอดขาย** (จากทีมขาย): Deal ID หรือ Account + Campaign · Sales ฿ · ROAS · ช่วงวันที่
- ค่าที่ `Manual` **ไม่ถูกทับ** โดย Import / Auto (ถาม "Replace manual values?")
- phase 2 (เตรียมไว้): `fetch_status` (`ok | failed | blocked`) · `fetched_at` · แถวที่ failed ขึ้นงาน "Enter metrics manually"

### 3.3 คะแนน (`rules.gradeEngine`)
**Performance ต่อโพสต์** (ratio > 1 = ดีกว่า benchmark)
| Pillar ของ deal | ratio |
|---|---|
| Awareness | CPM benchmark ÷ CPM จริง (CPM = Total cost ÷ Reach × 1,000) |
| Consideration | CPCons benchmark ÷ CPCons จริง (CPCons = Total cost ÷ consideration actions) |
| Awareness & Consideration | ค่าเฉลี่ยของ 2 ratio |
| Conversion / Affiliate | ROAS จริง ÷ ROAS target |
| Not set | ใช้ Default pillar ของ Phase · ไม่มี = ไม่คิด Performance |

**Operation ต่อ deal** (0–100): ส่ง Draft / Post ตรงเวลา (เทียบ Due) 50 · จำนวนรอบแก้ (1 รอบ = เต็ม · ลด 15 ต่อรอบเกิน) 30 · ไม่มี Incident 20

**Grade ต่อ partner** — จากโพสต์ล่าสุด **6 โพสต์ภายใน 6 เดือน** (ตั้งได้)
| Grade | เงื่อนไข (default · Settings › Grades) |
|---|---|
| **A** | Performance ratio เฉลี่ย ≥ 1.25 (ดีกว่า benchmark ≥ 20%) **และ** Operation ≥ 85 |
| **B** | ratio ≥ 1.0 **และ** Operation ≥ 70 |
| **C** | ratio ≥ 0.7 หรือ Operation ≥ 50 (ไม่เข้า A / B) |
| **D** | ratio < 0.7 **หรือ** Operation < 50 **หรือ** มี Incident ร้ายแรง (No-show / Breach) |
- น้ำหนักเมื่อมีทั้ง 2 ด้าน: Performance 60 · Operation 40 (ใช้จัดลำดับในตาราง) · เกณฑ์เกรดใช้ตามตารางข้างบน
- **< 2 โพสต์ที่มีข้อมูล** = "Not enough data" (ไม่ให้เกรด)
- ไม่มี metrics เลย → เกรดจาก Operation อย่างเดียว · ป้าย "Ops only"
- Affiliate คิดด้วย ROAS · แสดงแยกกลุ่มกับ KOL

### 3.4 Incident (Deal modal › History · ปุ่ม `+ Incident`)
- ประเภท: Late without notice · Missed brief · No-show · Breach of agreement · Other · Note · วันที่
- No-show / Breach = ร้ายแรง → Suggested D ทันที

### 3.5 Grade review
- เมื่อ Suggested ≠ Confirmed (หรือมีเกรดครั้งแรก) → เข้า **Grade review queue** (Dashboard › Partners และ Operations · งาน "Review grade" เฉพาะ KOL Manager / Admin)
- การ์ดรีวิว: Suggested · Confirmed เดิม · เหตุผลหลัก ("CPM ดีกว่า benchmark 25% · ตรงเวลา 4/4 · แก้ 1 รอบ") · รายการโพสต์ที่ใช้คิด
- ปุ่ม `Confirm` · `Override` (เลือกเกรด + เหตุผลบังคับ · ล็อกไว้ 90 วันหรือจนมีโพสต์ใหม่ 2 ชิ้น)
- **D ต้องมีคนยืนยันเสมอ** · Staff เห็นเกรดแต่รีวิวไม่ได้
- คำนวณใหม่เมื่อ: บันทึก / Import metrics · Post · Incident · Cancel · ทุกครั้งที่เปิดแอป (เฉพาะ partner ที่ข้อมูลเปลี่ยน)

### 3.6 Dashboard › tab ใหม่ **Partners**
ตัวกรอง: ช่วงเวลา · Campaign · Pillar · Partner type (KOL / Affiliate)
- **KPI 4 ใบ** (โครงเดียวกับ CR-29): Graded partners (+ Not enough data) · A + B share · **Spend on C + D** · Waiting for review
- **Grade mix** (จำนวน / Spend) แยก KOL · Affiliate
- **Grade × Tier** (ตาราง Mega–Nano × A–D · จำนวน + Spend · คลิกช่อง = KOL Master กรองไว้)
- **Grade movement** (ขึ้น / ลง ในช่วงที่เลือก)
- **Top performers (A)** + ปุ่ม `Add to campaign` · **Watch list (C / D)** + เหตุผลหลัก
- **Review queue** (ย่อ 5 รายการ + View all)
- สี Grade: A เขียว · B น้ำเงิน · C เหลือง · D แดง (ตามภาพเกณฑ์ · ตรวจ light / dark + ข้อความกำกับเสมอ ไม่ใช้สีอย่างเดียว)

### 3.7 หน้าอื่นที่ต้องแก้
| หน้า | แก้ |
|---|---|
| **New deal** | ตัวกรอง **Grade** ในแถวด่วน (All · A · B · C · D · Not graded) · chip เกรดในตาราง · เลือก D → เตือน "Graded D — <reason>" ต้องติ๊ก "Add anyway" · เรียงได้ตาม Grade |
| **KOL Master** | คอลัมน์ **Grade** (แทน Performance) · ตัวกรอง Grade · Bulk ไม่มี (เกรดมาจากระบบ) |

| **Deal modal** | Metrics มีที่มา (Auto / Import / Manual) · `+ Incident` · ratio เทียบ benchmark ของโพสต์ |
| **Campaign Planner** | ส่วน Benchmarks (§3.1) |
| **Dashboard › By campaign** | การ์ด "Clips beating benchmark 23% (target 20%)" · ตาราง CPM / CPCons / ROAS ต่อโพสต์ |
| **Operations** | งาน "Enter metrics" (D+7 ไม่มีข้อมูล) · "Review grade" (Manager) |
| **Settings › Grades** | เกณฑ์ A–D · น้ำหนัก · หน้าต่างเวลา / จำนวนโพสต์ · consideration actions · benchmark default |

## หมายเหตุการ implement (12/10/2026)
schema **24 → 25** (`store.js` `toV25` → `R.migrateV25` · ครั้งเดียว) · ไม่แตะ seed · ยอดเงินทุกหน้าเท่าเดิม · คะแนนทุกที่มาจาก `R.gradeEngine` (`src/rules-grade.js`) ตัวเดียว · ทดสอบด้วยข้อมูลสมมติเท่านั้น

- **§3.1 Benchmarks** — Phase Planner › ส่วน Benchmarks (คอลัมน์ซ้าย ใต้ Campaign): Awareness CPM · Consideration rate (%) · Cost per consideration (= CPM ÷ (1,000 × rate) ขึ้นเองเป็นตัวจาง · พิมพ์ทับได้) · Conversion ROAS · Affiliate ROAS · Campaign KPI % of clips beating benchmark · ว่าง = ค่า default ใน Settings › Grades · บันทึกพร้อมแผน (นับเป็น 1 การเปลี่ยน "Benchmarks")
- **§3.2 Metrics** — โพสต์มี Reach · Impressions · Views · Likes · Comments · Shares · Saves · Clicks (+ Sales ฿ · ROAS เมื่อ deal เป็น Conversion หรือ partner เป็น Affiliate) · ป้ายที่มา `Manual · 12/10` / `Import` / `Auto` (tooltip: วันที่ · D+7/D+30) · บรรทัด "CPM ฿12.00 · 1.25× benchmark" ตาม pillar · กรอกเอง = Manual
  - Deals › ⋯ › **Import metrics** (CSV / XLSX · template ดาวน์โหลดได้): จับคู่ Post link → Deal ID → Account + Campaign · ตัวอย่างก่อน Import (Import · No change · Manual — kept · Not found · Skipped · Error พร้อมเหตุผล) · ติ๊ก **Replace manual values** ถึงจะทับค่า Manual · Undo 10 วินาที · ยอดขาย (Sales / ROAS) ใช้ไฟล์เดียวกัน
- **§3.3 คะแนน** — Performance ต่อโพสต์ (ratio > 1 = ดีกว่า) · Operation ต่อ deal 50 / 30 / 20 · Grade จาก 6 โพสต์ล่าสุดใน 6 เดือน · < 2 โพสต์ = Not enough data · ไม่มี metrics = Ops only · ลำดับในตาราง = Performance 60 · Operation 40
- **§3.4 Incident** — Deal modal › History › `+ Incident` (Late without notice · Missed brief · No-show · Breach of agreement · Other) · No-show / Breach = เตือน "Serious — the partner is suggested D at once" · Remove ได้ (เก็บใน history)
- **§3.5 Grade review** — การ์ด: Suggested · Confirmed now · เหตุผลหลัก ("Awareness: 25% better than benchmark · on time 5/5 · 1 revision round on average") · Performance / Operation / Score · Posts used · `Confirm` · `Override` (เลือก A–D + เหตุผลบังคับ → ล็อก 90 วันหรือจนมีโพสต์ใหม่ 2 ชิ้น) · Open KOL · Staff เห็นแต่รีวิวไม่ได้ · เปิดจาก Dashboard › Partners · Operations ("Review grade") · KOL modal › Performance
- **§3.6 Dashboard › Partners** — ตัวกรอง ช่วงเวลา · Campaign · Pillar · Partner type · KPI 4 ใบ · Grade mix (Count / Spend · KOL / Affiliate) · Grade × Tier (คลิกตัวเลข → KOL Master กรอง Grade + Tier) · Top performers (A · `Add to campaign` → New deal) · Watch list (C / D + เหตุผล) · Grade movement · Review queue (5 + View all) · Export sheet `Partners`

### การตัดสินใจ (ตาม §6 หรือที่ spec ไม่ระบุ)
1. ไม่สร้าง store `post_metrics` แยก — ตัวเลขอยู่บน `deal_posts` เหมือนเดิม (CR-10) + field ใหม่ `reach` · `impressions` · `clicks` · `sales` · `roas` · `metrics_source` (auto / import / manual) · `metrics_day` (7 / 30) · `fetch_status` · `fetched_at` · captured_at = `metrics_updated_at` เดิม
2. ตัวเลขจากไฟล์เก่า (legacy) → Manual + ธง `metrics_legacy` (ยังแสดงสถานะ "Imported" แบบเดิม) · Paste ใน Deals › Performance บันทึกเป็น Import
3. Ops only: ใช้เกณฑ์ด้าน Operation ของตาราง A–D (≥ 85 A · ≥ 70 B · ≥ 50 C · ต่ำกว่า D)
4. Performance ต้องมีโพสต์ที่วัด ratio ได้อย่างน้อย 2 ชิ้น (ค่าเดียวกับ "ขั้นต่ำ 2 โพสต์") — น้อยกว่า = Ops only
5. Operation: ไม่มีอะไรให้วัดตรงเวลา = เต็ม 50 · รอบแก้นับต่อ deal · Incident ใด ๆ บน deal = 0/20 ของ deal นั้น · คะแนนของ partner = เฉลี่ย deal ของโพสต์ที่ใช้คิด
6. Incident ร้ายแรงในหน้าต่าง 6 เดือน = D แม้มีโพสต์ไม่ถึง 2 (No-show อาจไม่มีโพสต์) และทำลายการล็อกของ Override
7. A&C: เฉลี่ย ratio ที่มี (ขาดด้านหนึ่ง = ใช้ด้านที่มี)
8. Affiliate: ROAS เทียบ Affiliate ROAS target (ไม่มี = ใช้ ROAS target ของ Conversion) · Grade mix แยกแถว KOL / Affiliate
9. "Beating benchmark" ของ Campaign KPI = ratio > 1
10. Benchmark default ว่างตอนเริ่ม → seed: 20 partners = Ops only (A 17 · C 3) · 244 = Not enough data · ยังไม่มีใครถูกยืนยัน (ทุกที่แสดง "—" + วง "A?" ของคำแนะนำ) · 20 รายการรอรีวิว
11. เกรดที่แสดงทุกที่ = Confirmed เท่านั้น (ตาม §1)
12. Benchmarks บันทึกลง Campaign ทันที (เป็นเป้าวัดผล ไม่ใช่เงิน — ไม่ผ่าน approval) · event `benchmarks` ใน campaign_events
