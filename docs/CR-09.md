### 4.2 Time axis ใหม่ — `chart.timeAxis(range)`
**ปัญหา:** แกน X มี 2 ชั้น (dd/mm ทุก 3 สัปดาห์ + ชื่อเดือนอีกชั้น) ตำแหน่ง tick ไม่ตรงกับเส้น grid เดือน และรูปแบบวันที่ซ้ำกัน

**กติกา: แกนชั้นเดียว รูปแบบเดียว ต่อช่วงที่แสดง**

| ความยาวช่วง | แท่ง (bucket) | Tick + grid | รูปแบบ label |
|---|---|---|---|
| > 92 วัน (This year, Custom ยาว) | รายสัปดาห์ (จันทร์) | ต้นเดือนทุกเดือน | `Jan` `Feb` … (ถ้าช่วงข้ามปีใช้ `Jan 27` เฉพาะเดือน Jan) |
| 15 – 92 วัน (This quarter, Custom) | รายวัน | ทุกวันจันทร์ | `5 Oct` |
| ≤ 14 วัน | รายวัน | ทุกวัน | `Mon 5` |

- label อยู่**ตรงกับเส้น grid** (ไม่ลอยกลางช่วง) · ปีแสดงครั้งเดียวในข้อความช่วงวันที่ข้าง presets (เช่น "01/01/2026 – 31/12/2026")
- เส้น Today (แดงประ) + label "Today" คงเดิม
- Activity by campaign: label ชื่อ Campaign ซ้าย + "n posts" คงเดิม · Campaign ที่ไม่มีโพสต์ในช่วงยังแสดงแถว (ไม่เลื่อนตำแหน่งแถวอื่น) แต่ตัวอักษรสีเทา
- footnote "x posts without a date · y posts dated outside this range" คงเดิม
- Activity by date (By campaign) ใช้ `timeAxis` เดียวกัน: Daily → tick ทุกจันทร์ `5 Oct` · Weekly → tick ต้นเดือน หรือทุกจันทร์ถ้าช่วง ≤ 92 วัน · ตัดบรรทัดชื่อเดือนชั้นที่สองออก

### 4.3 Days left — `rules.daysLeft(item, today)` (ใช้กับ Campaign และ Phase)

| Status | แสดง | ตัวอย่าง (today = 06/10/2026) |
|---|---|---|
| On going | "n days left" · วันสุดท้าย = "Last day" · ≤ 7 วัน ตัวเลขสีเหลืองเข้ม | Charming Iconic Glow (จบ 24/10) = **18 days left** |

### 4.9 Deals — Stage ตรงกันระหว่าง Table · Pipeline · Drawer

- **ตัวเลขชุดเดียว:** Table และ Pipeline ใน scope เดียวกัน (Campaign · Phase · PIC · Filters) ต้องได้ จำนวนต่อขั้น และ summary strip (Committed · Pending · Paid) เท่ากันเสมอ · ย้ายขั้นใน view หนึ่ง (drag / Move stage) → อีก view อัปเดตทันที (อ่าน state เดียว ไม่ cache แยก)

- Campaign › Phase: ชื่อเต็มขึ้น 2 บรรทัด (บรรทัด 1 Campaign · บรรทัด 2 Phase) กว้างขั้นต่ำ 200px · ไม่ตัดด้านซ้าย
- **รวม Docs + Status เป็นคอลัมน์เดียว "Status"**: chip สถานะ (Not due · Missing docs · Ready · In run · With Accounting · Paid · Cancelled — CR-08 §4.3 โดย Submitted แสดงเป็น With Accounting) + บรรทัดเล็ก "Missing 4" · คลิก / hover = popover รายการที่ขาด (ID copy · Bank book · Bank details · Post evidence) แต่ละรายการเป็นลิงก์ไปที่แก้
- "Term not set" ย้ายจาก chip ข้าง Milestone เป็นไอคอน ! เล็กหลัง Milestone + tooltip (ยังนับใน Needs check)
- ปุ่ม `Request payment` → ปุ่มไอคอน + label สั้น `Request` กว้างคงที่ · ไม่มีสิทธิ์ → ซ่อน (ไม่แสดงปุ่ม disabled ทั้งตาราง) · ใน ⋯ มีรายการเดียวกัน
- คอลัมน์ตัวเลข Gross · WHT · Net ชิดขวา tabular-nums (กติกา §4.8) · ความสูงแถวเป้าหมาย 48px
- ที่ ≥ 1280px ไม่มี horizontal scroll · แคบกว่านั้นเลื่อนในกรอบตารางโดยตรึง ☐ + KOL

### 4.15 Payments — โครง tabs ใหม่ (ตามคนที่ทำงาน)
**ปัญหา:** Runs / History ไม่ชัดว่าใช้ทำอะไร และฝั่งบัญชีไม่มีที่ทำงานของตัวเอง

| Tab | ใครใช้ | ตอบคำถาม | เนื้อหา |
|---|---|---|---|
| **To pay** | PIC · ทีม KOL | "งวดไหนถึงกำหนด ขาดอะไร" | ตาม §4.14 + CR-08 §4.5 |
| **Payment runs** (= รอบจ่าย / PR) | ผู้ทำรอบ (Dream, Babe) · KOL Manager | "รอบวันศุกร์นี้มีอะไร ส่งบัญชีหรือยัง" | รายการรอบ + Run detail (CR-08 §4.6) · Draft → **Submit to Accounting** |
| **Accounting** | ทีมบัญชี · Admin | "ต้องโอนอะไร ส่งใบ 50 ทวิ อะไร" | §4.15.2 (แทน History) |

- คำอธิบายสั้นใต้ชื่อ tab ไม่ต้องมี — ใช้ ⓘ ข้างชื่อ tab (popover 1 บรรทัดตามคอลัมน์ "ตอบคำถาม")
- ปุ่มสถานะ run ใช้คำที่บอกว่าส่งต่อให้ใคร: `Submit to Accounting` (แทน Submit) · label สถานะตาม §3 (Draft · Returned · With Accounting · Paid · Closed)
- **Payment runs tab:** รายการรอบทุกสถานะ (filter สถานะ · default ซ่อน Closed) · Run detail ตาม CR-08 §4.6 แต่
  - Draft / Returned: Add / Remove line · Edit amount · Export PR (ไม่มีข้อมูลผู้รับถ้าไม่ Unlock) · **Submit to Accounting** (Admin · KOL Manager)
  - Returned: แถบเหลืองบนสุด "Returned by Earn on 10/10/2026 — <reason>"
  - With Accounting / Paid / Closed: อ่านอย่างเดียวสำหรับทีม KOL · ปุ่ม `Open in Accounting` (เฉพาะ Admin / Accounting)
  - Reopen as Draft (Admin เท่านั้น ตาม CR-08)

**4.15.1 สร้างรอบจาก To pay ได้ทันที**
- เลือกแถวใน To pay → ปุ่ม `Create payment run` → dialog: Pay date (default ศุกร์ถัดไป) · Prepared by → สร้าง run + เพิ่ม line ที่เลือก → เปิด Run detail · หรือ `Add to run ▾` (run Draft ที่มีอยู่)
- Run detail: ปุ่ม `Export PR` (ไฟล์ CR-08 §4.7) — ไฟล์ทุก sheet มีบรรทัดหัว **"รอบจ่าย: PR-2026-10-09 · วันจ่าย 09/10/2026"** และ sheet Summary · ชื่อไฟล์ `PR_09_10_26_PR-2026-10-09.xlsx`
- Export จาก To pay โดยตรง (ไม่ผ่าน run) = Payments CSV สำหรับดูเท่านั้น (ไม่ใช่ไฟล์ส่งบัญชี) · tooltip "To send to Accounting, create a payment run"

**4.15.2 Tab Accounting** (แทน History)
- **Row 1 — Queue cards:** `To transfer n · ฿net` (run สถานะ With Accounting) · `WHT certs to send n` · `Paid this month ฿x`
- **Section "Runs to pay"**: run ที่ With Accounting เรียงตาม pay date · แต่ละ run: Run id · Pay date · Prepared by · lines · Gross · VAT · WHT · Net · ปุ่ม `Open` · `Export PR` (ปลดล็อก vault แล้วได้ข้อมูลผู้รับครบ CR-08 §4.7) · `Mark paid` (ทั้งรอบหรือเลือกแถว · วันที่โอน) · `Return to team` (เหตุผลบังคับ → run กลับเป็น Draft สถานะ Returned + แจ้งใน Payment runs)
- **Section "WHT certificates"**: line ที่ Paid และ wht > 0 ยังไม่ส่ง · bulk `Mark sent` (วันที่) · คอลัมน์ ช่องทางส่ง (email / ที่อยู่ — แสดงเมื่อ Unlock) · Export `WHT summary` รายเดือน (CR-08 §4.8)
- **Section "Paid"** (เดิม History): line ที่ Paid ทั้งหมด · filter presets (This month default) · search · export
- `Mark paid outside app` (CR-08 §4.5 · ใช้เคลียร์งานเก่า) ย้ายมาอยู่ใน Accounting เป็นปุ่มรองของ section Paid · สิทธิ์ Admin / Accounting
- `Close run`: ใน Runs to pay เมื่อ run เป็น Paid (ปกติหลังส่งใบ 50 ทวิ ครบ) · Admin / Accounting
- Tab Accounting: Admin · Accounting แก้ได้ · KOL Manager / Staff / Viewer เห็นแบบอ่านอย่างเดียว (ไม่มีปุ่ม · Export PR แบบไม่มีข้อมูลผู้รับยังได้)
