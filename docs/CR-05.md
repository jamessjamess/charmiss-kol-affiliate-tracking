## 4. Implementation details

### 4.1 Role: KOL Manager
หัวหน้าทีม KOL — ทำงานแบบ staff ได้ทั้งหมด + วางแผน Campaign/งบ + จัดการข้อมูลที่กระทบเงิน แต่ไม่จัดการผู้ใช้และไม่ล้างข้อมูล

**Permission matrix ใหม่** — `rules.can(user, action)` (แทน matrix ของ CR-04 §4.4)

| Action | Admin | KOL Manager | Staff | Viewer |
|---|:-:|:-:|:-:|:-:|
| ดูทุกหน้า (ยกเว้น Role Management) · Export CSV · Backup | ✓ | ✓ | ✓ | ✓ |
| สร้าง/แก้ Deal, โพสต์, Move stage, Payment, PIC inline, Set pillar | ✓ | ✓ | ✓ | — |
| สร้าง/แก้ KOL, บัญชี, ราคา · Import KOL CSV | ✓ | ✓ | ✓ | — |
| แก้ Costs หลังมีการจ่าย (ต้องใส่เหตุผล) · เปลี่ยน Campaign ของ deal | ✓ | ✓ | — | — |
| Merge KOL · ลบ deal / KOL | ✓ | ✓ | — | — |
| สร้าง/แก้ Campaign & Phase · Phase Planner · งบ Campaign · % Phase · CTA · pillar target | ✓ | ✓ | — | — |
| Settings › Lists (Journey steps, Pillar, CTA, Platform) · Pillar targets | ✓ | ✓ | — | — |
| Settings › Tier rules | ✓ | — | — | — |
| Restore / Reset to seed | ✓ | — | — | — |
| Role Management | ✓ | — | — | — |

- Role chip สี: Admin = primary · KOL Manager = น้ำเงิน · Staff = เทา · Viewer = เทาขอบ
- ตาราง Permissions ในหน้า Role Management แสดง 4 คอลัมน์ตามนี้
- ไม่มี user ไหนถูกตั้งเป็น KOL Manager อัตโนมัติ — admin ตั้งเองในหน้า Role Management
- KOL Manager เป็น PIC ได้ (is_pic) เหมือน staff

> **หมายเหตุ (CR-09, 06/10/2026):** เพิ่ม role ที่ 5 **Accounting** (ทีมบัญชี · chip ม่วง · ไม่เป็น PIC · ไม่เห็น Settings / Role Management · หน้าแรก Payments › Accounting) + user เริ่มต้น **Earn** ผ่าน migration v9 · Staff แก้ Products ของ Campaign ได้ (+ New product) → CR-09 §4.7, §4.16

### 4.2 Switch role
- อยู่ในเมนูของ user card ล่าง side menu ต่อจากรายการ Switch user · หัวข้อ **"View as role"**: Admin · KOL Manager · Staff · Viewer
- **แสดงเฉพาะเมื่อ role จริงของ user ปัจจุบันคือ admin** (เมนูนี้ยังแสดงอยู่แม้ตอนดูเป็น role อื่น เพื่อให้สลับกลับได้)
- เลือกแล้ว: ตั้ง `role_override` ใน sessionStorage → ทุกหน้า render ตามสิทธิ์ของ role นั้นทันที (เมนู, ปุ่ม, ✎, ช่อง inline) · ไม่ต้อง reload
- ระหว่างดูเป็น role อื่น:
  - การ์ด user แสดง "Admin · viewing as Staff" และ role chip เป็นของ role ที่เลือก
  - แถบบางสีอ่อนเต็มความกว้างด้านบนเนื้อหา: "Viewing as Staff" + ปุ่ม "Back to Admin" (ไม่มีคำว่า Demo)
  - ข้อมูลที่แก้ยังบันทึก `changed_by` = user จริง (ไม่ใช่ role)
- ปิดแท็บ / เปิดใหม่ = กลับเป็น role จริง (เพราะเก็บใน sessionStorage)
- `rules.effectiveRole(user, roleOverride)` = roleOverride ถ้า user.role === 'admin' ไม่งั้น user.role

### 4.4 Phase Planner

> **หมายเหตุ (CR-11, 06/10/2026):** Phase Planner เปิดเป็น **create modal ขนาด L** กลางจอ (ไม่ใช่หน้าเต็ม / drawer) ทั้ง New campaign · New phase · Plan phases — ซ้าย Campaign 40% · ขวา Phases 60% (ซ้อนแนวตั้งเมื่อ modal แคบกว่า 1100px) · ปุ่ม `Create campaign` / `Save phases` · New product ระหว่างวางแผน = panel แทนที่ใน modal เดิม — ดู `docs/CR-11.md` §4.5 และ `docs/UI_PATTERNS.md`

> **หมายเหตุ (CR-10, 06/10/2026):** Start / End ของแต่ละ Phase และช่วงของ Campaign รวมเป็นช่อง **Period** ช่องเดียว (Date range picker · `validateRange`) · + Add phase เปิด picker ที่วันถัดจาก Phase ก่อนหน้า · Planner เปิดเป็น modal กว้างอย่างน้อย 880px — ดู `docs/CR-10.md` §4.8, §4.13
ใช้สร้าง/แก้หลาย Phase ของ Campaign เดียวในหน้าเดียว แทนการสร้างทีละ Phase

**ทางเข้า**
- `+ New campaign` → เปิด Planner โหมด new (ใส่ข้อมูล Campaign + Phase ในครั้งเดียว)
- Campaign drawer › ปุ่ม `Plan phases` → Planner โหมด edit
- ปุ่ม `+ New phase` เดิม → เปิด Planner ของ Campaign ที่เลือก และเพิ่มแถวว่างให้ 1 แถว

**Layout** (หน้าเต็มหรือ drawer กว้าง 880px · มือถือเต็มจอ)
1. **Campaign:** Name · CTA · KOL budget (฿) · Pillar target (ใช้ค่าเริ่มต้น / กำหนดเอง)
2. **Phases** (ตารางแก้ได้ทุกช่อง):

| # | Phase name | Start | End | Days | Budget (% \| ฿) | Amount | ⋯ |
|---|---|---|---|---|---|---|---|

   - toggle `% | ฿` ระดับทั้งตาราง · ช่อง Amount/% อีกแบบคำนวณให้
   - `+ Add phase`: start = end ของแถวก่อน + 1 วัน · end ว่าง
   - ⋯ ต่อแถว: Duplicate · Delete (ลบไม่ได้ถ้ามีโพสต์ใช้อยู่ → disabled + tooltip "Has posts — can't delete")
   - ลากเรียงแถวไม่ต้องทำ · ตารางเรียงตาม start date อัตโนมัติตอน Save
   - ปุ่มลัด `Split evenly` (แบ่ง % เท่ากันทุก Phase) และ `Fill remaining` (ให้แถวที่เลือกรับส่วนที่ยังไม่จัดสรร)
3. **Budget bar** (sticky ใต้ตาราง): แถบเดียวแบ่งสีตาม Phase (สี Phase ตาม CR-03 §4.7) เทียบงบ Campaign
   - ข้อความ: `Allocated ฿x of ฿y (z%)` · ถ้า < 100% = "Unallocated ฿n" (เทา) · ถ้า > 100% = **"Over budget by ฿n"** (แดง + ส่วนที่เกินแสดงเป็นแถบแดงต่อท้าย)
4. **Timeline preview:** แถบ Phase ตามวันที่ (แบบเดียวกับ Gantt ของ CR-02) · ช่วงทับเป็นลายทแยง · ช่วงว่างระหว่าง Phase เป็นเส้นประ
5. **Impact preview** (เฉพาะโหมด edit เมื่อเปลี่ยนวันที่): "n posts will move phase · m posts will need a phase" + ตารางเล็ก Phase · committed ก่อน → หลัง (ใช้ `resolvePostPhase` / `phaseCommitted` จาก CR-03)
6. กล่องตรวจ (✕ ! i) + ปุ่ม Save / Cancel

**Validation** — `rules.validatePhasePlan(campaign, phases, existingPosts)`

| ระดับ | Rule |
|---|---|
| Error | Campaign name ว่าง / ซ้ำ |
| Error | Phase ต้องมีชื่อ, start, end · end ≥ start · ชื่อ Phase ซ้ำกันใน Campaign เดียวกัน |
| Error | งบ % หรือ ฿ ติดลบ |
| Error | ลบ Phase ที่มีโพสต์ใช้อยู่ |
| **Warning (ต้องยืนยัน)** | **ผลรวมงบ Phase เกินงบ Campaign** → "Phase budgets exceed the campaign budget by ฿n" · กด Save แล้วขึ้น dialog "Save anyway?" |
| Warning | ช่วงวันที่ของ Phase ทับกัน (แจ้งช่วงที่ทับ) — กติกา CR-03 |
| Warning | ยังไม่ได้ใส่งบ Campaign แต่ใส่งบ Phase เป็น % (คำนวณเป็นเงินไม่ได้) |
| Info | ผลรวมงบ Phase น้อยกว่างบ Campaign ("Unallocated ฿n") |
| Info | มีช่วงว่างระหว่าง Phase (โพสต์ในช่วงนี้จะต้องเลือก Phase เอง) |

- Save บันทึกทุกแถวพร้อมกัน (ถ้ามี Error ห้ามบันทึกแม้แต่แถวเดียว) · บันทึก event ใน audit (type = `phase_plan`) ที่ Campaign
- หลัง Save: กลับไปหน้า Campaign & Phase และ highlight Campaign นั้น · ยอดราย Phase คำนวณใหม่ทันที

### 4.5 นิยามเงิน (ใช้เหมือนกันทุกหน้า — แก้ความสับสน Shortlist / Committed)

| คำ | นิยาม | ค่า seed (รวม) |
|---|---|---|
| **Budget** | งบ KOL ของ Campaign (หรือผลรวมงบ Phase เมื่อดูราย Phase) | ฿2,748,400 |
| **Committed** (= Actual usage) | ผลรวม total ของ deal ที่ถึง **Confirm QT ขึ้นไป** และไม่ Cancel | ฿1,783,579 |
| **Used %** | Committed ÷ Budget | 65% |
| **Remaining** | Budget − Committed (ติดลบ = เกินงบ สีแดง) | ฿964,821 |
| **Pending** | ผลรวม total ของ deal ที่ยังอยู่ **Shortlist / Contacted** (ยังไม่ยืนยัน ยังไม่นับเป็นการใช้งบ) | ฿98,000 |
| Paid (est.) | ตามเดิม (จ่ายครบ = เต็ม · จ่าย 50% = ครึ่ง) | ฿774,579 |

- เปลี่ยนชื่อ **"Shortlist" → "Pending"** ทุกที่ที่หมายถึงเงิน (ชื่อ "Shortlist" ใช้เป็นชื่อขั้นใน Journey อยู่แล้ว ทำให้สับสน)
- ลำดับคอลัมน์/ตัวเลขทุกที่: **Budget → Committed → Used % → Remaining → Pending** (Pending อยู่ท้ายเพราะยังไม่ใช่การใช้จริง)
- KPI card "Committed": บรรทัดรองเป็น `of ฿2.75M · 65% used · ฿965K remaining` และบรรทัดล่าง `+ ฿98K pending` (สีเทา)
- Phase committed (CR-03) ใช้นิยามเดียวกัน (นับเฉพาะ deal ที่ถึง Confirm QT ขึ้นไป) · Pending ราย Phase ใช้ postShare เหมือนกัน

### 4.6 Dashboard — 3 tabs

> **หมายเหตุ (CR-10, 06/10/2026):** Custom range ใช้ Date range picker ช่องเดียว (2 เดือน · พิมพ์ dd/mm/yyyy ได้ · คีย์บอร์ด · Phone = sheet เต็มจอ) แทน `<input type="date">` คู่ Start / End · Payments › Paid Custom ใช้ตัวเดียวกัน · Operations มี card **Samples to ship** — ดู `docs/CR-10.md` §4.8, §4.14

> **หมายเหตุ (CR-07, 06/10/2026):** presets เป็น This year (default) · This quarter · This month · Last month · Custom (ช่วงปฏิทินเต็ม) · Portfolio ไม่มี Pillar mix · Engagement ไม่มี ER / CPV · Phase budget / Allocation vs target เต็มแถว · Workload by PIC ย้ายไป By campaign · Operations เลือก PIC ก่อน + Due in next 7 days → CR-07 §4.1–4.3

**กติกากราฟทุกกราฟในแอป (ไม่ใช่แค่ Dashboard):** แท่งกราฟ, แท่งแนวนอน, progress bar, usage bar, budget bar, แถบ Phase/Timeline ต้องเป็น **มุมเหลี่ยม (border-radius 0)** ทั้งหมด — card และปุ่มยังโค้งได้ตามเดิม (แทนกติกา "มุมบนโค้ง 4px" เดิม) · ช่องว่าง 2px ระหว่าง segment ยังคงไว้

### 4.7 Campaign & Phase — ตาราง, Status, Timeline

> **หมายเหตุ (CR-10, 06/10/2026):** Timeline มี filter **Campaign** เลือกได้หลายตัว (chip · จำต่อคน) · เลือกแล้ว zoom เป็น **Fit** = เริ่มเร็วสุด − 7 วัน ถึงจบช้าสุด + 7 วัน (`rules.fitRange`) · แกนเวลาใช้ `R.timeAxis` · Campaign drawer กว้าง 60% (ไม่ modal) — ดู `docs/CR-10.md` §4.9, §4.13

**Tabs ของหน้า:** `Table | Timeline` (Timeline เดิมแยกออกมาเป็น tab ของตัวเองในหน้านี้ — ไม่ย้ายไป Dashboard เพราะเป็นเรื่องการวางแผนช่วงเวลา ส่วน Dashboard › By campaign มี Phase strip อยู่แล้ว) · filter Year / Status / Search ใช้ร่วมกันทั้ง 2 tab

**Table tab (ตารางกว้างเต็มจอ)**
- คอลัมน์ (ตามลำดับ): **Name · Status · Period · Budget · Committed · Used % · Remaining · Pending · Deals**
- **Name ห้ามถูกตัดจนอ่านไม่ออก:** กว้างขั้นต่ำ 320px · ชื่อยาวให้ขึ้นบรรทัดที่ 2 ได้ (ข้อยกเว้นของกฎบรรทัดเดียว เฉพาะคอลัมน์นี้) · Phase row เยื้อง 24px · ไม่แสดง ID ต่อท้าย (เช่น "PH-P3", "AC-P1" ต้องหายตาม §4.3)
- **ตัด % ลอยหน้างบ Phase** (59% / 41% …) ออกจากตาราง → ย้ายไปอยู่ใน popover ของช่อง Budget ("59% of campaign budget") และในหน้า Phase Planner
- Used %: ตัวเลข + แถบเหลี่ยม 80px (เกิน 100% = แดง) · Remaining ติดลบ = แดง "−฿13,700" · Budget ว่าง = "No budget" และ Used % / Remaining = "—"
- แถว Unscheduled / Needs phase (CR-03) แสดงใต้ Phase สุดท้ายของ Campaign เมื่อมียอด
- แถวรวมล่างสุดใช้นิยาม §4.5 (ไม่นับ Campaign ที่ Cancelled ยกเว้นติ๊ก "Include cancelled")

**Campaign status เพิ่ม On hold และ Cancelled**
- field ใหม่ `campaigns.status_override`: `null | 'on_hold' | 'cancelled'` + `status_reason` (บังคับเมื่อตั้งค่า) + `status_changed_at`
- Effective status: cancelled > on_hold > ตามวันที่ (Not started / On going / Complete)
- ตั้ง/ยกเลิกได้ใน Campaign drawer (admin + KOL Manager) · บันทึก event
- **On hold:** สร้าง deal ใหม่ / Add to phase ใน Campaign นี้ไม่ได้ (Error "Campaign is on hold") · deal เดิมยังแก้ได้ · chip สีเหลือง
- **Cancelled:** ต้องจัดการ deal ที่ยังไม่ปิด (List / In process) ก่อน — dialog เสนอ "Cancel n open deals" (ใส่เหตุผลเดียวกัน) · หลัง Cancel ห้ามสร้าง/แก้ deal (ยกเว้น Remark) · chip สีแดงอ่อน · ไม่นับในแถวรวมและ KPI ของ Dashboard (มีตัวเลือก Include cancelled)
- Phase ของ Campaign ที่ On hold / Cancelled แสดง status ของ Campaign แบบจาง
- Status tabs: All · On going · Not started · On hold · Complete · Cancelled
- Sort: On going → Not started → On hold → Complete → Cancelled (ใช้กับ combobox ด้วย · Cancelled ซ่อนใน combobox ยกเว้นพิมพ์ค้นหา)

**Timeline tab**
- Gantt เดิม (CR-02 §4.8) ย้ายมาอยู่ที่นี่ กว้างเต็มจอ · คอลัมน์ซ้ายเหลือ Name + Status (ชื่อเต็มไม่ตัด) · แถบเหลี่ยมทั้งหมด · On hold = แถบลายทแยงเหลือง · Cancelled = แถบเทาขีดฆ่า
- zoom: `Month | Quarter` · ปุ่ม Today
