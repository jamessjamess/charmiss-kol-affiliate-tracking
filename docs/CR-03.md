## 4. Implementation details

### 4.1 หลักการ
- **Phase = ช่วงเวลาที่ใช้แบ่งงบอย่างเดียว** Deal ไม่ต้องเลือก Phase
- ระบบจัด Phase ให้ **รายโพสต์** จากวันที่ · ถ้าจัดเองไม่ได้ (ไม่มีวันที่ / นอกช่วง / ช่วงทับกัน) ให้ผู้ใช้**เลือก Phase เอง**ที่โพสต์นั้น
- ปกติ Phase ใน Campaign เดียวกันควรตั้งไม่ให้ทับกัน แต่ถ้าตั้งทับกัน ระบบยอมให้บันทึก (Warning) แล้วโพสต์ที่ตกในช่วงทับจะต้องเลือก Phase เอง

### 4.2 Phase ของโพสต์ — `rules.resolvePostPhase(post, phasesOfCampaign)`
- `post_date_effective` = `post_date` ถ้ามี · ไม่งั้น `expected_post_date` ของโพสต์ · ไม่งั้น null
- หา Phase ของ Campaign ที่ `start_date ≤ post_date_effective ≤ end_date`:

| ผล | เงื่อนไข | Phase ที่ใช้ (`effective_phase`) |
|---|---|---|
| `auto` | เจอ 1 Phase พอดี | Phase นั้น (ไม่สน `phase_override`) |
| `none` | ไม่มีวันที่ | `phase_override` ถ้ามี · ไม่งั้น = Unscheduled |
| `outside` | มีวันที่แต่ไม่อยู่ใน Phase ไหน | `phase_override` ถ้ามี · ไม่งั้น = **Needs phase** |
| `overlap` | อยู่ในช่วงของมากกว่า 1 Phase | `phase_override` ถ้าเป็นหนึ่งใน Phase ที่ทับ · ไม่งั้น = **Needs phase** |

- `phase_override` เลือกได้เฉพาะเมื่อผลเป็น `none` / `outside` / `overlap` · ถ้าภายหลังวันที่ถูกแก้แล้วกลายเป็น `auto` ให้ใช้ auto และแสดง override เดิมเป็นสีจางพร้อม tooltip "Not used — date now falls in <Phase>"
- เพิ่ม/แก้ช่วงของ Phase แล้วทุกโพสต์คำนวณใหม่ทันที (ไม่ต้องแก้ deal)

**เงินต่อโพสต์** — `rules.postShare(deal, post)` = `total_cost / จำนวนโพสต์ของ deal` (deal ที่ไม่มีโพสต์ → ทั้งก้อนเป็น Unscheduled)
- **Phase committed** = ผลรวม postShare ของโพสต์ที่ `effective_phase` = Phase นั้น และ deal ไม่ Cancel
- **Campaign committed** = ผลรวม total_cost ของ deal ที่ไม่ Cancel (= ผลรวมทุก Phase + Unscheduled + Needs phase)
- **Primary phase ของ deal** = `effective_phase` ของโพสต์ที่วันที่เร็วที่สุด (ไม่มีวันที่อยู่ท้าย) · ใช้สำหรับจัดกลุ่มในตารางเท่านั้น

### 4.3 งบ Campaign และ % ต่อ Phase
- Campaign drawer (edit): field **KOL budget** (฿)
- Phase drawer (edit): ช่องงบมีปุ่มสลับ `% | ฿` · กรอกเป็น % แล้วระบบเก็บเป็นจำนวนเงิน = % × งบ Campaign (ปัดเป็นบาท) · แสดงทั้งสองค่าเสมอ เช่น "60% · ฿360,000"
- ถ้าเปลี่ยนงบ Campaign: ถามว่า "Keep phase % (budgets recalculated)" หรือ "Keep phase amounts"
- Campaign row ในตาราง: แสดง Allocated = ผลรวมงบ Phase · ถ้าไม่เท่างบ Campaign ให้มี chip "Unallocated ฿x" (หรือ "Over-allocated ฿x" สีแดง) — Warning ไม่บล็อกการบันทึก
- ช่วงวันที่ของ Phase ทับกันใน Campaign เดียวกัน → Warning "PH-P1 and PH-P2 overlap 03/09–04/09 — posts in this range need a phase" (บันทึกได้) · Timeline แสดงช่วงที่ทับเป็นแถบลายทแยง
- ลบ Phase ที่มีโพสต์ใช้อยู่ (ทั้ง auto และ override) ไม่ได้

### 4.4 Post-level phase picker (ใน Deal drawer › Posts และตอนสร้าง deal)
- ทุกแถวโพสต์มีคอลัมน์ **Phase**:
  - `auto` → แสดงชื่อ Phase สีปกติ (อ่านอย่างเดียว)
  - `none` (ไม่มีวันที่) → "Unscheduled" สีเทา + เลือก Phase ล่วงหน้าได้ (ไม่บังคับ)
  - `outside` / `overlap` → dropdown บังคับเลือก (Phase ของ Campaign นั้น; overlap ให้เลือกได้แค่ Phase ที่ทับ) · ถ้ายังไม่เลือก = ป้ายเหลือง "Needs phase"
- Validation:
  - Warning (นับในคอลัมน์ ⚠): โพสต์ที่เป็น Needs phase
  - Info: วันที่ของโพสต์อยู่นอกช่วง Campaign ทั้งหมดเกิน 60 วัน (มักเป็นการพิมพ์ปีผิด เช่น 2024)
- ใน New deal: เลือก **Campaign** (แทน Phase) · ใต้แต่ละโพสต์ที่ติ๊กไว้แสดง Phase ที่ระบบจัดให้จาก expected_post_date สด ๆ

### 4.5 Deals, Pipeline และ Campaign & Phase หลังเปลี่ยน
- **Deals toolbar** (จาก CR-02): Campaign → Phase ยังเหมือนเดิม แต่ความหมายเปลี่ยน
  - Phase filter = deal ที่มี**อย่างน้อย 1 โพสต์**ใน Phase นั้น
  - เพิ่มตัวเลือกพิเศษใน Phase dropdown: `Needs phase` และ `Unscheduled`
  - การจัดกลุ่มใช้ Primary phase (§4.2) · หัวกลุ่มแสดง Phase committed (ตามโพสต์) / งบ Phase
  - deal ที่มีโพสต์คร่อมหลาย Phase อยู่ในกลุ่มของ Primary phase และมี chip เล็ก "+1 phase" (tooltip บอกชื่อ Phase และเงินที่แบ่งไป)
  - Summary strip เมื่อเลือก Phase: Committed = Phase committed รวม · Budget = งบ Phase รวม
- **Pipeline:** เลือก Campaign (ไม่ใช่ Phase) · มี Phase filter แบบเลือกได้หลายตัว (default = ทุก Phase)
- **Campaign & Phase** (จาก CR-02): Committed ของ Phase = Phase committed · เพิ่มแถวย่อยใต้ Phase สุดท้ายของแต่ละ Campaign เมื่อมียอด: "Unscheduled ฿x" และ "Needs phase ฿x" (สีเหลือง คลิกแล้วไป Deals filter นั้น) · แถว Campaign: Budget = `campaigns.budget_kol`, Committed = Campaign committed

### 4.6 Pillar บังคับ + Set pillar
- Pillar ใช้ค่าจาก `pillar_list` (Awareness · Consideration · Conversion)
- **Error สำหรับ deal ใหม่ / deal ที่ไม่ legacy:** ขยับสถานะไป Confirm QT หรือขั้นที่เลยกว่านั้นโดยยังไม่มี pillar → dialog "Move stage" ต้องมีช่องเลือก Pillar ให้กรอกได้ในตัว
- deal legacy ที่ยังไม่มี pillar: ไม่บังคับ แต่เป็น Info และนับใน Needs attention
- **Set pillar (bulk):** เลือกหลายแถวในตาราง Deals → bulk bar มีปุ่ม `Set pillar` → เลือกค่า → ยืนยัน "Set pillar of n deals to Consideration?" → toast + Undo · บันทึก `deal_events` type = `pillar` (เพิ่ม type ใหม่)
- แก้ pillar ราย deal ได้ใน drawer (โหมด Edit) และแบบ inline ในตาราง Template (คอลัมน์ Pilar) แบบเดียวกับ PIC
- Needs attention (Overview) เพิ่ม:
  - **Phase to assign** = จำนวนโพสต์ที่ Needs phase (seed หลัง migrate = 0 → ซ่อน)
  - **Pillar not set** = deal ที่ไม่ Cancel และไม่มี pillar (seed = 252)

- **Phase strip** เหนือพื้นที่กราฟ (แสดงทุกโหมด): แถบสูง 6px ตามช่วงของแต่ละ Phase ใช้สีของ Phase + ชื่อ Phase บนแถบ · ช่วงที่ทับกันเป็นลายทแยง · ให้เห็นว่าแต่ละช่วงเป็น Phase ไหนแม้จะ Color by Pillar
- **แท่ง:** stacked ตาม Color by · โพสต์แล้ว = สีเต็ม · ยังไม่โพสต์ (ใช้ expected date) = สีเดียวกันจาง 40% + ขอบ — legend มี swatch "Planned" · Needs phase / Unscheduled = เทา + texture
- แกน Y แกนเดียว: Posts = จำนวนเต็ม nice step · Spend = ฿ แบบย่อ
