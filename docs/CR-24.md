# CR-24 — Operations = Work queue · ตัด Pillar allocation

ใช้กติกาถาวรใน CLAUDE.md

## 1. เป้าหมาย
เปิดหน้าเดียวแล้วรู้ว่า **วันนี้ต้องตามอะไร · ของใคร · ค้างมากี่วัน** และกดทำต่อได้ทันที

## 2. ปัญหาของหน้าเดิม (จากภาพ PIC = Amp)
- tiles To do เป็น 0 ทั้งหมด แต่มี deal ค้าง 9 ตัว (Confirm QT 1 · Brief 4 · Draft 1 4) → งานที่ **ไม่มีวันกำหนด** หายไปจากทุกช่อง ดูเหมือนไม่มีงาน
- Overdue กดไม่ได้ · "Due in next 7 days" ว่าง → ไม่มีรายการให้ลงมือ
- Active pipeline (กราฟแท่ง) บอกจำนวน แต่ไม่บอกว่าใครต้องทำอะไร / ค้างนานแค่ไหน
- Data health พับซ่อนไว้ · ตัวกรอง Tier ไม่ช่วยตามงาน

## 3. เดิม → ใหม่
- Dashboard › By campaign › **Pillar allocation** → ตัด (การ์ด · Export sheet · code) · Products given ขึ้นมาแทนที่ตำแหน่งเดิม
- Operations: tiles 5 ช่อง + Active pipeline + Due in next 7 days + Data health → **Summary 5 ช่อง (กดกรองได้) + Work queue + Stage flow + Team load + Data to fix**
- ตัวกรอง PIC · Campaign · Tier → **Assigned to** · Campaign · **Waiting on** (All / Us / KOL)

## 4. Spec

### 4.1 รายการงาน — `rules.workQueue(state, {person, campaignIds, waitingOn})`
ทุกงานค้างเป็น 1 แถว · ฟังก์ชันเดียวใช้ทั้งหน้า + Export

| แหล่ง | เงื่อนไข | Next action | รอใคร | Due |
|---|---|---|---|---|
| Deal · Contacted | — | Confirm quotation | Us | — |
| Deal · Confirm QT | — | Send brief | Us | — |
| Deal · Brief | Script ในแผน | Script from KOL | KOL | expected_script_date |
| Deal · Brief (ไม่มี Script) / Script | — | Draft 1 from KOL | KOL | expected_draft1_date |
| Deal · Draft k | มี Draft k+1 ในแผน | Draft k+1 from KOL | KOL | expected_draft{k+1}_date |
| Deal · Draft สุดท้าย | — | Approve content | Us | expected_approve_date (ถ้ามี) |
| Deal · Approve | — | Post from KOL | KOL | expected_post_date |
| Shipment | To ship / Shipped | Ship samples / Confirm delivery | Us | ship_by_date |
| Payment | To pay ที่ถึงกำหนดตาม term | Pay KOL | Us | วันครบกำหนดจ่าย |
| Metrics | Post แล้ว ครบ D+7 ยังไม่กรอก (CR-11) | Enter metrics | Us | post date + 7 |
| Approval | คำขอ Pending (Manager / Admin เท่านั้น) | Review request | Us | submitted + 2 วัน |

- **Shortlist ไม่อยู่ในรายการ** (เป็นรายชื่อ ไม่ใช่งานค้าง) · ดูได้ใน Stage flow
- Deal Cancel / Posted ไม่อยู่ (ยกเว้นงานหลังโพสต์: Payment · Metrics)
- **Stuck** = อยู่ stage เดิมนานกว่า `lookups.ops_stuck_days` (default 7 · Settings › Operations) และยังไม่ Overdue → badge "Stuck 12 d" (เป็น flag ไม่ใช่กลุ่ม)
- **Due ใช้ `rules.dueDate()` ตัวเดิม** (ไม่คำนวณใหม่)

### 4.2 Summary (แถวบน · กดแล้วกรอง Work queue)
| Tile | นับ |
|---|---|
| **Overdue** | due < วันนี้ (แดง) |
| **Due this week** | due วันนี้ – 7 วัน |
| **No due date** | งานที่ไม่มี due · บรรทัดรอง "n waiting on KOL" (ควรตั้งวัน) |
| **Stuck** | มี flag Stuck |
| **Waiting on us** | รอใคร = Us · บรรทัดรอง "n shipments · n payments · n metrics · n approvals" |
- tile ที่เลือกอยู่มีกรอบเน้น · กดซ้ำ = ยกเลิกกรอง · ค่า 0 แสดงเทา

### 4.3 Work queue (ตารางหลัก)
- จัดกลุ่มเป็น section ตาม due: **Overdue · Today · This week · Later · No due date** (section ว่างไม่แสดง · หัว section มีจำนวน · พับได้)
- คอลัมน์: **Due** ("3 d overdue" แดง / "Today" / "in 2 d" / "—") · KOL (รูป + ชื่อ) · Campaign · Stage · **Next action** · **Waiting on** (chip Us / KOL) · In stage (วัน · + Stuck) · Assigned to (ซ่อนเมื่อดูของคนเดียว) · ปุ่ม
- **ปุ่มบนแถว** (เห็นเลย ไม่ซ่อน): Deal → `Move stage` · Shipment → `Mark shipped` / `Mark delivered` · Payment → `Mark paid` · Metrics → `Enter metrics` · Approval → `Review` · ไม่มี due → ลิงก์ `Set date` (เปิด popover ตั้งวันของขั้นนั้นทันที)
- คลิกแถว (นอกปุ่ม) = Deal modal (tab ที่ตรงกับงาน: shipment → Shipments & posts · payment → Costs & payment)
- ภายใน section เรียง due เก่า → ใหม่ แล้ว In stage มาก → น้อย
- ทำงานเสร็จจากแถว → แถวหายพร้อม toast Undo · ตัวเลข Summary อัปเดตทันที
- มือถือ: แต่ละแถวเป็นการ์ด (Due + KOL + Next action + ปุ่ม)

### 4.4 Stage flow (แทน Active pipeline)
- แถบแนวนอน 1 แถว: Shortlist → Contacted → Confirm QT → Brief → Script → Draft 1–3 → Approve · แต่ละช่อง: จำนวน · "avg n d" (วันเฉลี่ยใน stage) · จำนวน Stuck (แดงถ้า > 0)
- คลิกช่อง = กรอง Work queue ตาม stage (Shortlist → เปิด Deals › Pipeline แทน)
- บรรทัดท้าย: "Posted n · Cancelled n" (เดิม)

### 4.5 Team load (เมื่อ Assigned to = Everyone · Manager / Admin)
- ตาราง 1 แถวต่อคน: Open deals · Overdue · Due this week · No due date · Stuck · Waiting on us
- เรียง Overdue มาก → น้อย · คลิกชื่อ = เปลี่ยน Assigned to เป็นคนนั้น

### 4.6 Data to fix (แทน Data health)
- section ท้ายหน้า ชื่อ "Data to fix (n)" · **กางอยู่ถ้า n ≤ 10** · แต่ละรายการมีลิงก์ `Fix` ไปช่องนั้นใน Deal modal (ใช้รายการ Missing เดียวกับ CR-22 §3.6)
- รวมรายการใหม่: shipment ไม่มี Ship by · Post date นอกช่วง Campaign (CR-23)

### 4.7 ตัวกรอง + อื่นๆ
- **Assigned to**: default = ตัวเอง (ถ้าอยู่ในรายชื่อ PIC) · Manager / Admin เลือก Everyone ได้ · ชื่อ tab "Operations · Amp" → **"Operations"** (ชื่อคนอยู่ในตัวกรองแล้ว)
- **Campaign** multi-select (เฉพาะ Approved · default ทุก Campaign ที่ไม่ Complete)
- **Waiting on**: All / Us / KOL
- ตัด Tier
- จำค่าตัวกรอง + section ที่พับ ต่อผู้ใช้ (localStorage)
- Export: sheet `Work queue` (คอลัมน์เดียวกับตาราง · ไม่มี PII)

### การตัดสินใจ (ตาม §6 หรือที่ spec ไม่ระบุ)
1. ไม่มีไฟล์ CLAUDE.md → ใช้กติกาถาวรเดิม
2. Anchor Amp จาก seed: deal ค้าง **9** = Contacted 1 · Brief 4 · Draft 1 4 (ภาพบอก Confirm QT 1 — ใน seed เป็น Contacted) · Posted 63 · Cancelled 3 ✓ · Draft 1 ทั้ง 4 มีแผน 1 รอบ → งานถัดไป = **Approve content (Us)** ตามตาราง §4.1 (ไม่ใช่งานรอ KOL อย่างที่ T1 เขียน) · Brief 4 = Script from KOL (KOL) · ไม่มี due ทั้ง 9 → No due date (8 แถวมี Set date · Contacted ไม่มีวันให้ตั้ง)
3. Work queue ของ Amp มี 27 แถว: deal 9 + Pay KOL 18 (deal ที่โพสต์แล้วถึงกำหนดจ่าย)
4. Shipped → Confirm delivery ไม่มี due (No due date) · KOL buys own (KOL purchase) ไม่อยู่ในรายการ · Payment = To pay ที่ Ready / Missing docs (ไม่รวม Not due · On hold · อยู่ใน run แล้ว)
5. Approval: ไม่มีเจ้าของ (PIC) → แสดงเมื่อ Assigned to = Everyone หรือเป็นตัวผู้ดูเอง · Team load ไม่นับ Approval
6. Stuck ใช้กับแถว deal เท่านั้น · In stage ของงานอื่น = วันนับจากวันครบกำหนด / วันที่สร้าง / วันที่ส่ง · deal จากไฟล์เก่าไม่มี log ที่มีวันที่ → In stage "—" และไม่ติด Stuck (seed: Stuck 0 ทั้งหมด)
7. Campaign filter default = Approved ที่ไม่ Complete / Cancelled (seed: CH · KS · PH — AC Complete แล้ว) · แถวที่ไม่มี Campaign (shipment ไม่มี deal) แสดงเสมอ
8. Everyone เลือกได้เฉพาะ Admin / KOL Manager · Staff ที่ไม่ใช่ PIC ยังเห็น Everyone เหมือนเดิม
9. Data to fix: แถวต่อสิ่งที่ต้องแก้ (deal ที่ Missing รวมเป็นแถวเดียวต่อ deal) · Term / Pillar not set ของ Data health เดิมอยู่ใน Missing แล้ว (ไม่ซ้ำ)
10. Undo ของ Mark shipped / delivered ใช้ได้ทุกที่ที่ใช้ปุ่มนี้ (หน้า Shipments · การ์ด Pipeline ด้วย)
