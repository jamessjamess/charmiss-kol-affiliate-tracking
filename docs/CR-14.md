## 4. Implementation details

### 4.1 Dashboard › All campaigns — Status (multi-select)
- ตำแหน่ง: scope bar ต่อจากช่วงวันที่ · **แทน checkbox Include cancelled** · ปุ่ม Export อยู่ขวาเหมือนเดิม
- ตัวเลือก (เรียงตาม sortCampaigns · มีจำนวน Campaign ที่ทับช่วงวันที่ · มีจุดสีตาม status chip เดิม): `On going` · `Not started` · `On hold` · `Complete` · `Cancelled`
- Status = effective status **ณ วันนี้** (CR-05 §4.7: cancelled > on_hold > ตามวันที่)
- **Default = ทุกค่ายกเว้น Cancelled** (= พฤติกรรมเดิมที่ไม่ติ๊ก Include cancelled)
- ป้ายบนปุ่ม: ครบ default → `Status: All except cancelled` · ทั้งหมด → `Status: All` · 1 ค่า → `Status: On going` · 2 ค่า → `Status: On going, Complete` · 3 ค่าขึ้นไป → `Status: 3 selected`
- ใน popover: ปุ่ม `Select all` · `Reset` (กลับ default) · ไม่ต้องมีช่องค้นหา (มี 5 ค่า)
- Scope ของทุก widget ใน tab = Campaign ที่**ทับช่วงวันที่ และ status อยู่ในที่เลือก** → KPI 5 cards · Campaign portfolio (รวมแถว Total) · Activity by campaign · Pillar mix · KOL tier mix
- เลือก 0 ค่า → ไม่อนุญาต (ค่าสุดท้ายติ๊กออกไม่ได้ · tooltip "Select at least one status")
- จำค่าต่อ user · ปุ่ม Clear all filters (ถ้ามีใน tab) นับเมื่อไม่ใช่ default
- Export: sheet `Summary` มีบรรทัด "Status: …" และช่วงวันที่ที่ใช้
- tab **By campaign** และ **Operations** ไม่เพิ่มตัวกรองนี้ · combobox Campaign ยังแสดง status chip ตามเดิม

### 4.2 `ui.multiSelect` — component เดียว + แก้ bug ช่องค้นหา
**Bug (screenshot Campaign & Phase › Table):** เปิด dropdown `All campaigns` แล้ว**ช่องค้นหาใน popover สูงผิดปกติ (~280px)** placeholder "Search campaign" ลอยกลางกล่อง · รายการ Campaign ถูกดันลงล่าง
- ให้หา root cause (น่าจะเป็น style ของช่อง Search หลักของหน้า เช่น `flex: 1` / `height: 100%` / selector กว้างเกิน ที่ไปโดน input ใน popover) แล้วแก้ที่ต้นเหตุ · scope CSS ของ component ด้วย class ของตัวเอง
- เขียน multi-select เป็น component เดียว `ui.multiSelect({ options, value, searchable, onChange, label })` แล้วเปลี่ยนทุกจุดมาใช้: Campaign & Phase (Table · Timeline) · Dashboard Status (§4.1) · Shipments / Filters ที่เป็น multi-select

| ส่วน | Spec |
|---|---|
| ปุ่ม (trigger) | สูงเท่า control อื่นในแถว (36px) · ป้าย `All campaigns` / ชื่อ 1 ค่า / `n selected` · ลูกศร ▾ |
| Popover | กว้าง ≥ ปุ่ม และ ≥ 280px · สูงสุด 400px · วางใต้ปุ่ม ชิดซ้าย (ล้นจอ → ชิดขวา) · ลอยเหนือ tabs / ตาราง |
| ช่องค้นหา (`searchable` เมื่อ > 7 ตัวเลือก หรือกำหนดเอง) | **บรรทัดเดียว สูง 32px** · ไอคอนแว่น · focus อัตโนมัติเมื่อเปิด · กรองรายการทันที (ไม่สนตัวพิมพ์ · ค้นภาษาไทยได้) · ไม่เจอ = "No matches" |
| รายการ | checkbox + ชื่อ (ขึ้นบรรทัดได้ ไม่ตัด) + chip status ชิดขวา · scroll ในตัวเมื่อเกินความสูง |
| Footer | `Select all` · `Clear` (หรือ `Reset` เมื่อมี default) |
| ปิด | คลิกนอก · Esc · ค่าเปลี่ยนทันทีที่ติ๊ก (ไม่ต้องกด Apply) |
| Keyboard | ↑ ↓ เลื่อน · Space ติ๊ก · Esc ปิด แล้วคืน focus ที่ปุ่ม |

### 4.3 Campaign & Phase › Table — ค้นหาตาราง (ช่อง `Search campaign or phase`)
ตรวจและแก้ให้ทำงานตามนี้ (`rules.filterCampaignTree(tree, query)`):
- ค้นจาก**ชื่อ Campaign** และ**ชื่อ Phase** (ไม่สนตัวพิมพ์ · ตัดช่องว่างหัวท้าย · ภาษาไทยได้ · พิมพ์แล้วกรองทันที debounce 150ms)
- ตรงชื่อ Campaign → แสดง Campaign + **ทุก Phase**
- ตรงเฉพาะชื่อ Phase → แสดงแถว Campaign (เป็นบริบท · ตัวเลขของ Campaign ทั้งก้อน) + **เฉพาะ Phase ที่ตรง** · Campaign กางอัตโนมัติ
- highlight คำที่ตรง · ไม่มีผล → empty state "No campaigns or phases match "…"" + ปุ่ม `Clear search`
- ใช้ร่วมกับ: Year · dropdown Campaign (§4.2) · Status tabs · Include cancelled (ของหน้านี้ยังเป็น checkbox เดิม) — ทุกตัวกรองเป็น AND
- **Status tabs** นับตามผลค้นหา + dropdown Campaign · แถว **Total** = ผลรวมของ Campaign ที่แสดง
- Search ใช้ร่วมทั้ง Table และ Timeline (CR-05) · ค่าคงอยู่เมื่อสลับ tab

### 4.4 KOL Master — `Last phase` → `Last campaign`

- **Bug ที่ต้องแก้ไปด้วย:** ตอนนี้ Last phase ไม่ได้มาจาก deal เดียวกับ Last worked — genygee28 แสดง Last worked 04/09/2026 (โพสต์ของ Charming Iconic Glow) แต่ Last phase เป็น "Phase 1 · KOL 30 Acc" (deal ของ Acne Fade Concealer ที่ยังอยู่ขั้น List ไม่มีโพสต์)

- KOL drawer / Export KOL Master: เปลี่ยนชื่อคอลัมน์เป็น `Last campaign` และใช้ค่าเดียวกัน

### 4.5 KOL — `contact_id`
- **KOL drawer › Profile:** บรรทัด `Contact` = `contact_channel` (select เดิม) + ช่อง `contact_id` (placeholder ตาม channel เช่น "LINE ID") · โหมดอ่าน: "LINE · kolsample.a" + ปุ่ม copy (copy เฉพาะ contact_id) · ว่าง = "—"
- **Validation (Error):** `rules.looksLikePhone(text)` = ตัด `-` ช่องว่าง `+` แล้วเป็นตัวเลขล้วน ≥ 9 หลัก → "Phone numbers can't be saved here. Use Payee vault." · ไม่เกิน 120 ตัวอักษร
- **Info:** มี contact_channel แต่ contact_id ว่าง → "Add the contact ID so the team can reach this KOL"
- **KOL Master ตาราง:** ไม่เพิ่มคอลัมน์ · Search ค้นจาก contact_id ได้ · Filters เพิ่ม `Contact: Has contact ID / Missing contact ID`
- **New KOL modal (CR-11) / Create KOL ใน New deal:** มีช่อง Contact channel + Contact ID
- **Export KOL Master:** เพิ่มคอลัมน์ `contact_channel` · `contact_id`
- สิทธิ์: ดูได้ทุก role · แก้ตามสิทธิ์แก้ KOL เดิม (CR-05)

### 4.6 Import KOL — Template ใหม่
- Template อ้างอิง: `KOL_Master_Import_Template.xlsx` (ชีท KOL_Import) / `.csv` — 10 คอลัมน์ตามลำดับ: `display_name` · `platform` · `profile_link` · `followers` · `kol_category` · `kol_type` · `gender` · `pic` · `contact_channel` · `contact_id`
- **คอลัมน์ที่รู้จัก** (ลำดับไม่สำคัญ · ไม่สนตัวพิมพ์ · ตัดช่องว่างหัวท้าย): `display_name*` · `platform*` · `profile_link*` · `followers*` · `kol_category` · `kol_type` · `gender` · `pic` · `contact_channel` · `contact_id` · (ไฟล์เก่า) `rate_card` · `gencode_expense` · `gencode_period` · `basket_fee` · `asset_fee` · `expediting_fee` · `note`

- preview เดิม (match · new account · new KOL · error) · `kol_type` match ตาม CR-07
- ไฟล์ CSV มี BOM UTF-8 ได้ (Excel "CSV UTF-8") · ตัวเลข followers ที่มีลูกน้ำ ("125,000") อ่านเป็น 125000
