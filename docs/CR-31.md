# CR-31 — Campaign mix · Deals toolbar · Move stage dialog

ใช้กติกาถาวรใน CLAUDE.md · ช่องบังคับต่อ stage อยู่ที่ `rules.stageRequirements()` ที่เดียว · ที่อยู่เก็บใน vault (เข้ารหัส CR-16) เท่านั้น

## 1. เดิม → ใหม่
- By campaign ไม่มีกราฟ mix → + **Pillar mix · KOL tier mix · Platform mix** ใต้ Budget vs Actual (§2.1)
- Deals: ไอคอนพับเล็กข้าง Group by · view switch จาง → ปุ่ม **Expand all / Collapse all** · switch แบบ segmented เด่น (§2.2)
- Ship to มีแค่ dropdown ที่อยู่เดิม / Choose later → + **New address** กรอกในที่ แล้วบันทึกเข้า KOL Master (§2.3)
- ลาก 1 ขั้นที่ข้อมูลครบ = ย้ายทันที · ช่อง "Date" ไม่บอกว่าวันอะไร → ลากเข้า Draft / Approve **ต้องยืนยันวันที่ทำเสร็จ** · ทุกช่องวันที่มีชื่อชัด (§2.4)
- ย้ายทันทีไม่มีที่ใส่ Note · Note อยู่แค่ใน log → **Note ทุก stage** แสดงใน Timeline (§2.5)
- Contacted dialog หัวข้อ "Confirm QT details" · เติม Rate card ให้ → หัวข้อ **Contacted details** · ไม่เติมค่า · มี Note (§2.6)
- แถบแดงภาษาไทย "บันทึกลงเครื่องไม่ได้ — กด Backup ก่อนปิดหน้า" → หาสาเหตุ + ภาษาอังกฤษ (§2.7)

## 2. Spec

### 2.1 By campaign — แถว mix
- วางต่อจาก **Budget vs Actual by month** · 3 การ์ดเท่ากัน ใช้ component เดียวกับ All campaigns (CR-29) · กรอง Campaign / Phase ของหน้า
- ข้อความเตือน "x% of spend has no pillar · Set default pillar per phase" ลิงก์ไปหน้า Edit ของ Campaign นี้

### 2.2 Deals toolbar
- view switch **Table · Pipeline · Performance** เป็น segmented control ขนาดเท่าปุ่มอื่น (ตัวหนา · ตัวที่เลือกพื้นเข้ม / ตัวอักษรขาว · ไม่ใช่ข้อความเทา) · วางชิดซ้ายของแถว 2 (ก่อน status chips) ให้เห็นก่อน
- แทนไอคอนพับข้าง Group by ด้วยปุ่มข้อความ `Expand all` · `Collapse all` (แบบ Campaign & Phase) ชิดขวา
  - Table: พับ / กางกลุ่มตาม Group by · Pipeline: พับ / กาง Posted + Cancelled + lane ที่ว่าง
- จำค่า view + พับ/กาง ต่อผู้ใช้

### 2.3 Ship to — กรอกที่อยู่ได้ทันที
- dropdown Ship to: ที่อยู่เดิมของ KOL (label) · **+ New address** · Choose later
- เลือก New address → ถ้า vault ล็อก: ปุ่ม `Unlock to add` ในที่ · ปลดแล้วกางฟอร์ม: Label · Recipient name · Address · Phone · ☑ Set as default
- บันทึกพร้อม Move → สร้าง `shipping_addresses` ของ KOL (เข้ารหัส) + ผูกกับ shipment · แสดงเป็น label "Home · Bangkok" ทุกที่
- ใช้ได้ทั้ง Move stage · Deal modal › Shipments · หน้า Shipments (แถว Missing address)
- ยัง optional ("Choose later" ได้)

### 2.4 วันที่ที่ทำเสร็จ + ชื่อวันที่
- ช่อง Date ใน Move stage เปลี่ยนชื่อตามปลายทาง:
  | ปลายทาง | ชื่อช่อง |
  |---|---|
  | Contacted | Contacted on \* |
  | Confirm QT | QT confirmed on \* |
  | Brief | Brief sent on \* |
  | Script | Script approved on \* |
  | Draft k | **Draft k done on \*** |
  | Approve | Approved on \* |
  | Post | Posted on \* |
- ช่องวันคาดใน Next expected ใช้ชื่อ "**Draft 2 due**" · "Draft 3 due" · "Script due" · "Post due" (แทน "Expected Draft 2 date")
- Deal modal › Timeline: คอลัมน์ "Expected / Done" → "**Due / Done on**"
- **ลากเข้า Draft 1 / 2 / 3 หรือ Approve = เปิด dialog เสมอ** (แม้ข้อมูลครบ) · ค่าเริ่ม "Draft k done on" = วันที่ลาก · กด Enter = Move · stage อื่นที่ข้อมูลครบยังย้ายทันทีเหมือนเดิม (+ toast มี `Add note`)

### 2.5 Note ทุก stage
- ทุก Move stage dialog มีช่อง **Note** (optional · บังคับเฉพาะถอยหลัง / ออกจาก Cancelled ตามเดิม) · ตัดชื่อ "Note for history"
- Draft k: ช่อง Note ของ "Draft k notes" กับ Note ทั่วไปรวมเป็นช่องเดียว (ไม่มี 2 ช่องชื่อ Note)
- บันทึกใน `step_notes` ของขั้นนั้น (ทุก step_key) + History
- ย้ายทันที (ไม่เปิด dialog) → toast "Moved to Brief · Undo · Add note" · Add note เปิดช่องเล็ก
- Deal modal › Timeline คอลัมน์ Links / notes: แสดง note ย่อ 1 บรรทัด + tooltip ทุกขั้น (ไม่ใช่แค่ Draft)

### 2.6 Contacted dialog
- หัวข้อส่วน "Confirm QT details" → **Contacted details**
- CTA \* (ว่างเริ่มต้น · กติกา CR-22) · Rate card / Payment term **optional และว่างเสมอ** (ไม่เติมแม้ deal มีค่า · แสดง hint "Current ฿2,500" + "Last rate card…" · เว้นว่าง = ไม่เปลี่ยนค่าเดิม)
- Note (§2.5) ใช้เป็น Remark ของการติดต่อ

### 2.7 แถบ "บันทึกลงเครื่องไม่ได้"
- ข้อความเป็นภาษาอังกฤษ: "Can't save on this device — back up before closing" · ปุ่ม `Backup now`
- **หาสาเหตุ** และรายงาน: localStorage เต็มหรือไม่ (ขนาดปัจจุบัน / quota) · มีข้อมูลใหญ่ที่ควรอยู่ IndexedDB (รูป · notes · log) หรือไม่ · ถ้าเต็มจริง ให้ย้าย store ที่ใหญ่สุดไป IndexedDB + แสดงขนาดที่ใช้ใน Settings › Data ("Using 4.6 MB of ~5 MB")
- แถบแสดงเฉพาะเมื่อเขียนไม่สำเร็จจริง · หายเมื่อเขียนได้อีกครั้ง

### สาเหตุแถบ "บันทึกลงเครื่องไม่ได้"
- localStorage มีที่ประมาณ **5 MB ต่อเว็บ** (ทุก key รวมกัน) · ข้อมูลทำงาน (seed) = **1.34 MB** (deals 0.34 · kol_master 0.27 · deal_status_log 0.17 · kol_accounts 0.16 · deal_posts 0.14)
- ทุกครั้งที่อัปเกรด schema แอปเก็บ **สำเนาข้อมูลทั้งก้อนก่อนอัปเกรด** (`_before_v12` · `_before_v14` · `_before_v15`) และข้อมูลที่อ่านไม่ได้ (`_corrupt`) ไว้ใน localStorage และไม่เคยลบ → 2–3 สำเนา + ข้อมูลจริง ≈ เต็ม 5 MB → save ข้อมูลจริงไม่ผ่าน (QuotaExceededError) → แถบแดง
- รูปโปรไฟล์ / รูปใน notes อยู่ใน IndexedDB อยู่แล้ว (CR-16 / CR-20) ไม่ใช่สาเหตุ · อีกกรณีที่ขึ้นแถบได้คือหน้าต่าง Private
- แก้: สำเนาเหล่านั้นย้ายไป IndexedDB (ดาวน์โหลดได้เหมือนเดิม) · ข้อมูลทำงานยังอยู่ localStorage (1.3 MB จาก ~5 MB ยังเหลือที่มาก) — ไม่ย้าย store ของข้อมูลจริงไป IndexedDB เพราะต้องเปลี่ยนการโหลดทั้งแอปเป็น async โดยไม่จำเป็น
