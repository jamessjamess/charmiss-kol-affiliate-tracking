## 4. Implementation details

### 4.1 ลำดับขั้นของ deal — `rules.dealPlan(deal)`
`[Shortlist] → [Contacted] → Confirm QT → Brief → Script → Draft 1 → [Draft 2] → [Draft 3] → Approve → Post`
- Draft 2 / 3 ตาม `draft_rounds` (กติกา CR-02 เดิม · `+ Add draft round` เดิม · สูงสุด 3)
- **Script และ Approve อยู่ในแผนของทุก deal เสมอ** (ไม่มี toggle)
- Group: Script · Draft 1–3 · Approve = **In process** (สีน้ำเงิน) · Post = Complete

### 4.2 ย้ายขั้น (Move stage / ลากการ์ด)
- ถอยหลังได้ตามกติกาเดิม
- **ข้ามขั้นไปข้างหน้าได้** (เช่น Brief → Draft 1 หรือ Draft 2 → Post) → dialog แสดง "These steps will be marked done on dd/mm: Script, Approve" · ขั้นที่ข้ามได้วันที่ = วันที่ย้าย + บันทึก `deal_status_log` ทีละขั้น (note "auto-completed") — ข้อมูลวันที่ของทุกขั้นจึงครบเสมอ
- Guard เดิมคงอยู่: Confirm QT ต้องมี Payment term + Pillar · Post ต้องมีลิงก์ + วันที่ทุกโพสต์
- เข้า **Approve** → ไม่มี guard เพิ่ม · `approved_date` = วันที่ย้าย (แก้ได้ใน drawer)

### 4.3 Due date / Overdue — `rules.dueDate(deal)`
ขั้นถัดไปของ deal → วันที่คาดไว้:
| ขั้นถัดไป | ใช้วันที่ |
|---|---|
| Script | `expected_script_date` (ว่าง = ไม่มี due) |
| Draft k | `expected_draft{k}_date` (เดิม) |
| Approve | `expected_approve_date` (ว่าง = ไม่มี due) |
| Post | `expected_post_date` (เดิม) |
- Overdue · Next due ในตาราง · Dashboard › Operations · Due in next 7 days ใช้ฟังก์ชันนี้ตัวเดียว
- Shipments `ship_by` (CR-10) ไม่เปลี่ยน: Draft 1 expected (หรือ post) − lead days
