# CR-32 — Address & payee ในหน้า · Delivered ตั้งแต่ Draft 1 · Payment documents

ใช้กติกาถาวรใน CLAUDE.md · ที่อยู่ / เลขบัญชี เก็บใน vault (เข้ารหัส CR-16) เท่านั้น · แสดงเป็น label

## 1. เดิม → ใหม่
- Deal modal › Shipments: ลิงก์ "Add address" ใช้ไม่ได้ / ไม่รู้ไปไหน · Payments › "Payee details ↗" ออกไปหน้าอื่น → **เพิ่มได้ในที่** + ลิงก์ `Open in KOL Master` (§2.1)
- Mark sample as delivered มีแค่ตอน Post → **ตั้งแต่ Draft 1** (§2.2)
- Partner type มี KOL · Affiliate · Both (CR-25) · CR-30 ตัด Both แค่ตอนสร้าง แต่ header / ตัวกรองยังมี → **ตัด Both ทั้งระบบ** (§2.4)
- Documents: ID copy · Bank book · Bank details (note + link ทุกรายการ) → **ID copy · Bank book · Post proof** + ตัวเลือก **All documents in one file** + **Note รวม** (§2.3)

## 2. Spec

### 2.1 Add address / payee ในหน้า
- **Deal modal › Shipments & posts:** "Ship to (default): No address · `Add address`" →
  - กดแล้ว vault ล็อก → ปุ่ม `Unlock to add` ในที่ · ปลดแล้วกางฟอร์มเดียวกับ CR-31 §2.3 (Label · Recipient · Address · Phone · ☑ Set as default)
  - บันทึก → `shipping_addresses` ของ KOL + ตั้งเป็น Ship to ของ shipment ที่ยัง To ship (ถามก่อน "Use for 1 open shipment?")
  - ลิงก์เล็ก `Open in KOL Master` → เปิด KOL modal › tab Payee & shipping (ซ้อนบน Deal modal · มี ‹ Back)
- **Payments › Payment details › Pay to:** "No payee yet · `Add payee`" → ฟอร์มในที่ (Bank · Account name · Account number · ☑ Default) ผ่าน vault เหมือนกัน · บันทึกแล้วผูกกับแถวจ่ายนี้ · `Open in KOL Master` เหมือนกัน
- หน้า Shipments แถวที่ "Missing" address → ลิงก์ `Add address` ใช้ฟอร์มเดียวกัน

### 2.2 Mark sample as delivered ตั้งแต่ Draft 1
- Move stage ปลายทาง **Draft 1 / 2 / 3 / Approve / Post** และ shipment ยังไม่ Delivered → แสดง ☑ **Mark sample as delivered** + วันที่ (default = วันที่ Move)
  - **ติ๊กไว้ให้** เมื่อปลายทาง = Draft 1 ขึ้นไป (KOL ทำงานได้แปลว่าได้ของแล้ว) · เอาออกได้
  - KOL buys own → ข้อความเดียวกันเป็น "Mark product as purchased"
- shipment ที่ยัง To ship (ไม่เคย Mark shipped) → ติ๊กแล้วบันทึก Shipped + Delivered วันเดียวกัน
- Deal modal › Shipments: ปุ่ม `Delivered` ใช้ได้ทุก stage ตั้งแต่ Confirm QT (เดิมมีแล้ว · ตรวจว่าไม่ซ่อน)
- เก็บตก (จากภาพ): Posted link ที่ domain ไม่ตรงกับแพลตฟอร์มของ account (เช่น Instagram แต่ใส่ facebook.com) → เตือนส้ม "This link isn't an Instagram link" (ไม่บล็อก)

### 2.3 Payment documents
| รายการ | ช่อง |
|---|---|
| ☐ **ID copy** | ☑ Received · วันที่ · Link |
| ☐ **Bank book** | ☑ Received · วันที่ · Link |
| ☐ **Post proof** (ใหม่) | ☑ Received · วันที่ · Link · **Posted on** (prefill จาก Post date ของ deal · แก้ได้) · hint "Screenshot of the live post showing the post date" |
- ตัด **Bank details** ออกจากรายการ default (ข้อมูลบัญชีอยู่ใน Pay to / vault แล้ว) · ข้อมูลเดิมที่ติ๊กไว้คงอยู่เป็นรายการ custom
- ตัดช่อง Note รายรายการ → **Note รวม** 1 ช่องท้ายส่วน Documents
- ☐ **All documents in one file** (บนสุดของส่วน Documents):
  - ติ๊กแล้ว → ซ่อน 3 รายการ แสดงแค่ Link (บังคับ · https) + วันที่ได้รับ + Note รวม
  - นับเป็นครบ "Docs 3/3" เมื่อมี Link
  - เอาติ๊กออก → กลับไปแสดงรายการเดิม (ค่าเดิมยังอยู่)
- `+ Add document` ยังใช้ได้ (ซ่อนเมื่อ All in one file)
- คำเตือนเดิม "don't type ID card or bank account numbers here" และการตรวจเลขยาว (CR-27) ใช้กับ Note รวม / Link
- เก็บตก: บรรทัด "Includes Other: - · ฿100" → ถ้า Other fee note ว่างหรือ "-" แสดง "Includes other fee ฿100"

### 2.4 ตัด Partner type "Both" ทั้งระบบ
- `lookups.partner_types` เหลือ **KOL · Affiliate** (แก้ CR-25 · CR-30)
- KOL Master header: `912 partners (KOL 912 · Affiliate 0 · Both 0) · 928 accounts` → **`912 partners · KOL 912 · Affiliate 0 · 928 accounts`**
- ตัวกรอง Partner (KOL Master · New deal · Deals): **All partners · KOL · Affiliate**
- ตัด Both ออกจาก: KOL modal › Overview · Bulk edit › Set partner type · Import (ค่า `both` = error แถว "Use KOL or Affiliate") · Export · Dashboard KPI / tooltip การ์ด KOL & Affiliate engaged · chip `KOL+AFF`
- ข้อมูลเดิม `both` (ถ้ามี) → `kol` ตอนโหลด + log "partner_type both → kol" · ค้นในโค้ดว่าไม่เหลือ `'both'` นอก migration

### 2.5 Payment readiness + Export for accounting (v1.2)
**เทียบ Export ปัจจุบัน กับ PR sheet ที่ทีมใช้** (เทียบเฉพาะคอลัมน์ · ห้ามคัดลอกข้อมูลจริงลงโค้ด / seed / test)

| ประเด็น | Export ระบบตอนนี้ | PR sheet | แก้เป็น |
|---|---|---|---|
| Project | ชื่อ Campaign ("Campaign Nov - Dec") | ชื่อสินค้า (เช่น Kiss Signal Lip Gloss) | **ชื่อสินค้าของ deal** (หลายตัวคั่น ", ") · ไม่มีสินค้า = ชื่อ Campaign |
| ชื่อ-นามสกุล · ที่อยู่ตามบัตร · ธนาคาร · เลขบัญชี | ว่าง (ยังไม่มี payee ก็ส่งได้) | ครบทุกแถว | **บังคับก่อนส่ง** (§ด้านล่าง) |
| Link เอกสาร | ใส่ Post link (facebook.com) ผิดช่อง | ลิงก์ Google Doc / Drive ของเอกสาร | ใช้ลิงก์ **All in one file** หรือรวมลิงก์ ID copy · Bank book · Post proof (คั่นบรรทัด) · ไม่ใช้ Post link |
| Payee ID / Line ID | Payee ID ว่าง · "PL-000005" ไปอยู่ช่อง Line ID (คอลัมน์เลื่อน) | ไม่มี | แก้บั๊กคอลัมน์เลื่อน · Payee ID ย้ายไปท้าย · **ตัด Line ID** |
| เบอร์โทร · ส่งแล้ว (Earn) · WHT rate | มี | ไม่มี | ตัด (ลดข้อมูลส่วนตัวในไฟล์) · WHT rate รวมเป็นหัวคอลัมน์ "WHT 3%" |
| Email / ที่อยู่ส่งใบ WHT | มี | ไม่มี | คงไว้ท้ายตาราง (ใช้ส่งหนังสือรับรองหัก ณ ที่จ่าย) |
| แยก sheet | 1 sheet ต่อรอบ | 1 tab ต่อช่วงยอด + วันที่ ("ยอดน้อยกว่า 1,000 dd/mm/yy" · "ยอด 1,000-3,000 dd/mm/yy") | **1 sheet ต่อช่วงยอด** · ชื่อ sheet แบบเดียวกับ PR · ช่วงยอดตั้งได้ที่ Settings › Payments (default < 1,000 · 1,000–3,000 · > 3,000) |
| ยอด < 1,000 | มีคอลัมน์ VAT / WHT เป็น 0 | ไม่มีคอลัมน์ VAT / WHT | sheet < 1,000 ตัดคอลัมน์ VAT / WHT |

**ลำดับคอลัมน์ Export (ตาม PR):** No · Project · ชื่อ Account · Type (KOL / AFF) · ชื่อ-นามสกุล · ที่อยู่ตามบัตรประชาชน · ธนาคาร · เลขบัญชี · จำนวนเงิน · VAT 7% · WHT 3% · จำนวนเงินที่ต้องชำระ · Link (สำเนาบัตร หน้า Bookbank หลักฐานการลงคลิปพร้อมวันที่ลงงาน) · PIC · Print (สำหรับดรีม) · Email / ที่อยู่ส่งใบ WHT · Payee ID · Deal ID
- แถวบนสุด "รอบจ่าย: PR-yyyy-mm-dd · วันจ่าย dd/mm/yyyy" · แถวท้าย "รวม" ต่อ sheet
- ตัวเลขเป็น number (ไม่ใช่ข้อความ) · ธนาคารใช้ชื่อสั้นแบบ PR (กสิกร · กรุงไทย · ไทยพาณิชย์ · กรุงศรี · กรุงเทพ …) จาก `lookups.banks`

**Ready to send — ต้องครบก่อน `Send to accounting` / Export** (`rules.paymentReadiness(line)`)
| ช่อง | ที่มา | บังคับ |
|---|---|---|
| ชื่อ-นามสกุล (ตามบัตร) | Payee profile (vault) | ✓ |
| ที่อยู่ตามบัตรประชาชน | Payee profile (vault) · **ฟิลด์ใหม่** แยกจากที่อยู่ส่งของ | ✓ |
| ธนาคาร · เลขบัญชี · ชื่อบัญชี | Payee profile (vault) | ✓ |
| เอกสาร | All in one file **หรือ** ID copy + Bank book + Post proof (มีลิงก์) | ✓ |
| โพสต์แล้ว (Post link + Post date) | deal | ✓ เมื่อ term = Pay after post |
| Project (สินค้า) | deal | ✓ (ขาด = ลิงก์ Add products) |
| จำนวนเงิน > 0 · Payment term | deal | ✓ |
| Email / ที่อยู่ส่งใบ WHT | Payee profile (vault) · **ฟิลด์ใหม่** | เตือน (ไม่บล็อก) เมื่อ WHT > 0 |
| PIC | Assigned to | ✓ |

- Payment details มีกล่อง **Ready to send** แสดง ✓ / ✗ ทุกข้อ · ข้อที่ขาดกดแล้วไปกรอกในที่ (Add payee · Add documents · Add products)
- ตาราง To pay: chip "Ready" (เขียว) / "Missing 2" (ส้ม · tooltip บอกรายการ) · ตัวกรอง **Ready / Not ready**
- `Send` / `Send to accounting` / Export: แถวที่ไม่ครบ = กดไม่ได้ (tooltip รายการที่ขาด) · bulk ส่งเฉพาะแถวที่ครบ + แจ้ง "3 lines skipped — missing details"
- Manager / Admin: `Send anyway` ได้ (ต้องใส่เหตุผล · log)
- `Mark paid` ไม่บังคับ readiness (กรณีจ่ายนอกระบบไปแล้ว) แต่แสดงเตือนรายการที่ขาด

**ฟิลด์ใหม่ใน Payee profile (vault · เข้ารหัส):** Full name (as on ID) · ID-card address · Email / address for WHT certificate (เดิมมี Bank · Account name · Account number)
- ไม่เก็บเลขบัตรประชาชน (ใช้ลิงก์สำเนาบัตรแทน ตามที่ทีมทำอยู่)

**Export มีข้อมูลส่วนตัว**
- ต้อง Unlock vault ก่อน · เฉพาะ Manager / Admin (Staff เห็นปุ่มเทา "Ask a manager to export")
- ไม่เก็บไฟล์ในแอป · log เก็บแค่ "exported n lines · PR-…" ไม่เก็บเนื้อหา
- ข้อความใต้ปุ่ม: "This file contains personal and bank details — share only with accounting"

### การตัดสินใจ (ตาม §4 หรือที่ spec ไม่ระบุ)
1. Post proof อยู่ในรายการเฉพาะงวดที่จ่าย **หลังโพสต์** (Pay after post · งวด Final ของ 50/50) — งวด Prepaid / Deposit ยังไม่มีโพสต์ จึงมี 2 รายการ (Docs n/2) · payee แบบบริษัทใช้ Company certificate · Bank book (· VAT certificate) แทน ID copy
2. Post proof ไม่ติ๊กเองจากโพสต์ (เดิม Post evidence ติ๊กเองเมื่อมีลิงก์ + วันที่) — เป็นเอกสารที่ต้องเก็บ · ID copy / Bank book ที่บันทึกไว้ใน Payee profile ยังนับว่าได้รับ (ใช้ Docs folder ของ payee เป็นลิงก์)
3. Bank details ไม่ใช่เอกสารแล้ว แต่ยังเป็นสิ่งที่ "ขาด" สำหรับสถานะ Missing docs / การตรวจรอบจ่าย (Full mode) เหมือนเดิม
4. "Pay after post" ใน readiness ใช้กับงวดที่จ่ายหลังโพสต์ทุกแบบ (รวม Final ของ 50/50)
5. ฟอร์ม Add payee ในที่มี Full name (as on ID) · ID-card address · Email WHT ด้วย (spec §2.1 ระบุแค่ Bank · Account name · Account number แต่ T7 ต้องเป็น Ready หลังเพิ่ม) · label อัตโนมัติ Primary / ชื่อธนาคาร
6. ช่วงยอด: ค่าเดิม 1,000 · 10,000 ที่เก็บใน Settings เปลี่ยนเป็น 1,000 · 3,000 ครั้งเดียว (`bands_cr32`) · ช่วงกลางรวมยอด 3,000 พอดี ("ยอด 1,000-3,000") · คำเตือน "ยอดสูง" ในรอบจ่ายยังเป็น ฿10,000
7. ชื่อ sheet ใช้วันที่แบบ ddmmyy ("ยอด 1,000-3,000 091026") — Excel ไม่ยอมให้มี "/" ในชื่อ sheet
8. Export ทั้ง Simple (Export for accounting · Export again) และ Full (Export PR ของรอบ) = ผู้มี permission **`payment.export`** (Role Management › Payments) — Admin · KOL Manager · Accounting · **Phase 1: Staff ทุกคน** (แก้ตามผู้ใช้ 09/10/2026 · ปิด Staff ภายหลัง = แก้ค่า `staff` ของแถวนี้ใน rules-roles.js) · ต้องใส่ passphrase ของ vault ตอน export · คนที่ไม่มีสิทธิ์ดูรายละเอียด payee (`payee.unlock` — Staff) ปลดล็อกได้เพื่อไฟล์นั้นเท่านั้น: vault ล็อกกลับทันทีหลังสร้างไฟล์ และยังไม่เห็นเลขบัญชีบนหน้าจอ · ไม่มี "Export without payee details" อีก · log เก็บว่าใคร export
9. ข้อความ "share only with accounting" อยู่ใน dialog ก่อน export และ tooltip ของปุ่ม (แถบ bulk แคบ)
10. Summary sheet ยังอยู่ท้ายไฟล์ (สรุปต่อช่วงยอด)
11. Partner type ยังให้เปลี่ยนชื่อคำได้ใน Settings (2 รายการ)
12. ทดสอบด้วยข้อมูลสมมติเท่านั้น (ชื่อ / ที่อยู่ / บัญชี / ลิงก์ "made-up" · passphrase สมมติ) · ภาพไฟล์ export ปิดคอลัมน์ข้อมูลส่วนตัว
