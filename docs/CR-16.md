## 4. Implementation details

### 4.1 KOL profile modal (แทน drawer)
- คลิกแถวใน KOL Master / ชื่อ KOL ในหน้าอื่น → **modal L** (`ui.createModal` ขนาด L · CR-11) · route `#kol/K0001/overview` (ลิงก์ตรงได้ · Back ของเบราว์เซอร์ปิด modal)
- **Header (sticky):** รูปโปรไฟล์ 64px · ชื่อ + copy · ID · Tier · Status · platform + followers · PIC · ปุ่ม `Add to campaign` · `Edit` · ✕ · ปุ่ม ‹ › (และคีย์ ↑ ↓) เลื่อนไป KOL ก่อน / ถัดไปตามลำดับในตารางที่กรองอยู่ (ผ่าน dirty check)
- **แถบสรุป (ใต้ header ทุก tab):** Deals n · Committed ฿ (ไม่นับ Cancel) · Last worked · Last campaign · On-time badge · Latest rate

| Tab | เนื้อหา | ตัวเลขบน tab |
|---|---|---|
| **Overview** | 2 คอลัมน์: ซ้าย Profile (Category · Type · Gender · Contact · KOL status · Default payment term · Note · Source) · ขวา Accounts (+ Add account) และ **Current deals** (deal ที่ยังไม่ปิด + แถบ Journey ย่อ) | — |
| **Deals & history** | History ตาม Campaign (เดิม) + ตัวกรอง All / Open / Posted / Cancelled · แถวคลิกเปิด Deal drawer (ซ้อนเหนือ modal) · สรุป "n deals in n campaigns · ฿x" | จำนวน deal |
| **Performance** | ตัวเลขเดิม (On-time · Avg delay · Late posts · Overdue now · Avg draft rounds · Completion · Avg views / post · ER · CPV) + ตารางโพสต์ทั้งหมด (Campaign · platform · post date · views · ER · ลิงก์) + โพสต์ที่ช้า | จำนวนโพสต์ |
| **Rates** | Price reference (Latest / Average CR-07) · **Rate history** ตารางเดียวรวม 2 แหล่งเรียงวันที่ใหม่ก่อน: ราคาที่เสนอ (rate quotes · + Add rate) และราคาที่ตกลงใน deal (Campaign · ฿ · stage) · ไม่นับงานฟรี (CR-07) | จำนวนรายการ |
| **Payee & shipping** | §4.2 · §4.3 | n payees · n addresses |

- `Edit` = แก้ Profile ใน tab Overview (inline) · ปุ่ม Save / Cancel ล่าง modal · dirty check เมื่อปิด / เปลี่ยน tab / เลื่อน KOL
- จำ tab ล่าสุดต่อ user · เปิดจาก Payments chip "Missing: Bank details" → เปิดที่ tab Payee & shipping ทันที
- ซ้อน 1 ชั้นได้ตาม CR-11 (เช่น `+ Add account`, `+ Add payee` เป็น modal M เหนือ modal นี้ · Deal drawer เหนือ modal)
- มือถือ < 768px: เต็มจอ · tabs เลื่อนแนวนอน

### 4.2 Payee หลายรายการต่อ KOL
- tab Payee & shipping › ส่วน **Payees**: การ์ดต่อ payee: Label · ★ Default · Payee type · VAT / WHT · Bank ···1234 · เอกสาร (✓ / Missing) · Verified · ปุ่ม `Edit` · `Set as default` · `Archive`
- `+ Add payee` (modal M): Label * · Payee type · VAT registered · Default WHT · Price basis · Bank details (เข้ารหัส · กติกา CR-08) · เอกสาร · Docs link · ตั้งเป็น default ได้
- กติกา: มี default 1 รายการเสมอ (payee แรกเป็น default อัตโนมัติ) · payee ที่ถูกใช้ใน payment line แล้ว **ลบไม่ได้ → Archive** · Archive default ไม่ได้จนกว่าจะตั้ง default ใหม่ · เปลี่ยนบัญชี → Verify ตาม CR-08
- **เลือกผู้รับเงิน:**
  - Deal drawer › Payment: `Pay to: [Default · Primary ▾]` → เลือก payee อื่นของ KOL นั้น (`deals.payee_id`) · บันทึก `deal_events` type `payee`
  - Payments › To pay: แสดง label payee ถ้าไม่ใช่ default · Missing docs คิดจาก payee ที่เลือก · ก่อน Add to run เปลี่ยนได้จาก ⋯ › `Change payee`
  - line ที่ Add to run แล้ว ล็อก payee (`payee_id` + `payee_version_at_submit` เดิม)
- Export PR · WHT summary ใช้ payee ของแต่ละ line (ไม่เปลี่ยนรูปแบบไฟล์)
- Import payee details (CR-08): เพิ่มคอลัมน์ไม่บังคับ `payee_label` · KOL ที่มี payee อยู่แล้ว → เลือกใน dialog: `Add as another payee` / `Replace default` / `Skip`

### 4.3 ที่อยู่ส่งของหลายรายการต่อ KOL
- tab Payee & shipping › ส่วน **Shipping addresses**: การ์ดต่อที่อยู่: Label · ★ Default · "Address on file" (ล็อก) หรือรายละเอียดเต็ม (Unlock ตามสิทธิ์ CR-10) · `Edit` · `Set as default` · `Archive`
- `+ Add address` (modal M): Label * · Recipient * · Phone · Address * (เข้ารหัสทันที) · ตั้งเป็น default ได้
- **เลือกที่อยู่ต่อ shipment:** Deal drawer › Shipments / Shipments module / New shipment / Mark shipped → `Ship to: [Default · บ้าน ▾]` (`sample_shipments.address_id`) · ว่าง = default ณ ตอน Mark shipped แล้วบันทึก address_id ที่ใช้จริง
- Shipments ตาราง: คอลัมน์ Address แสดง label + "on file" / "missing" · Export shipping list / Print pick list (Unlock) ใช้ที่อยู่ของแต่ละ shipment
- สิทธิ์ตาม CR-10 เดิม (Staff เพิ่ม / แก้ได้กับ KOL ของตัวเอง · ดูเต็มได้เฉพาะ Admin / KOL Manager / Accounting เมื่อ Unlock)

### 4.4 รูปโปรไฟล์ KOL
- ใส่รูป: ใน modal header คลิก avatar → `Upload photo` (เลือกไฟล์) · ลากไฟล์มาวาง · วางจาก clipboard (Ctrl/⌘ + V) · `Remove photo`
- รับ JPG / PNG / WebP ≤ 5 MB → **ย่อและครอปสี่เหลี่ยมจัตุรัสตรงกลาง 256×256 · บันทึกเป็น WebP คุณภาพ 0.8** (ประมาณ 10–25 KB) · ปรับตำแหน่งครอปได้ก่อนบันทึก (ลากภาพในกรอบวงกลม)
- **เก็บใน IndexedDB** store `kol_photos` (key = kol_id) — ไม่เก็บใน localStorage เพราะพื้นที่ไม่พอ (911 KOL × ~20 KB) · `kol_master.photo` เก็บแค่ metadata
- แสดงที่: KOL Master ตาราง (32px แทนวงกลมตัวอักษร) · modal header (64px) · New deal การ์ด KOL · Deal drawer header · Pipeline card **ไม่แสดง** (การ์ดต้องกระชับ) · ไม่มีรูป = วงกลมตัวอักษรเดิม
- **Backup:** Settings › Backup มีตัวเลือก `Include photos` (default เปิด) → ใส่รูปเป็น base64 ใน JSON (ไฟล์ใหญ่ขึ้น · แสดงขนาดโดยประมาณก่อนดาวน์โหลด) · Restore ที่มีรูป → เขียนกลับ IndexedDB · Restore ที่ไม่มีรูป → รูปเดิมในเครื่องคงอยู่
- Settings › ข้อมูลในเครื่องนี้: แสดง "Photos n · x MB"
- ข้อความใต้ปุ่มอัปโหลด: "Use the KOL's public profile picture only" — ห้ามใช้รูปบัตร / เอกสาร
- สิทธิ์: เพิ่ม / เปลี่ยน / ลบรูป = ตามสิทธิ์แก้ KOL (CR-05) · ดูได้ทุก role
- `file://` ที่ IndexedDB ใช้ไม่ได้ (บางเบราว์เซอร์) → ปุ่ม Upload disabled + tooltip "Photos aren't available in this browser" · ระบบอื่นทำงานปกติ

## หมายเหตุการ implement (08/10/2026)

- `src/screen-profile.js` (ใหม่, `KT.profile`) = modal L + 5 tabs · `src/rules-profile.js` (ใหม่) = payee / ที่อยู่ / สรุป / Rate history / ‹ › / route / รูป / migrate v15 · `src/photos.js` (ใหม่, `KT.photos`) = IndexedDB `kol_photos` · `screen-kol.js` เหลือตาราง + Import + New KOL (drawer ของ KOL ถูกเอาออก)
- **modal ไม่ใช้ `<dialog>`** แต่เป็น overlay z-index 35 (ใต้ Deal drawer z 40) — ถ้าใช้ `<dialog>` แบบ showModal Deal drawer จะซ้อนเหนือไม่ได้ (top layer) · หน้าเบื้องหลัง `inert` · Tab วนอยู่ใน modal
- **ย้าย Shipping ตอนโหลด ไม่ใช่ตอน Unlock (§3):** ในแอปนี้ shipping details ของ CR-10 เก็บเป็น record เข้ารหัสแยก (`payee_profiles.secure_ship`) ไม่ได้ปนใน `secure` ของบัญชี → migrate v15 ย้าย ciphertext ทั้งก้อนไป `shipping_addresses` ได้เลยโดยไม่ถอดรหัส → ไม่มีสถานะ "รอย้าย" (`needs_shipping_split` ไม่จำเป็น) · banner "n shipping addresses waiting to move" ยังมีใน Settings แต่จะไม่ขึ้น (นับ payee ที่ยังมี `secure_ship` = 0 เสมอหลัง v15) · `readShip` อ่านรูปแบบเก่าได้ → TC-12 ใช้ไม่ได้ตามตัวอักษร (ผลเทียบเท่า: ที่อยู่ Primary ถูกสร้าง · payee ไม่มี shipping แล้ว · ไม่มี banner)
- สำเนาก่อน upgrade v15 แทนที่สำเนา v14 (`_before_v14` ถูกลบ) เพื่อไม่ให้ localStorage เต็ม
- **Pay to (§9 #4):** เลือกต่อ deal · line ที่อยู่ใน run / submitted / paid ล็อก payee เดิม · deal ที่มีงวดหนึ่งเข้า run แล้วยังเปลี่ยน Pay to ได้ (มีผลกับงวดที่ยังไม่เข้า run) · stored line ที่ยังไม่เข้า run ตามไปด้วย และคิดภาษีใหม่ด้วยสูตรเดิม (WHT rate ที่ยืนยันไว้คงเดิม) · ⋯ Change payee ใน To pay = เปลี่ยน Pay to ของ deal (manual line = เปลี่ยน payee ของ line)
- Committed ในแถบสรุป = ทุก deal ที่ไม่ Cancel (เหมือน History เดิม) · Rate history ไม่นับ quote ราคา ฿0 (แถวจากไฟล์เก่าที่ไม่มีราคา)
- Payee import: KOL ที่มี payee แล้ว → Add as another payee (default เมื่อ `payee_label` ต่างจาก label ของ default) / Replace default (default เมื่อไม่มีบัญชี) / Skip (default เมื่อมีบัญชีแล้ว) · label ซ้ำ → เติมเลข (เช่น "Agency ABC 2")
- Ship to: Mark shipped ทีละรายการมี select · หลายรายการพร้อมกัน / Mark all shipped ของ Pick list = แต่ละ shipment ใช้ที่อยู่ของตัวเอง (ไม่เลือก = default ตอนนั้น) · Edit (⋯) มี Ship to · New shipment มี Ship to (ว่าง = default ตอน Mark shipped)
- รูป: Merge KOL → ย้ายรูปของคนที่ถูกรวมไปให้คนที่เหลือ (ถ้ายังไม่มีรูป) · ตาราง KOL Master avatar 32px → ชื่อในคอลัมน์ KOL ขึ้นบรรทัดใหม่แทน "…"
