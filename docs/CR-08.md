## 4. Implementation details

### 4.1 หลักการ / Design decision
**ปัญหาจากไฟล์ PR ที่ใช้จริง**
- ทำจ่ายเป็น**รอบรายสัปดาห์** (ไฟล์มีรอบ 21/08 · 28/08 · 04/09 · 11/09 · 18/09 · 25/09 · 02/10 · 09/10 · 17/10) และแยก sheet ตามยอด (< 1,000 · 1,000–3,000 · 3,000–9,999 → ล่าสุดรวมเป็น 1,000–9,999)
- 1 แถว = **การจ่าย 1 ครั้ง** ไม่ใช่ 1 deal (deal แบบ 50/50 จ่าย 2 ครั้ง) · มีทั้ง KOL และ AFF (Affiliate) ในไฟล์เดียว · มีแถว "เบิก" (พนักงานสำรองจ่ายไปก่อน)
- ภาษีคำนวณด้วยมือ: สูตร WHT ใช้คอลัมน์ไม่ตรงกันในแต่ละ sheet · มีแถว VAT ที่ไม่เท่ากับ 7% · แถวรวมบาง sheet พิมพ์ตัวเลขเองไม่ตรงผลรวมจริง · บางงานตกลงยอด**สุทธิ** (เช่นสุทธิ ฿1,000 → ยอดก่อนหัก ฿1,030.93)
- เอกสาร (สำเนาบัตร · หน้า Bookbank · หลักฐานโพสต์พร้อมวันที่ · หนังสือรับรอง / ภ.พ.20 สำหรับบริษัท) ตรวจด้วยตา · มี sheet ที่หมายเหตุว่า "เอกสารไม่ครบ ไม่ต้องกรอก"
- ไฟล์มีข้อมูลส่วนบุคคลเต็ม (ที่อยู่ตามบัตร เบอร์ เลขบัญชี) หลายสำเนาบน Drive

**ตัดสินใจ: แยกเป็น Module ใหม่ "Payments"** (ไม่ใช่ redesign tab เดิมใน Deals) เพราะ
1. หน่วยงานต่างกัน — Deals นับ "งาน" แต่ทำจ่ายนับ "งวด" และรวมเป็น **รอบจ่าย (Payment run = PR)**
2. คนใช้ต่างกัน — PIC ขอจ่าย / แนบเอกสาร · ผู้ทำรอบ (เช่นรอบของ Dream, Babe) รวบรวมและส่งบัญชี · บัญชีจ่ายและส่งใบ 50 ทวิ
3. ต้องรวมงานที่ไม่ใช่ deal ได้ (Affiliate, เบิก) ให้ 1 รอบ = 1 ไฟล์ PR ครบ
4. แยกส่วนที่แตะข้อมูลอ่อนไหวออกมาให้ควบคุมได้ที่เดียว

**ข้อมูลผู้รับเงิน — ผูกกับ KOL Master กรอกครั้งเดียว**
- เลขบัญชี / ที่อยู่ตามบัตร / ช่องทางส่งใบ WHT / เอกสาร (สำเนาบัตร · Bookbank) เป็นของ **คน** ไม่ใช่ของงวด → เก็บที่ **Payee profile ของ KOL** ครั้งเดียว ทุกรอบดึงไปใช้เอง · แก้เมื่อ KOL เปลี่ยนเท่านั้น
- กรอก/แก้ได้ 2 ทาง แต่เป็น record เดียวกัน: KOL Master › KOL drawer › Payee **หรือ** Payments (คลิก chip "Missing: Bank details" / เมนู ⋯ ของแถว → dialog เดียวกัน)
- หลักฐานโพสต์เป็นของ **งวด** → ดึงอัตโนมัติจาก Posts ของ deal ไม่ต้องแนบเอง
- แอปเก็บข้อมูลใน localStorage ของทุกเครื่องและ Backup JSON บน Drive ที่แชร์กัน → ข้อมูลอ่อนไหว**เข้ารหัส** (Payee vault §4.4): ใครก็กรอก/อัปเดตได้ตามสิทธิ์ แต่ดูเต็มและ Export ลงไฟล์ PR ได้เฉพาะคนที่มี passphrase (ผู้ทำรอบ / บัญชี) · หน้าจอทั่วไปเห็นแค่ "KBank ···1234"
- เปลี่ยนเลขบัญชีหลังเคยจ่ายแล้ว → ต้อง **Verify** กับ KOL ก่อน Submit รอบถัดไป (กันโอนผิดบัญชี / ถูกหลอกให้เปลี่ยนบัญชี)

**Flow**

```
Deal ถึงกำหนดจ่าย (ตาม term)  ─┐
Manual line (Affiliate / เบิก) ─┴─► To pay ──► Run (Draft) ──► Submitted ──► Paid ──► WHT cert sent

                                     └─ PIC แนบ/ติ๊กเอกสาร          └─ ส่งบัญชี       └─ ปิดรอบ
```

### 4.3 Payment line — งวดที่ต้องจ่าย

> **หมายเหตุ (CR-11, 06/10/2026):** ขั้น **Request payment ถูกตัดออก** — งวดที่ถึงกำหนดอยู่ใน To pay เองเสมอ · เอกสารครบ = Ready ทันที · ใช้ **Hold** (เหตุผลบังคับ · line `on_hold` · Add to run ไม่ได้) / **Release** แทนเมื่อยังไม่ควรจ่าย · ดู `docs/CR-11.md` §4.9
**งวดจาก Payment term** — `rules.dueLines(deal, today)` (term ตาม CR-02 §4.3)

| term | งวด | ถึงกำหนด (due) | ยอด |
|---|---|---|---|
| prepaid | Full | เมื่อถึง Confirm QT (ต้องจ่ายก่อน Brief) | Total |
| split_50 | Deposit · Final | Deposit เมื่อถึง Confirm QT · Final เมื่อ Complete | Deposit = ปัดครึ่งขึ้นของ Total/2 · Final = Total − Deposit |
| postpaid | Full | เมื่อ Complete | Total |
| null (Not set) | Full | เมื่อ Complete + chip "Term not set" | Total |
| free | — | — | — |

- Total = ผลรวม cost fields ของ deal (CR-05) · deal ที่ Total = 0 และ term ≠ free → ไม่สร้างงวด แต่ขึ้นใน **Needs check** "฿0 deal"
- งวดที่จ่ายแล้วตาม flag เดิม (`paid_50` → Deposit, `paid_full` → ทั้งหมด) ไม่แสดงใน To pay
- deal ถูก Cancel หลังมี line → line ที่ยังไม่ Paid เปลี่ยนเป็น Cancelled อัตโนมัติ + reason "Deal cancelled" · line ที่ Paid แล้วคงไว้ + Warning "Paid on a cancelled deal"

**สถานะของ line** — `rules.lineStatus(line, payee, deal)`

| Status | เงื่อนไข | สี |
|---|---|---|
| Not due | ยังไม่ถึง due (แสดงใน To pay › Upcoming 14 days) | เทา |
| Missing docs | ถึงกำหนดแล้ว แต่เอกสารไม่ครบ (§4.4) | เหลือง |
| Ready | ถึงกำหนด + เอกสารครบ + ยังไม่อยู่ใน run | เขียวจาง |
| In run | อยู่ใน run สถานะ Draft | น้ำเงิน |
| Submitted | run ถูก Submit แล้ว | น้ำเงินเข้ม |
| Paid | มี paid_date | เขียว |
| Cancelled | ยกเลิก (มีเหตุผล) | แดงจาง |

**ภาษี** — `rules.calcPaymentTax({ agreed_amount, price_basis, payee_type, vat_registered, wht_rate }, settings)`
- `gross` (ยอดก่อน VAT):
  - price_basis = gross → `gross = agreed_amount`
  - price_basis = net (ตกลงยอดสุทธิ, บริษัทออก WHT ให้) → ถ้า agreed_amount ≥ threshold: `gross = round2(agreed_amount / (1 − wht_rate))` ไม่งั้น `gross = agreed_amount`
- `vat = vat_registered ? round2(gross × 7%) : 0`
- `wht = gross ≥ wht_threshold ? round2(gross × wht_rate) : 0` (ใบ 50 ทวิ ออกเฉพาะ line ที่ wht > 0)
- `net = gross + vat − wht` (ยอดที่โอนจริง) · round2 = ปัดครึ่งขึ้น 2 ตำแหน่ง
- `wht_rate` default จาก payee profile → ถ้าไม่มี profile ใช้ default ตามประเภท · แก้ราย line ได้ (เลือกจาก `wht_rates`)
- **Committed / Paid (est.) ไม่เปลี่ยนสูตร** (ยังใช้ Total ของ deal) · ส่วนต่างจาก gross-up แสดงใน Run เป็น "WHT borne by company ฿x"

### 4.4 Payee profile · Bank details (เข้ารหัส) · เอกสาร
**KOL drawer › section ใหม่ "Payee"** (ต่อจาก Payment term · คอลัมน์ซ้ายของ layout CR-07 §4.7) — component เดียวกันใช้เป็น dialog จากหน้า Payments

| กลุ่ม | ช่อง | เก็บแบบ |
|---|---|---|
| Tax & terms | Payee type (Individual / Company) · VAT registered · Default WHT rate · Price basis (Gross / Net) | ปกติ |
| Bank details | Account holder name · Bank · Account number · Full name (ตามบัตร / ชื่อบริษัท) · Address on ID card / company address · Phone · WHT certificate contact (email หรือที่อยู่) · Tax ID (ไม่บังคับ) | **เข้ารหัส** (`secure`) · ปกติเก็บแค่ `bank_name` + `account_last4` |
| Documents | ID copy · Bank book · Company certificate · VAT certificate (ภ.พ.20) — แต่ละอย่างเป็นวันที่ได้รับ · Docs folder (ลิงก์ Drive) | ปกติ |

- **View (ล็อก):** "KBank ···1234 · Updated 02/10/2026 by Pizza" · chip เอกสาร · ลิงก์โฟลเดอร์ · ปุ่ม `Unlock to view` (เฉพาะคนที่มีสิทธิ์ §4.9)
- **View (ปลดล็อกแล้ว):** แสดงทุกช่อง · เลขบัญชีซ่อนเป็น ••• + ไอคอนตา · ไอคอน copy ต่อช่อง (เลขบัญชี · ชื่อ)
- **✎ Edit:**
  - ปลดล็อกอยู่ → ฟอร์มมีค่าเดิม · Save เฉพาะเมื่อมีช่องเปลี่ยน
  - ล็อกอยู่ → ช่องเข้ารหัสแสดงเป็น "Saved · ···1234" · ปุ่ม `Replace bank details` = กรอกชุดใหม่ทั้งชุด (ไม่ต้องรู้ passphrase)
  - Save → เข้ารหัสทันทีในเครื่อง · `details_version + 1` · บันทึก event `payee_details_changed` (ไม่มีค่าใดๆ ใน event)
- **ไม่ต้องกรอกซ้ำ:** ทุก line / ทุก run ของ payee นี้ใช้ข้อมูลล่าสุดอัตโนมัติ · Request payment / Add manual line ไม่มีช่องบัญชีให้กรอกอีก (ถ้ายังไม่มี → chip "Missing: Bank details" คลิกเปิด dialog Payee)
- เปลี่ยน payee type / VAT / WHT แล้วถาม "Apply to n open payment lines?" (line ที่ยังไม่ Submit)

**Verify เมื่อข้อมูลบัญชีเปลี่ยน**
- Save bank details ใหม่ ขณะ payee นี้**เคยมี line ที่ Paid** → `needs_verification = true` · chip แดง "Bank details changed 06/10/2026 by Amp — verify with KOL"
- Line ของ payee นี้ Submit ไม่ได้ (Error ใน runChecks) จนกว่า Admin / KOL Manager กด `Mark as verified` (บันทึก verified_by / verified_at)
- กรอกครั้งแรก (ยังไม่เคยจ่าย) ไม่ต้อง verify

**Payee vault** — `src/vault.js` (Web Crypto · ไม่ใช้ library ภายนอก)
- **Setup (Admin, ครั้งเดียว):** Settings › Payments › Payee vault › `Set up` → ตั้ง passphrase (≥ 12 ตัว, กรอก 2 ครั้ง) → สร้าง RSA-OAEP 3072 key pair → private key เข้ารหัสด้วย AES-GCM 256 ที่ derive จาก passphrase (PBKDF2-SHA-256, 600,000 รอบ, salt สุ่ม 16 bytes) → เก็บใน `lookups.payee_vault` · passphrase ไม่ถูกเก็บที่ไหน
- **บันทึกข้อมูล (ไม่ต้องใช้ passphrase):** สุ่ม AES-GCM key ต่อ record → เข้ารหัส JSON ของช่องอ่อนไหว → ห่อ key ด้วย public key → เก็บ `secure` · ล้างค่าในฟอร์มออกจากหน่วยความจำหลัง Save
- **Unlock:** ปุ่ม `Unlock payee details` (top bar ของ Payments และใน section Payee) → ใส่ passphrase → private key อยู่ในหน่วยความจำเป็น CryptoKey แบบ non-extractable · **Auto-lock** เมื่อไม่ใช้งาน 15 นาที · Switch user · reload · ปุ่ม `Lock` · แถบ "Payee details unlocked · Lock" แสดงตลอดที่ปลดล็อก
- **Change passphrase (Admin):** ใส่ของเดิม + ใหม่ → ห่อ private key ใหม่อย่างเดียว ข้อมูลไม่ต้องเข้ารหัสใหม่
- **ลืม passphrase:** `Reset vault` (Admin, พิมพ์ RESET) → ลบ `secure` ทุก record (เก็บ bank_name / last4 / เอกสารไว้) → ทุก payee ขึ้น "Missing: Bank details" → setup ใหม่แล้วกรอกใหม่ · dialog เตือนชัดเจนว่ากู้คืนไม่ได้
- **Import ครั้งแรก (Admin / KOL Manager):** Settings › Payee vault › `Import payee details (CSV)` · คอลัมน์ `account_handle, payee_type, full_name, id_address, phone, wht_contact, bank_name, account_name, account_no, tax_id, docs_link` · จับคู่ KOL ด้วย handle (trim, ไม่สนตัวพิมพ์, ตัด @) · ไม่เจอ → สร้าง payee ใหม่แบบไม่ผูก KOL (เช่น Affiliate) หรือข้าม (เลือกใน dialog) · มีข้อมูลอยู่แล้ว → ข้าม หรือ Replace (เลือกใน dialog · Replace นับเป็นการเปลี่ยน → Verify) · เข้ารหัสทีละแถวทันที · ไม่เก็บไฟล์ · report: Matched n · New payee n · Skipped n · มี `Download CSV template` (header อย่างเดียว)
- Browser ที่ไม่มี `crypto.subtle` → ปิดฟีเจอร์ vault พร้อมข้อความ "This browser can't encrypt payee details" (Export PR ยังได้แบบไม่มีข้อมูลผู้รับ)
- Backup JSON / Restore มี `secure` และ `payee_vault` แบบเข้ารหัสไปด้วย → เครื่องอื่น Unlock ด้วย passphrase เดิมได้

**Guard ข้อมูลอ่อนไหว** — `rules.looksSensitive(text)`
- ทุกช่องในแอปที่ไม่ใช่ Bank details (note, remark, cancel reason, docs link, project label, KOL note) ถ้าพบตัวเลขติดกัน ≥ 10 หลัก (หลังตัด `-` และช่องว่าง) หรือรูปแบบเลขบัตร 13 หลัก → **Error** "This looks like an account or ID number. Put it in Payee › Bank details (encrypted)." บันทึกไม่ได้
- Import / Restore Backup ที่มีค่าแบบนี้ในช่องอื่น → ตัดค่าทิ้ง + แจ้งจำนวนช่องที่ถูกตัดใน report

**เอกสารที่ต้องครบ** — `rules.docsRequired(line)`

| ผู้รับ | เอกสาร (ครบ = มีวันที่) | ที่มา |
|---|---|---|
| Individual | ID copy · Bank book · **Bank details** (มี `secure`) | payee profile (ครั้งเดียวต่อคน) |
| Company | Company certificate · Bank book · Bank details · + VAT certificate (ภ.พ.20) ถ้า vat_registered | payee profile |
| ทุกคน · งวด Final / Full ของ deal | **Post evidence** | อัตโนมัติจาก `deal_posts`: ทุกโพสต์ในแผนมี post_link + post_date |
| Reimburse | — (อ้างอิงคนสำรองจ่าย) | — |

- To pay และ Run แสดงสิ่งที่ขาดเป็น chip เช่น "Missing: Bank details · ID copy · Post evidence" · คลิก chip = เปิด dialog Payee (component เดียวกับ KOL drawer) หรือ Deal drawer › Posts ตรงจุด · Save แล้วทุก line ของ payee นี้อัปเดตสถานะทันที
- Deposit / Full ของ prepaid ไม่ต้องมี Post evidence

### 4.6 Tab Runs (Payment run = PR)

  - แถวรวมทั้ง run ท้ายตาราง: Gross · VAT · WHT · Net · WHT borne by company
- **Actions ตามสถานะ**

| Status | Actions |
|---|---|
| Draft | Add lines (เปิด To pay แบบ picker) · Remove · Edit amount · **Export PR** · **Submit** (เมื่อไม่มี Error) |
| Submitted | Export PR อีกครั้ง · **Mark paid** (ทั้ง run หรือเลือกแถว · วันที่จ่าย) · Move line back to To pay (เหตุผล) · Reopen as Draft (Admin) |
| Paid | ทุก line จ่ายแล้ว → ปุ่ม Close run · ยังติดตามใบ 50 ทวิ ใน History |
| Closed | อ่านอย่างเดียว |

**Sync กลับ deal** — `rules.syncDealPayment(deal, lines)` เมื่อ line เปลี่ยนเป็น Paid / ยกเลิก Paid

> **หมายเหตุ (CR-09, 06/10/2026):** status label `Draft · Returned · With Accounting · Paid · Closed` (ค่าที่เก็บไม่เปลี่ยน) · ปุ่ม **Submit to Accounting** · run ที่ส่งแล้วทีม KOL อ่านอย่างเดียว (Open in Accounting · Reopen = Admin) · Mark paid / Return to team / Close run ทำใน tab Accounting · Export PR ทุกคนกดได้ (ข้อมูลผู้รับเฉพาะคนที่ Unlock ได้) · ไฟล์ `PR_dd_mm_yy_<run id>.xlsx` ทุก sheet มีบรรทัด "รอบจ่าย: … · วันจ่าย …" เป็นแถว 1 → CR-09 §3, §4.15

- ขณะล็อก → dialog ถาม `Unlock and export` หรือ `Export without payee details` (6 คอลัมน์ว่าง + หมายเหตุใน sheet Summary "Payee details not included")
- payee ที่ยังไม่มี Bank details → แถวว่าง 6 คอลัมน์ + dialog สรุป "Missing bank details: n" (ปกติไม่เกิดเพราะ Submit ไม่ผ่าน)
- ชื่อไฟล์ / ชื่อ sheet ไม่มีข้อมูลส่วนบุคคล

**Payments CSV** (ปุ่มรองใน To pay / History): line_id, run_id, campaign, KOL, milestone, gross, vat, wht, net, status, paid_date, PIC — ไม่มีข้อมูลส่วนบุคคล
