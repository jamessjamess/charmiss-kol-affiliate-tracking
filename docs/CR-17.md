## 4. Implementation details

### 4.1 Operations mode
- **Settings › Operations mode** (Admin): `Payments: Simple / Full` · `Shipments: Simple / Full` + คำอธิบายสั้น
  - Simple = "Your team records when payments are made and samples are shipped"
  - Full = "Payment runs and the Accounting tab handle payments; pick lists for shipping"
- สลับ mode ได้ทุกเมื่อ · ข้อมูลไม่หาย (ใช้ตารางเดียวกัน) · Simple → Full: line ที่ Sent แสดงเป็น run "With Accounting" · Paid คงเดิม
- `rules.opsMode('payments' | 'shipments')` เป็นจุดเดียวที่หน้าจอใช้ตัดสินว่าจะแสดงอะไร

### 4.2 Payments — Simple mode
**Flow:** งวดถึงกำหนด (To pay) → (ไม่บังคับ) Export ส่งบัญชี = **Sent** → ทีม KOL ได้ยืนยันว่าโอนแล้ว → **Mark paid**

**Tabs:** `To pay` · `Sent` · `Paid` (ซ่อน Payment runs / Accounting)
- Header: `Due now ฿` · `Sent, not yet paid ฿` · `Paid this month ฿` (คลิก = ไป tab นั้น)

| Tab | แถว | ปุ่มบนแถว (มองเห็นเลย ไม่ซ่อนใน ⋯) | Bulk |
|---|---|---|---|
| **To pay** | งวดที่ถึงกำหนด · ไม่รวม Sent · Hold แสดงพร้อมเหตุผล | **`Mark paid`** · ⋯ (Hold · Change payee · Open deal) | `Export for accounting` · `Mark paid` |
| **Sent** | ส่งบัญชีแล้วรอโอน · คอลัมน์ Sent dd/mm · ค้างกี่วัน (> 7 วัน = เหลือง) | **`Mark paid`** · ⋯ (Move back to To pay) | `Mark paid` · `Export again` |
| **Paid** | จ่ายแล้ว · Paid date · Paid by · Ref · WHT cert (☐ ติ๊กได้บนแถว) | ⋯ `Mark unpaid` (Admin / KOL Manager · เหตุผลบังคับ) | `Mark WHT cert sent` · `Export` |

- **`Mark paid`** → popover เล็ก: Paid date (default วันนี้) · Ref (ไม่บังคับ) · `Confirm` (Enter) · bulk ใช้วันที่ / ref เดียวกันทั้งชุด
  - งวดที่ยังไม่มี line → สร้าง line (snapshot ยอดตามกติกา CR-08) แล้วตั้ง Paid ในครั้งเดียว
  - `rules.syncDealPayment` อัปเดต flag ของ deal → Dashboard Paid / Outstanding · Journey Payment track เปลี่ยนทันที
  - toast "Marked n payments as paid · Undo" (Undo 10 วินาที)
- **`Export for accounting`** = ไฟล์ PR เดิม (CR-08 · ข้อมูลผู้รับต้อง Unlock) → หลังดาวน์โหลดถาม "Mark n lines as sent to accounting?" (default Yes) → `sent_at` · ย้ายไป tab Sent · ระบบสร้าง `payment_run` ให้อัตโนมัติ (ชื่อ "Sent dd/mm" · สถานะ With Accounting) เพื่อเก็บว่าส่งชุดไหน
- **เอกสาร (ID copy · Bank book · …)** แสดงเป็นไอคอนเทา "Docs 2/4" + popover รายการที่ขาด · **ไม่ขวาง Mark paid** · Export for accounting ยังเตือน "n lines have missing documents" (Export ต่อได้)
- **Deal drawer › Payment:** แต่ละงวดมีสถานะ + ปุ่ม `Mark paid` / `Mark unpaid` (ตามสิทธิ์) — ไม่ต้องไปหน้า Payments
- **สิทธิ์ (Simple):**

| Action | Admin | KOL Manager | Staff | Viewer | Accounting |
|---|:-:|:-:|:-:|:-:|:-:|
| Mark paid · Export for accounting · Hold | ✓ | ✓ | ✓ (deal ที่ตัวเองเป็น PIC) | — | ✓ |
| Mark unpaid | ✓ | ✓ | — | — | ✓ |
| Mark WHT cert sent | ✓ | ✓ | ✓ (ของตัวเอง) | — | ✓ |

### 4.3 Shipments — Simple mode
**Flow:** To ship → **Shipped** → **Delivered** (กดบนแถวได้เลย)

| Tab | ปุ่มบนแถว | Bulk |
|---|---|---|
| **To ship** | **`Shipped`** · ⋯ (Shipped & delivered · Set ship-by · Not required · Change address) | `Mark shipped` · ⋯ `Create pick list` |
| **In transit** | **`Delivered`** · ⋯ (Report problem · Edit tracking) | `Mark delivered` |
| **Delivered** | อ่านอย่างเดียว · ⋯ `Undo delivered` | — |

- **`Shipped`** → popover: Shipped date (default วันนี้) · Carrier (ไม่บังคับ · จำค่าล่าสุดของ user) · Tracking (ไม่บังคับ) · `Confirm` (Enter)
- **`Shipped & delivered`** (ส่งเอง / Messenger / มอบมือ) → ตั้งทั้ง 2 วันที่ในครั้งเดียว
- **`Delivered`** → วันที่ default วันนี้ · Confirm
- ที่อยู่ไม่บังคับ (ทีมอาจคุยที่อยู่ทาง LINE) · ไม่มีที่อยู่ = chip "No address" เตือนเฉยๆ
- Pick list (CR-11) อยู่ใน ⋯ (ไม่ใช่ปุ่มหลัก)
- **Deal drawer › Shipments** และ **Pipeline card ⋯** มี `Mark shipped` / `Mark delivered` ตรงนั้นเลย
- สิทธิ์: ตาม CR-11 §4.10 (Staff Mark shipped / delivered ได้ทุก shipment)

### 4.4 จุดอื่นที่ต้องสอดคล้อง
- **Dashboard › Operations › To do** (CR-11): Simple mode ใช้ card `Payments to confirm n` (Sent เกิน 7 วันแต่ยังไม่ Paid · ของ PIC ที่เลือก) แทน `Docs to collect` · `Shipments to ship` เดิม
- **Journey (Deal drawer):** Payment track แสดง To pay → Sent dd/mm → Paid dd/mm · Shipment track เดิม
- **Deals › chips (CR-13):** `Docs to collect` ซ่อนใน Simple mode (เอกสารไม่ขวางแล้ว)
- **Go-live clean-up (CR-11):** ยังใช้ได้ · "Mark paid outside app" ใช้ฟังก์ชันเดียวกับ Mark paid
- **Export PR · WHT summary:** รูปแบบเดิม

### 4.5 Staff สร้าง Campaign / Phase ได้ + Approve โดย Manager (ทุก mode)
**สิทธิ์ใหม่** (แทนแถว "สร้าง/แก้ Campaign & Phase" ใน CR-05 §4.1)

| Action | Admin | KOL Manager | Staff | Viewer | Accounting |
|---|:-:|:-:|:-:|:-:|:-:|
| สร้าง Campaign / Phase (Phase Planner) | ✓ อนุมัติทันที | ✓ อนุมัติทันที | ✓ **รอ Approve** | — | — |
| แก้ชื่อ · CTA · Products · Note ของ Campaign ที่อนุมัติแล้ว | ✓ | ✓ | ✓ (มีผลทันที) | — | — |
| แก้ **Budget · Period · Pillar target · Phase (เพิ่ม / ลบ / วันที่ / งบ)** ของ Campaign ที่อนุมัติแล้ว | ✓ ทันที | ✓ ทันที | ✓ **เป็นคำขอแก้ รอ Approve** | — | — |
| Approve / Reject | ✓ | ✓ | — | — | — |
| ตั้ง On hold / Cancelled (CR-05) | ✓ | ✓ | — | — | — |

**สถานะ**
| approval_status | ความหมาย | เพิ่ม Deal ได้ไหม | นับใน Dashboard |
|---|---|---|---|
| **Pending approval** | Staff สร้างแล้ว รอ Manager | **ไม่ได้** | ไม่นับ (มีใน Status filter CR-14 เป็นค่า "Pending approval" · ไม่อยู่ใน default) |
| **Approved** | ใช้งานได้ | ได้ | นับตามปกติ |
| **Rejected** | ถูกตีกลับ + เหตุผล | ไม่ได้ | ไม่นับ |

**Pending approval ≠ Not started** — Approval บอกว่า "อนุญาตให้ใช้หรือยัง" ส่วน Not started / On going / Complete บอก "อยู่ช่วงเวลาไหน" (คำนวณจากวันที่) · Campaign ที่รออนุมัติอาจมีวันที่เริ่มไปแล้วก็ได้ จึงแยกกัน
- **Effective status** (`rules.campaignStatus` · ใช้ทุกที่ที่แสดง chip สถานะ และ Status filter / tabs): `Cancelled` > **`Rejected`** > **`Pending approval`** > `On hold` > ตามวันที่ (`Not started` · `On going` · `Complete`)
- ยังไม่อนุมัติ → chip แสดง **Pending approval** (เหลือง) แทนสถานะตามวันที่ · บรรทัดเทาใต้ chip บอกช่วงเวลา เช่น "Starts 01/11" / "Started 3 days ago" ให้ Manager เห็นว่าเร่งแค่ไหน
- Campaign & Phase › Status tabs: `All · On going · Not started · Pending approval · On hold · Complete · Rejected · Cancelled` (ซ่อน tab ที่เป็น 0 ยกเว้น All) · Dashboard Status filter (CR-14) เพิ่ม `Pending approval` · `Rejected` (ไม่อยู่ใน default)
- Phase ใช้กติกาเดียวกัน (Phase pending ใน Campaign ที่อนุมัติแล้ว → chip Pending approval ที่แถว Phase)

**Flow ของ Staff**
- Phase Planner (CR-11 modal) ปุ่มหลักเป็น **`Submit for approval`** (แทน Create campaign) · footer บอก "A manager needs to approve this before deals can be added" · มีช่อง `Note to approver` (ไม่บังคับ)
- หลังส่ง: Campaign แสดงในตาราง Campaign & Phase พร้อม chip **"Pending approval"** (เหลือง) · ผู้สร้างแก้ต่อได้จนกว่าจะถูกตัดสิน
- ถูก Reject → chip "Rejected" + เหตุผล · ผู้สร้างแก้แล้ว `Resubmit` ได้ · หรือ `Delete` (ยังไม่มี deal)
- เพิ่ม Phase ให้ Campaign ที่อนุมัติแล้ว → Phase นั้น Pending (Campaign เดิมใช้งานต่อได้)
- แก้ Budget / Period / Phase ของ Campaign ที่อนุมัติแล้ว → บันทึกเป็น `pending_change` · หน้าจอแสดงค่าเดิม (ยังมีผล) + แถบ "Change pending: Budget ฿600,000 → ฿700,000" · ยกเลิกคำขอเองได้

**Flow ของ Manager (Admin / KOL Manager) — หน้า Approvals**
- **ที่อยู่:** Campaign & Phase › tab ใหม่ **`Approvals n`** (ต่อจาก Table · Timeline) · route `#campaigns/approvals`
  - ทางเข้า: badge ตัวเลขบนเมนู Campaign & Phase · Dashboard › Operations › To do card **`Approvals n`** · คลิกแล้วมาที่ tab นี้
  - Manager เห็นคำขอทั้งหมด · Staff เห็นเฉพาะคำขอของตัวเอง (ชื่อ tab `My requests n`) เพื่อติดตามผล
- **1 การ์ด = 1 คำขอ** เรียงเก่าสุดก่อน · ตัวกรอง `Pending · Decided` (default Pending) · Type (New campaign · New phase · Change)

| ส่วนของการ์ด | New campaign | New phase | Change |
|---|---|---|---|
| หัว | ชื่อ Campaign + chip type · "Submitted by Babe · 08/10/2026 · 2 days ago" | ชื่อ Phase › Campaign | ชื่อ Campaign / Phase ที่ขอแก้ |
| รายละเอียดสั้น | **Period** 01/11–30/11 (30 วัน · Starts in 24 days / Started 3 days ago) · **Budget** ฿x · **Phases** n + แถบ timeline เล็ก (สีเทา ordinal CR-13) · **Pillar target** 10/20/70 · **Products** n (ชื่อสั้น) · **CTA** | Period · Budget · ทับช่วงกับ Phase เดิมไหม (⚠ "Overlaps Phase 2 on 03–04/09") · งบรวม Phase เทียบงบ Campaign | ตาราง **Field · Current · Requested** เฉพาะช่องที่ขอแก้ |
| ผลกระทบ | งบรวมทุก Campaign ที่ On going ในช่วงเดียวกัน ฿x → ฿y | งบ Phase รวม vs งบ Campaign (เกิน = แดง) | deal ที่ได้รับผล n (เช่น วันที่ Phase เปลี่ยน → โพสต์ที่ย้าย Phase n) |
| Note จากผู้ขอ | ถ้ามี (ช่อง `Note to approver` ตอน Submit · ไม่บังคับ) | | |
| ปุ่ม | **`Approve`** · **`Reject`** (เหตุผลบังคับ) · `Open details` (เปิด Campaign drawer / Phase Planner แบบอ่านอย่างเดียว) | เหมือนกัน | เหมือนกัน |

- เลือกหลายการ์ด › `Approve selected` ได้ · Reject ทีละรายการเท่านั้น (ต้องมีเหตุผล)
- หลังตัดสิน: การ์ดย้ายไป Decided พร้อม "Approved by Dream · 09/10" / "Rejected: <เหตุผล>" · toast + Undo 10 วินาที
- **Campaign drawer** ของรายการที่รออนุมัติยังมี banner + ปุ่ม Approve / Reject เหมือนกัน (เผื่อเข้ามาจากตาราง)
- Approve คำขอแก้ → ค่าใหม่มีผลทันที · Reject → ค่าเดิมคงอยู่ + เหตุผลแสดงให้ผู้ขอ (ใน My requests และบนแถบ Change pending)
- ทุกการตัดสินบันทึก `campaign_events` type `approval`

**Guard ที่ต้องมี**
- **New deal / Bulk shortlist / KOL › Add to campaign:** Campaign ที่ไม่ Approved แสดงใน combobox เป็นตัวเลือกเทาพร้อม chip "Pending approval" · เลือกไม่ได้ · tooltip "Waiting for manager approval"

- Import / Restore ข้อมูลเก่าที่ไม่มี approval_status → ถือเป็น Approved
- ผู้ที่อนุมัติได้สร้างเองถือว่าอนุมัติทันที (ไม่ต้องให้คนอื่นอนุมัติซ้ำ)
