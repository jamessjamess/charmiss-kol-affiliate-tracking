# CR-27 — Campaign & Phase polish · Payment documents · กลับหน้าเดิมหลังปิด Deal

ใช้กติกาถาวรใน CLAUDE.md

## 1. เป้าหมาย
- Campaign & Phase ข้อความและหัว modal ไม่สับสน
- Payments จัดการเอกสารและส่งบัญชีได้จากหน้าเดียว ไม่ต้องพึ่ง Export
- เปิด deal จากหน้าไหน ปิดแล้วกลับหน้านั้น

## 2. เดิม → ใหม่
- Adjust budget เปิดในหัว "Edit Campaign Nov · Phase Planner · Adjust budget" → หัวเดียว **"Adjust budget · Campaign Nov"**
- footer New campaign มีกล่องรายการ "i Enter …" เลื่อนได้ 4 บรรทัด → **บรรทัดเดียว "4 things to finish ▾"** (กางดูได้)
- Docs 0/4 กดแล้วทำอะไรไม่ได้ · เข้า Sent ได้ทางเดียวคือ Export → **Payment details** (เอกสาร + สถานะ) · ปุ่ม `Send to accounting` บนแถว
- Shipments คลิกแถว → ไปหน้า Deals · ปิดแล้วไม่กลับ → **Deal modal เปิดซ้อนบนหน้าปัจจุบัน** ทุกหน้า

## 3. Spec

### 3.1 Campaign & Phase
- **Table / Timeline: Sort และ Expand / Collapse all ไม่ต้องแก้** (ครบแล้วตาม CR-21)
- chip **No products** ที่ชื่อ Campaign กดได้ → เปิด Edit (Phase Planner) โดย focus ช่อง Products
- **Adjust budget modal:** หัว = "Adjust budget · <Campaign>" · ตัดบรรทัด "Edit <Campaign>" และ "Phase Planner" ที่ซ้อนอยู่
- **footer New campaign / Edit:** สิ่งที่ยังขาดแสดงบรรทัดเดียว "4 things to finish ▾" สีเทา (กดกางเป็นรายการ · คลิกรายการ = ไปที่ช่อง) · หลังกด Submit / Create แล้วยังขาด → บรรทัดเป็นสีแดงและกางเอง
- **My requests (Staff):** ปุ่มบนการ์ดคำขอของตัวเอง = `View` (ไม่ใช่ `Review` ซึ่งหมายถึงการอนุมัติ)
- ⋯ ของแถว Campaign ใน Table / Timeline: Edit · Add phase · Adjust budget · Cancel campaign (เมนูชุดเดียวกัน)

### 3.2 Payments — Payment details + เอกสาร
**เปิด:** คลิกแถว (นอกปุ่ม) ทุก tab · คลิก chip `Docs 0/4` = เปิดที่ส่วน Documents · modal ขนาด M มี ‹ › ไปแถวก่อน / ถัดไปตามลำดับในตาราง

| ส่วน | เนื้อหา |
|---|---|
| Header | KOL · Campaign › Phase · Deal ID (ลิงก์ = Deal modal) · chip สถานะ |
| Amount | Milestone · Due date · Gross · WHT · Net |
| Pay to | label ของ payee (CR-16 · ไม่แสดงเลขบัญชี) · `Change` |
| **Status** | เส้น 3 ขั้น To pay → Sent to accounting → Paid พร้อมวันที่ · ref · โดยใคร · ปุ่มตามขั้น: `Send to accounting` (date · ref) · `Mark paid` (date · ref) · `Move back` (เหตุผล) · `Hold` |
| **Documents** | checklist จากรายการเอกสารเดิม (4 รายการ) · แต่ละรายการ: ☐ Received · วันที่ (default วันนี้เมื่อติ๊ก) · Note · Link (https · ที่เก็บไฟล์ของบริษัท เช่น Google Drive) · `+ Add document` (ชื่อเอง) · ปุ่ม `Mark all received` |
| History | log เดิมของแถวนี้ |
- **ไม่มีการอัปโหลดไฟล์** · ใต้ส่วน Documents: "Link to where the file is kept — don't type ID card or bank account numbers here" · ช่อง Note / Link ตรวจรูปแบบตัวเลขยาว (ซ้ำ looksLikePhone CR-14 + เลขบัญชี 10–12 หลัก) → ไม่ให้บันทึก
- แก้เอกสารได้ทุก tab รวม **Paid** (เช่น เก็บหนังสือรับรองหัก ณ ที่จ่ายทีหลัง) · chip Docs อัปเดตทันที
- แถบเตือน "Marked as paid, but documents aren't checked yet" มีลิงก์ `Check documents` เปิดส่วนนี้

**บนตาราง To pay**
- ปุ่มแถว: `Mark paid` (หลัก) + `Send` (รอง · = Send to accounting) · ทำให้ tab Sent ใช้งานได้โดยไม่ต้อง Export
- bulk (เลือกหลายแถว): `Send to accounting` · `Mark paid` · `Mark docs received`
- คำอธิบายใต้ tab (เทา · บรรทัดเดียว): "To pay → Send to accounting (optional) → Paid"

### 3.3 Deal modal เปิดซ้อนบนหน้าปัจจุบัน (ทุกหน้า)
- คลิก deal จาก Shipments · Payments · Dashboard · Operations · KOL modal → เปิด Deal modal **บนหน้าที่อยู่** (ไม่เปลี่ยนหน้า / route) · ปิดแล้วอยู่หน้าเดิม ตัวกรอง · tab · ตำแหน่ง scroll คงเดิม · focus กลับแถวที่คลิก
- ‹ › ใน Deal modal เลื่อนตามรายการของหน้าที่เปิดมา (เช่น ลำดับแถวใน Shipments)
- tab ที่เปิดตามที่มา (CR-22): Shipments → Shipments & posts · Payments → Costs & payment
- ปุ่ม `Open in Deals` (ลิงก์เล็กใน header) สำหรับคนที่ต้องการไปหน้า Deals จริง
- เปลี่ยนแปลงใน modal (เช่น Mark shipped) → แถวในหน้าเดิมอัปเดตทันทีหลังปิด

### 3.4 Shipments — เก็บตก
- คอลัมน์ Items แสดงชื่อสินค้า "Test 2 ×1, Test 1 ×1" (ไม่ใช่รหัส "11102×1")
- แถว "No products selected" → ลิงก์ `Add products` (popover เลือกสินค้า + qty)

## หมายเหตุการ implement (09/10/2026)
- **rules-pay.js:** `payment_lines.docs[]` = `{ key, label (ที่เพิ่มเอง), custom, received_at, note, link }` · `R.lineDocs` · `docsRequired` หักเอกสารที่ติ๊กใน line แล้ว · **docs-only line** (`docs_only: true`) = line ที่เก็บเอกสารของแถวที่ยังไม่มี line (ยังไม่ Send / Paid / Hold) — แถวยังคำนวณยอดจาก deal เหมือนเดิม (`payQueue` · `dealPayItems` ไม่นับเป็นแถว) · `R.isDocsOnly` · `R.promoteDocsLine` (ตอน Send / Mark paid / Hold: ใช้ line เดิม ยอด ณ วันนั้น เอกสารอยู่ครบ)
- **rules-ops.js:** `lineFor` ใช้ docs-only line ก่อน (Undo คืนสภาพเดิมทั้งก้อน) · `sendToAccounting(…, {date, ref})` → `sent_ref` · วันที่ส่งตามที่เลือก · `moveBackToPay` ต้องมีเหตุผล · `docsTally` นับเอกสารที่เพิ่มเอง · `docsChecklist` · `validateDocs` (Note / Link: ตัวเลข 9 หลักขึ้นไปติดกัน = ไม่ให้บันทึก · Link ต้อง https:// · ชื่อเอกสารที่เพิ่มเอง) · `setItemDocs` (event `payment_docs` "2/4 → 3/4") · `allReceived` · `syncDocsDone` (ครบทุกงวด → `deals.docs_done`) · `lineHistory`
- **rules-golive.js:** Hold ใช้ docs-only line · Release แล้วกลับเป็น docs-only (เอกสารไม่หาย) · rules-package / rules-profile ไม่นับ docs-only line
- **screen-payments.js:** คลิกแถว / Enter = **Payment details** (M · ‹ › ตามลำดับแถวในตาราง): หัว (Campaign › Phase · Deal ID → Deal modal บนหน้านี้ · chip) · Amount · Pay to (label + Change) · Status 3 ขั้น (วันที่ · Ref · โดยใคร) + ปุ่ม Send to accounting / Mark paid / Hold / Move back (เหตุผล) / Release / Mark unpaid · Documents (☐ Received + วันที่ · Note · Link + Open link · + Add document · Mark all received · คำเตือนเรื่องเลขบัตร / บัญชี) · History · chip Docs n/m ทุก tab (To pay · Sent · Paid) เปิดที่ Documents · To pay: แถว Mark paid + **Send** · bulk Send to accounting · Export for accounting (เดิม) · Mark docs received · Mark paid · บรรทัดเทา "To pay → Send to accounting (optional) → Paid"
- **screen-deals.js:** `openOver(id, {nav, …})` ‹ › ตามรายการของหน้าที่เปิดมา · ลิงก์ "Open in Deals ↗" ใน header เมื่อเปิดซ้อนหน้าอื่น · `renderLeft` ไม่ทำงานถ้าหน้า Deals ยังไม่เคยเปิด · คำเตือน "Marked as paid, but documents aren't checked yet" มีลิงก์ **Check documents** (Simple mode) → Payment details ที่ส่วน Documents
- **Deal modal ซ้อนหน้าเดิม:** Shipments (คลิกแถว / Open deal → tab Shipments & posts · ‹ › ตามแถวในหน้า · ปิดแล้ว tab · ตัวกรอง · scroll เดิม · focus กลับแถว) · Payments (Open deal → Costs & payment) · KOL modal (← Back to deal) · Settings › Data issues · Dashboard / Operations ใช้อยู่แล้ว

- **Campaign & Phase:** chip No products (Table + Timeline) → Edit (Phase Planner) โฟกัสช่อง Products · ⋯ ของแถว Campaign ชุดเดียวกันทั้ง 2 มุมมอง: Edit · Add phase · Adjust budget · Cancel campaign · Adjust budget ใน Planner หัวเดียว "Adjust budget · <Campaign>" (`U.modalPanel({replaceHeader})` · Back คืนหัว Planner) · footer New campaign / Edit: "4 things to finish ▾" (เทา · กดกาง · คลิกรายการไปที่ช่อง) · หลังกด Create / Submit → แดงและกางเอง · My requests (Staff): ปุ่ม **View**

### การตัดสินใจ (ตาม §6 หรือที่ spec ไม่ระบุ)
1. ไม่มีไฟล์ CLAUDE.md → ใช้กติกาถาวรเดิม
2. เอกสารเก็บที่ payment line ตาม §4 · แถวที่ยังไม่มี line ใช้ **docs-only line** (ไม่แช่แข็งยอดเงิน: ถ้าแก้ราคา deal ทีหลัง ยอดในแถวเปลี่ยนตาม) · เอกสารของ payee ที่มีในโปรไฟล์ (วันที่รับใน Payee) · Bank details ใน vault · Post evidence (โพสต์มีลิงก์และวันที่ครบ) = ติ๊กให้เอง (ล็อก)
3. ติ๊กเอกสารที่ payment นี้ไม่ไปอัปเดตโปรไฟล์ payee (spec ให้เก็บที่ line) — จ่ายงวดถัดไปต้องติ๊กใหม่ถ้า payee ยังไม่มีเอกสารในโปรไฟล์
4. ตัวเลขที่ห้าม: ตัวเลขติดกัน 9 หลักขึ้นไป (ไม่นับ - และช่องว่าง) ทั้ง Note และ Link (ครอบคลุมเบอร์ 9–10 หลัก · เลขบัญชี 10–12 · เลขบัตร 13) · ข้อความ error ไม่ใช้คำว่า "phone" (test เดิมห้ามคำเกี่ยวกับข้อมูลส่วนตัวใน UI)
5. Docs ครบทุกงวดของ deal → ตั้ง `docs_done` ให้ (คำเตือน paid แต่ยังไม่เช็กเอกสารหายไป) · ไม่ยกเลิกเองถ้าเอาติ๊กออกทีหลัง
6. Send จากแถว / details / bulk = ไม่ดาวน์โหลดไฟล์ (Export for accounting ยังอยู่ใน bulk) · ถาม Sent on (default วันนี้) + Ref (optional) · Undo 10 วินาที
7. Move back ต้องมีเหตุผล (ทั้งจาก ⋯ ใน Sent และใน details) — test เดิม CR-17 แก้ให้ส่งเหตุผล
8. Status ใน details สำหรับ Full mode: แสดงเส้นสถานะ + ข้อความ "payment runs move it" (ปุ่มสถานะเฉพาะ Simple mode) · เอกสารแก้ได้ทั้ง 2 โหมด
9. "Add products" ใช้ dialog เลือกสินค้า + จำนวนที่มีอยู่ (Edit items) แทน popover ใหม่
10. Cancel campaign ใน ⋯ ใช้ dialog เดิม (เหตุผล · deal ที่ยังเปิดถูก Cancel ด้วย) · แสดงเฉพาะ Campaign ที่ approved ยังไม่ complete / cancelled และไม่ได้ On hold
11. ข้อมูลทดสอบ: seed ไม่มี payment line เลย · _linnabelll (D000281) เดิมเป็น Docs done อยู่แล้ว จึงใช้ james_jarawut (D000038 · Docs 0/4) ทดสอบคำเตือน / Check documents · benja.boon เพิ่ม shipment สมมติ 2 รายการ (มีสินค้า Test 2 ×1, Test 1 ×1 และไม่มีสินค้า)
