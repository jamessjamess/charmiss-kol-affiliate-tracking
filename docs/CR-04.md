- **โครง:** side menu ซ้ายกว้าง 232px (sticky เต็มความสูง) · เนื้อหาอยู่ขวา max 1440px · ไม่มี tab bar ด้านบนแล้ว
- **บนสุด:** "Charmiss KOL Tracker"
- **เมนู (ลำดับนี้เท่านั้น)** — ไอคอน outline 20px + label:
  1. Dashboard
  2. Campaign & Phase
  3. Deals
  4. KOL Master
  5. Settings
  6. Role Management (แสดงเฉพาะ admin)
- item ที่เลือก: พื้นสีอ่อนของ primary + แถบซ้าย 3px สี primary + ตัวหนา · hover: พื้นเทาอ่อน
- **ล่างสุดของ side menu:**
  - การ์ด user ปัจจุบัน: วงกลมตัวอักษรแรก + ชื่อ + role chip · คลิก = เมนู "Switch user" (§4.4)
  - ปุ่ม ◐ Dark mode
  - เมนู ⋯ (Backup data, Restore data, Export all CSV) — จุดเตือน backup ย้ายมาอยู่ที่นี่
- **ยุบได้:** ปุ่ม « ยุบเหลือไอคอน 64px (tooltip = ชื่อเมนู) · จำค่าใน localStorage
- **มือถือ < 768px:** ซ่อน side menu · มี top bar 56px (☰ + ชื่อหน้า) · ☰ เปิด menu เป็น drawer ซ้ายทับเนื้อหา
- **Page header** ของแต่ละหน้า (ในพื้นที่เนื้อหา): ชื่อหน้า (h1 22px) + ปุ่ม primary ของหน้านั้นชิดขวา (เช่น "+ New deal") — ปุ่มที่เคยอยู่ใน toolbar ให้ย้ายมาที่นี่ ไม่ซ้ำ
- Route: `#dashboard` (default) · `#campaigns` · `#deals` · `#kols` · `#settings` · `#roles` · route เดิม `#overview` → redirect `#dashboard`

### 4.2 Deals — KOL Tier
**Deal tier** — `rules.dealTier(deal, accounts, posts, tierRules)`
- = tier ของบัญชีที่ followers สูงสุด **ในบรรดาบัญชีที่ใช้ในโพสต์ของ deal นั้น** (เพราะคือบัญชีที่จ้าง)
- ถ้า deal ยังไม่มีโพสต์ → ใช้บัญชีที่ followers สูงสุดของ KOL
- ไม่มี followers เลย → `Unknown`
- ใช้ `tier_rules` เดิม (Nano 0 · Micro 10,000 · Mid-tier 50,000 · Macro 100,000 · Mega 1,000,000)

**แสดงผล**
- คอลัมน์ KOL: ต่อท้ายชื่อด้วย tier chip เล็กสีเทา (เช่น `Micro`) · tooltip "Based on @handle · 33,700 followers"
- Template view: เพิ่มคอลัมน์ `Tier` หลัง Name Account (export แบบ Template ไม่ต้องมี เพื่อให้ตรงไฟล์ Template)
- Export Deals CSV: เพิ่มคอลัมน์ `kol_tier`, `tier_followers`

**Filter**
- ใน toolbar เพิ่ม dropdown `Tier` (multi-select): Mega · Macro · Mid-tier · Micro · Nano · Unknown — ถัดจาก Phase dropdown
- Status tabs / Summary strip / Group headers นับตาม filter นี้ด้วย
- Pipeline มี Tier filter เหมือนกัน

### 4.3 Deals — Group by
- control `Group by` (segmented หรือ dropdown) อยู่ซ้ายของ `Compact | Template`: **Phase · Stage · KOL Tier · None**
  - default = Phase เมื่อเลือกมากกว่า 1 Phase (เหมือนเดิม) · ถ้าเลือก Phase เดียว default = Stage
  - จำค่าที่ผู้ใช้เลือกไว้ใน localStorage (ต่อมุมมอง Compact / Template)
- **Phase:** ตามกติกา CR-03 §4.5 (Primary phase)
- **Stage:** กลุ่มตามขั้นปัจจุบัน ใช้ label เดียวกับคอลัมน์ Stage เรียงตาม journey
  - `Shortlist · Contacted · Confirm QT · Brief · Script · Draft 1 · Draft 2 · Draft 3 · Posted · Cancelled`
  - ซ่อนกลุ่มที่ว่าง · Cancelled ยุบไว้เป็น default
  - หัวกลุ่ม: ชื่อขั้น · status chip (List / In process / Complete / Cancelled) · n deals · ฿committed · จำนวน overdue (สีแดง ถ้ามี)
- **KOL Tier:** เรียง Mega → Macro → Mid-tier → Micro → Nano → Unknown
  - หัวกลุ่ม: tier · ช่วง followers (เช่น "100K – 1M") · n deals · ฿committed · ค่าเฉลี่ยต่อ deal · Views รวม · CPV (ถ้ามี views)
- **None:** ตารางแบนไม่มีหัวกลุ่ม
- ทุกแบบ: กาง/หุบกลุ่มได้ · ปุ่ม "Expand all / Collapse all" · ตัวเลขในหัวกลุ่มคำนวณตาม filter ที่ใช้อยู่ · Stage stepper, PIC inline, bulk action ทำงานเหมือนเดิมในทุกการจัดกลุ่ม
- ห้ามจัดกลุ่ม 2 ชั้นใน CR นี้

### 4.4 Role Management (UI-level)
**ข้อจำกัดที่ต้องแสดงให้ผู้ใช้เห็น (ที่เดียว คือหัวหน้า Role Management, 1 บรรทัดสีเทา):**
"Roles control what each person sees and can edit in this file. They are not a security control — anyone with the file can change data. Real access control comes with the online version."

**หน้า Role Management** (admin เท่านั้น)
- Page header: "Role Management" + ปุ่ม `+ Add user`
- ตาราง: Name · Email · Role · PIC (☑ + pic_name) · Status (Active / Inactive) · Deals as PIC (จำนวน) · Last active (วันที่ user นี้แก้ข้อมูลล่าสุด จาก logs/events)
- คลิกแถว → drawer (view-before-edit) แก้ name, email, role, is_pic, pic_name, active
- Validation:
  - Error: display_name ว่าง · email ไม่ลงท้าย `@lomr.co.th` · pic_name ซ้ำกับ user อื่น
  - Error: ห้ามลด role หรือปิด active ของ admin คนสุดท้าย
  - Warning: ปิด active ของ user ที่ยังเป็น PIC ของ deal ที่ยังไม่ปิด → แสดงจำนวน + ปุ่ม "Reassign PIC…" (ใช้ bulk reassign จาก CR-02)
- เปลี่ยน pic_name → อัปเดตค่า `pic` ใน deals และ kol_master ที่ใช้ชื่อเดิมให้ด้วย (ถามยืนยันพร้อมจำนวน)
- ส่วนล่างของหน้า: ตาราง **Permissions** แบบอ่านอย่างเดียว (ตาม matrix ด้านล่าง)

**Permission matrix** — `rules.can(user, action)`

| Action | Admin | Staff | Viewer |
|---|:-:|:-:|:-:|
| ดูทุกหน้า (ยกเว้น Role Management) · Export CSV | ✓ | ✓ | ✓ |
| สร้าง/แก้ Deal, โพสต์, ขยับสถานะ, Payment, PIC inline, Set pillar | ✓ | ✓ | — |
| สร้าง/แก้ KOL, บัญชี, ราคา · Import KOL CSV | ✓ | ✓ | — |
| Merge KOL · ลบ deal / KOL | ✓ | — | — |
| สร้าง/แก้ Campaign & Phase (ช่วงวันที่, งบ Campaign, % Phase, pillar target) | ✓ | — | — |
| Settings › Lists, Pillar targets | ✓ | — | — |
| Backup | ✓ | ✓ | ✓ |
| Restore / Reset to seed | ✓ | — | — |
| Role Management | ✓ | — | — |

- action ที่ทำไม่ได้: **ซ่อน** ปุ่มสร้าง/ลบ · ช่อง inline (PIC, pillar) แสดงเป็นข้อความธรรมดา · ปุ่ม Edit ใน drawer ซ่อน · ถ้าเข้าหน้า Role Management ด้วย URL ตรง ๆ ให้ขึ้น "You don't have access to this page"
- `rules.can` ต้องถูกเรียกทั้งตอน render และก่อนเขียนข้อมูลทุกครั้ง (ป้องกันการกดผ่าน UI ที่ค้าง)

**Current user (Switch user)**
- การ์ด user ล่าง side menu → เมนูรายชื่อ user ที่ active → เลือกแล้วตั้ง `meta.current_user_id` · ไม่มีรหัสผ่าน
- เปิดไฟล์ครั้งแรกบนเบราว์เซอร์ใหม่ (ยังไม่มี state) → ใช้ U000 Admin
- `changed_by` ใน deal_status_log และ deal_events = `current_user_id` · History แสดงชื่อ user
- Deals › Filters เพิ่มตัวเลือกลัด **"My deals"** = PIC = pic_name ของ user ปัจจุบัน (ซ่อนถ้า user ไม่ใช่ PIC)

**PIC list**
- dropdown PIC ทุกที่ (Deals inline, bulk reassign, drawer, KOL Master, New deal) = users ที่ is_pic + active เรียงตามชื่อ
- Settings › Lists ตัดรายการ PIC ออก และใส่ลิงก์ "Manage PIC in Role Management"

- Viewer: ไม่มี ✎ เลย · deal ที่ Cancel แล้ว: แก้ได้เฉพาะ Remark และ Cancel reason (ที่เหลือล็อก "Cancelled — reopen with Move stage first")

### 4.6 New deal — PIC ตาม User Account
- ลำดับค่าเริ่มต้นของ PIC (New deal, Add to phase / shortlist, bulk shortlist):
  1. `pic_name` ของ **user ปัจจุบัน** ถ้า user นั้น is_pic + active
  2. ไม่งั้นใช้ PIC ของ KOL (kol_master.pic)
  3. ไม่งั้นว่าง (ต้องเลือก — Error ตามเดิม)
- ข้างช่อง PIC แสดงที่มาเป็นข้อความเล็ก: "You" / "KOL default"
- bulk shortlist: ใช้ข้อ 1 กับทุก deal ที่สร้าง (ถ้า user ไม่ใช่ PIC ใช้ข้อ 2 ราย KOL)

### 4.7 CTA = เป้าหมายช่องทางขายของ Campaign
- CTA คือช่องทางที่ Campaign ต้องการพาคนไปซื้อ เช่น `TikTok` · `All Channel` · `Eveandboy` · `7-11`
- `lookups.cta_list` seed ค่าเริ่มต้น 4 ค่านี้ · admin เพิ่ม/ปิดได้ใน Settings › Lists
- **Campaign มี CTA เป็นค่าหลัก:** field `campaigns.cta` (Campaign drawer › edit, admin) · แสดงเป็น chip ในตาราง Campaign & Phase และในหัว Dashboard โหมด Campaign
- **Deal ดึง CTA จาก Campaign** ตอนสร้าง และแก้เป็นค่าอื่นได้ใน section Deal info (เช่น Campaign = All Channel แต่ deal นี้ดันเฉพาะ TikTok) · ถ้าต่างจาก Campaign ให้แสดง chip "Differs from campaign"
- เปลี่ยน CTA ของ Campaign → ถาม "Apply to n open deals that still use the old CTA?"
- Deals › Filters เพิ่ม CTA · Export Deals CSV มี `cta` อยู่แล้ว (export แบบ Template ใช้คอลัมน์ CTA ตามเดิม)
- Migration: `campaigns.cta = null` ทุก Campaign (ทีมตั้งเอง) · ค่า cta ของ deal เดิมไม่เปลี่ยน (ว่างทั้งหมด)

### 4.8 Payment term ตอนสร้าง Deal — ผูกกับ KOL Master แต่แก้ได้
- New deal / Add to phase: ช่อง Payment term prefill จาก `kol_master.default_payment_term` พร้อมข้อความเล็ก "From KOL Master"
- แก้ในฟอร์มได้ทันที → ข้อความเปลี่ยนเป็น "Changed for this deal" และมี checkbox "Also update KOL default" (ไม่ติ๊กเป็นค่าเริ่มต้น)
- ถ้า KOL ยังไม่ตั้ง term: ช่องว่าง + บังคับเลือก (Error) + checkbox "Save as this KOL's default" ติ๊กไว้เป็นค่าเริ่มต้น
- ใน drawer ถ้า term ของ deal ต่างจากค่า default ของ KOL ให้แสดง chip "Differs from KOL default"
- กติกา "Apply to open deals" ตอนแก้ที่ KOL Master ยังใช้ตาม CR-02 §4.3
