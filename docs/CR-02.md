## 4. Implementation details

### 4.1 หลักการ
- Journey แยกเป็น 2 track ที่ไม่บังคับกัน: **Content plan** (งานเดินถึงไหน) และ **Payment term** (เงินถึงกำหนดเมื่อไร)
- **Complete = โพสต์ครบ** เหมือนเดิม (ตรงกับ Template) ส่วนเรื่องเงินดูที่ Payment / Unpaid / Needs attention
- ยอดผูกพันและสูตรเงินไม่เปลี่ยน

### 4.2 Content plan (Journey ตามแผนของแต่ละ deal)

> **หมายเหตุ (CR-07, 06/10/2026):** Deal drawer › Journey แสดงเป็น **timeline แบบ SLA** (วันที่ผ่านแต่ละขั้น · ⏱ ระยะเวลา · late / overdue เทียบ expected · Waiting n d) แทน stepper — กติกา Move stage / Content plan ไม่เปลี่ยน → CR-07 §4.9

- ขั้นของ deal = List steps เดิม (Shortlist, Contacted, Confirm QT) → **Brief** → [**Approve Script** ถ้า `script_required`] → **Approve Draft 1 … Approve Draft {draft_rounds}** → **Post**
- ขั้นที่ไม่อยู่ในแผนต้องไม่แสดงใน stepper, Stage column, Pipeline และไม่นับในกติกา "ข้ามขั้น"
- `next_step` หลัง Draft สุดท้ายของแผน = Post
- Move stage ไป Approve Draft k ที่ k > `draft_rounds` ไม่ได้ (Error) → ใน dialog มีตัวเลือก **"+ Add draft round"** ที่เพิ่มรอบแล้วขยับในครั้งเดียว · สูงสุด 3 รอบ
- Drawer › Journey มีบรรทัด **Content plan**: `Drafts: 2 [−] [+]` · `Script: [toggle]`
  - ลดรอบได้เฉพาะรอบที่ยังไม่ผ่าน · ปิด Script ได้เฉพาะเมื่อยังไม่ผ่าน Approve Script
  - ใช้ได้โดยไม่ต้องกด Edit (เป็น action เหมือน Move stage) และบันทึก `deal_events` type = `plan`
- New deal: `draft_rounds = 1`, `script_required = false`
- Warning เรื่องวันที่ (overdue, approved ก่อน brief) ใช้เฉพาะรอบในแผน · ถ้ามีวันที่ของรอบนอกแผน → Info "มีวันที่ Draft n แต่แผนมี m รอบ"
- `due_date` ของ Approve Draft n ใช้ `expected_draft{n}_date` เหมือนเดิม

### 4.3 Payment term

> **หมายเหตุ (CR-07, 06/10/2026):** การแสดงผลใน Deal drawer เป็น **Payment track** ใต้ Journey (Docs → Deposit 50% / 50% → Paid · Before Brief / After Post · สีตาม payment_state) — กติกา payment_state ไม่เปลี่ยน → CR-07 §4.9

> **หมายเหตุ (CR-08, 06/10/2026):** สถานะจ่ายของ deal (Docs / 50% / Paid) ไม่ติ๊กที่ deal แล้ว — มาจาก **Payment line** ในหน้า Payments แล้ว sync กลับไปที่ `docs_done` / `paid_50` / `paid_full` (+ วันที่) · กติกา Payment term / Due / payment_state ไม่เปลี่ยน · งวดที่ต้องจ่ายคำนวณจาก term (Prepaid = Full ตอน Confirm QT · 50/50 = Deposit ตอน Confirm QT + Final ตอน Complete · หลังโพสต์ / Not set = Full ตอน Complete) → CR-08 §4.3

**ตั้งค่า**
- KOL Master › Profile มี field **Default payment term** (view / edit) และเพิ่มเป็นตัวเลือกใน Filters ของหน้า KOL Master
  - ถ้าเปลี่ยนค่าแล้ว KOL มี deal ที่ยังไม่ปิด (List / In process) ให้ถาม **"Apply to n open deals?"** · Yes = อัปเดต deal เหล่านั้น + บันทึก `deal_events`
- New deal / Add to shortlist: ดึง `payment_term` จาก KOL · ถ้า KOL ยังไม่ระบุ ต้องเลือกก่อนบันทึก (**Error เฉพาะ deal ใหม่**) และมี checkbox "Save as this KOL's default"
- Drawer › Payment แก้ term ได้ในโหมด Edit (บันทึก `deal_events` type = `payment_term`)

**Milestones ตาม term** (checkbox ที่ไม่เกี่ยวข้องให้ซ่อน)

| term | milestones | กำหนด |
|---|---|---|
| prepaid | Docs → Paid | ต้อง Paid ก่อนถึง Brief |
| split_50 | Docs → Deposit 50% → Paid | Deposit ก่อนถึง Brief · Paid หลัง Post |
| postpaid | Docs → Paid | Paid หลัง Post |
| free | — | — |
| null | Docs → 50% → Paid (แบบเดิม) | ไม่มีกำหนด |

**payment_state** (`rules.paymentState(deal, today)`)

| State | เงื่อนไข | สี |
|---|---|---|
| Paid | paid_full | เขียว |
| Deposit paid | split_50 และ paid_50 แต่ยังไม่ paid_full และยังไม่ Post | น้ำเงิน |
| Overdue | prepaid ผ่าน Brief แล้วยังไม่ Paid · split_50 ผ่าน Brief แล้วยังไม่ Deposit | แดง |
| Due | (split_50 / postpaid / null) Complete แล้วยังไม่ Paid | เหลือง |
| Not due | ยังไม่ถึงกำหนด | เทา |
| Free | term = free | เทา |

- Payment column แสดงบรรทัดเดียว: term ตัวเล็กสีเทา + state เช่น `50/50 · Deposit paid` · `After post · Due` · `Not set · Paid` · tooltip แสดง Docs / Deposit / Paid พร้อมวันที่
- **Unpaid (นิยามเดิม)** = Complete และ term ≠ free และยังไม่ paid_full → seed ต้องยังได้ **130**
- Info: term = free แต่ total > 0 → "Free แต่มีค่าใช้จ่าย ฿x"
- Overview › Needs attention เพิ่ม 2 รายการ:
  - **Payment before brief** = prepaid / split_50 ที่สถานะ Overdue (seed = 0 → ซ่อน)
  - **Payment term not set** = deal ที่ยังไม่ปิดและ term = null (แสดงจำนวน คลิกแล้วไป Deals filter นี้)
- Deals › Filters › Payment เปลี่ยนตัวเลือกเป็น payment_state + term

### 4.8 Campaign & Phase
**Status (คำนวณจากวันที่ ไม่ให้กรอกเอง)** — `rules.phaseStatus(phase, today)`, `rules.campaignStatus(phases, today)`
- Phase: Not started = today < start · On going = start ≤ today ≤ end · Complete = today > end
- Campaign: On going ถ้ามี Phase ใด On going · Not started ถ้าทุก Phase ยังไม่เริ่ม · Complete ถ้าทุก Phase จบแล้ว · ถ้ามีทั้ง Phase ที่จบแล้วและที่ยังไม่เริ่มแต่ไม่มี On going → On going (อยู่ระหว่าง Phase)
- Chip: On going = น้ำเงิน · Not started = เทาขอบ · Complete = เขียวจาง

**Header & Filter**
- Header: "Campaign & Phase" · ขวา `+ New ▾` (New campaign / New phase) เป็น primary ปุ่มเดียว
- **Year** dropdown: default = ปีปัจจุบัน · ตัวเลือก = ปีที่มีข้อมูล + "All years" · Campaign อยู่ในปีนั้นถ้ามี Phase ใดคาบเกี่ยวกับปี
- **Status tabs** พร้อมจำนวน Campaign: All · On going · Not started · Complete
- **Search** ชื่อ Campaign / Phase (ถ้าเจอ Phase ให้แสดง Campaign แม่ด้วย)

**Sort** — `rules.sortCampaigns(campaigns, phases, today)`
- Campaign: On going (end_date ใกล้สุดก่อน) → Not started (start_date ใกล้สุดก่อน) → Complete (end_date ล่าสุดก่อน) · ถ้าเท่ากันใช้ start_date แล้วชื่อ
- Phase ภายใน Campaign: start_date น้อยไปมาก
- ลำดับนี้ใช้กับ Campaign dropdown ในหน้า Deals ด้วย

**Layout** (เต็มความกว้าง · แถวสูง 44px เท่ากันทั้งตารางและ timeline)
- ซ้าย (ตาราง): Name (Campaign = chevron + ชื่อตัวหนา · Phase = เยื้อง + ชื่อ) · Status · Period · Budget · Committed (+ usage bar 80px + %, แดงถ้า > 100%, ไม่มีงบ = "No budget") · Deals
  - แถวรวมล่างสุด: Total · Budget · Committed · Deals (ไม่นับ Cancel) ตาม filter
- ขวาสุด (**Gantt timeline**, กว้างที่เหลืออย่างน้อย 480px, เลื่อนแนวนอนในกรอบตัวเอง, ตารางซ้าย sticky)
  - ช่วง = ม.ค.–ธ.ค. ของปีที่เลือก (All years = เดือนแรกถึงเดือนสุดท้ายที่มีข้อมูล) · หัวคอลัมน์เป็นเดือน (Jan … Dec) · เส้นแบ่งเดือนสีอ่อน
  - เส้นแนวตั้ง **Today** (สี primary บาง ๆ) + ปุ่ม "Today" เลื่อน timeline ไปที่วันนี้
  - แถว Phase: แท่งสูง 16px มุมโค้ง 4px สีตามสถานะ (On going น้ำเงินทึบ · Not started ขอบเทา · Complete เขียวจาง) · Committed เกินงบ = ขอบแดง
  - แถว Campaign: แท่งบาง 6px สีเทาเข้ม ตั้งแต่ start แรกถึง end สุดท้าย
  - Tooltip: ชื่อ · dd/mm/yyyy – dd/mm/yyyy · "12 days left" / "Starts in 5 days" / "Ended" · ฿committed / ฿budget
  - คลิกแท่งหรือแถว = เปิด drawer ของ Campaign / Phase (view-before-edit)
- มือถือ (< 768px): ซ่อน timeline และมีปุ่มสลับ `Table | Timeline`
- ลบ Phase ที่มี deal ไม่ได้ (กติกาเดิม)
