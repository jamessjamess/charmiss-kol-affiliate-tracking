# CR-23 — Products given · Cancelled report · Next due · Drag to Post / Cancel · Ship by · Deal modal fixes

ใช้กติกาถาวรใน CLAUDE.md · ช่องบังคับต่อ stage อยู่ที่ `rules.stageRequirements()` ที่เดียว · due ทุกที่ใช้ `rules.dueDate()` ตัวเดียว
ลำดับทำงานที่แนะนำ: §3.8 (แก้บั๊ก Deal modal) → §3.1 + §3.7 (Dashboard) → §3.2–3.6

## 1. เป้าหมาย
- By campaign เห็นสินค้าที่ให้ไป และ deal ที่ยกเลิกพร้อมเหตุผล
- ทุกงานที่รอจาก KOL มีวันกำหนด · งานฝั่งเรา (Approve) ไม่ต้องถาม
- ลากการ์ดไปจบที่ Post หรือ Cancel ได้ในจังหวะเดียว
- วันกำหนดส่งสินค้ามาจากคนตั้ง ไม่ใช่ระบบเดา
- Deal modal แสดงครบตาม CR-22

## 2. เดิม → ใหม่
- By campaign ไม่มีข้อมูลสินค้า → + การ์ด **Products given** (§3.1)
- By campaign ไม่มีสรุปการยกเลิก → + การ์ด **Cancelled deals** (§3.7)
- Next expected: Draft 2 / 3 optional · Draft สุดท้ายถาม Expected approve → Draft ถัดไปในแผน **บังคับ** · ไม่ถาม Expected approve · ถาม **Post due** แทน (§3.2)
- ลากไป Post / Cancel ลากไม่ถึง (section อยู่ล่างจอ) → **drop zone ลอยล่างจอ** (§3.3)
- Ship by คำนวณเอง (CR-10) แล้วขึ้น Overdue เอง → ช่อง **Ship by \*** ไม่มีค่าเริ่ม · เลิกใช้ค่าคำนวณเป็น due (§3.4)
- เตือน "not in exactly one phase" อ่านไม่รู้เรื่อง → ข้อความบอกวันที่และช่วง Campaign (§3.5)
- Cancel: เหตุผลเป็นข้อความอิสระ → **Reason (รายการ) \*** + รายละเอียด (§3.6)
- Deal modal ไม่มี tabs และอื่นๆ (บั๊ก CR-22) → แก้ตาม §3.8

## 3. Spec

### 3.1 Products given (Dashboard › By campaign)
- การ์ดเต็มความกว้าง ต่อจาก Pillar allocation · ใช้ตัวกรอง Campaign / Phase ของหน้า · นับเฉพาะ shipment ของ deal ที่ไม่ Cancel
- **Stat tiles 4 ช่อง** (ไม่ใช้กราฟ): **Total pieces** ("to n KOLs") · **NPD** (% of total) · **Warehouse** (% of total) · **KOL buys own** ("฿x reimbursed")
- **ตาราง 1 แถวต่อสินค้า:** Product (TR code + ชื่อ) · **Total** · NPD · Warehouse · KOL buys own (0 = "—") · Delivered (Delivered / Purchased) · To ship (To ship / Shipped) · KOLs
  - เรียง Total มาก → น้อย · แถวท้าย Total (KOLs ไม่นับซ้ำ)
  - shipment ไม่มีรายการสินค้า → แถว **"Product not recorded"** สีเทาท้ายตาราง
  - คลิกแถว → Shipments กรอง Campaign (+ Phase) + สินค้านั้น
  - ไม่มี shipment → "No products sent yet — they're recorded when a deal moves to Confirm QT"
- Export Dashboard: + sheet `Products given` (ไม่มี PII)
- คำนวณที่ `rules.productsGiven(deals, shipments, {campaignId, phaseId})` ตัวเดียว (การ์ด + Export)

### 3.2 Next expected — งานถัดไปของ KOL บังคับ · Approve ไม่ถาม
หลักการ: ถามวันที่ของ **สิ่งที่ KOL ต้องส่งถัดไป** และบังคับเสมอ · Approve เป็นงานฝั่งเรา ไม่ถามวันคาด

| Move ไป | Next expected | บังคับ |
|---|---|---|
| Brief | Expected Draft 1 date (+ Expected script date ถ้ามี Script ในแผน) | Draft 1 ✓ · Script ✓ |
| Script | Expected Draft 1 date | ✓ |
| Draft k · แผนมี Draft k+1 | **Expected Draft k+1 date** | **✓** (เดิม optional) |
| Draft k · Draft สุดท้ายในแผน | **Post due** (prefill ค่าเดิม) + ลิงก์ `+ Add Draft k+1 round` | Post due — · กด Add round แล้ว Expected Draft k+1 **✓** |
| Draft k ที่ไม่อยู่ในแผน (☑ Add Draft k to the plan) | ขยายแผนก่อน แล้วใช้กติกา 2 แถวบน | ตามแถวบน |
| Approve | Post due | ✓ |

- ตัดช่อง **Expected approve date** ออกจาก Move stage dialog · ฟิลด์ `expected_approve_date` ยังแก้ได้ใน Deal modal › Timeline (ใช้ภายใน · ไม่บังคับ)
- `rules.dueDate`: ขั้นถัดไป = Approve → ใช้ `expected_approve_date` เฉพาะถ้ามีค่า · ว่าง = ไม่มี due / ไม่ขึ้น Overdue
- ตัวอย่างจากภาพ (D000374 3decox · Draft 1 → Draft 2 ☑ Add Draft 2 to the plan): ส่วน Next expected = **Post due** + `+ Add Draft 3 round` (ไม่มี Expected approve date) · กด Add Draft 3 round → **Expected Draft 3 date \***
- error: "Enter the expected Draft 3 date" · "Enter the post due"
- ข้ามหลายขั้น: ถามเฉพาะ Next expected ของปลายทาง (เดิม)

### 3.3 Drag ไป Post / Cancel ได้ทันที
- ระหว่างลากการ์ดใน Pipeline → แสดง **drop zone ลอยล่างจอ** (sticky · เต็มความกว้างของ board) 2 ช่อง: **"Drop to mark as posted"** (เขียว) · "Drop to cancel" (แดง · เล็กกว่า) · หายเมื่อปล่อย
- ลาก Posted / Cancelled section ที่กางอยู่ก็ยังใช้ได้ (เดิม)
- ใช้ได้จากทุก stage ก่อน Post (CR-20 §4.9) · เน้น Draft 1 / 2 / 3 / Approve
- ปล่อยแล้ว **เปิด Move stage dialog ปลายทาง Post เสมอ** (ต้องมี Posted link) แบบย่อ:
  - แสดงเฉพาะส่วนที่ยังขาด (Costs · Pillar · Payment term · CTA · Sample shipment · วันที่ขั้นที่ข้าม / Draft ที่ไม่ทำ = Not needed · Approve date) + ส่วน **Post** (Posted link \* · Post date \* · Mark sample as delivered)
  - ส่วนที่ครบแล้วยุบเป็นบรรทัดสรุป "✓ Costs ฿1,000 · ✓ Shipment NPD" (คลิกเพื่อกางแก้)
  - focus ช่อง Posted link ทันที · Enter = Move เมื่อครบ
- Cancel ใน dialog → การ์ดกลับที่เดิม · Move สำเร็จ → toast Undo (ย้อนทั้งหมด)
- ส่วน Post: ถ้า shipment ยังไม่ Delivered → ☑ **Mark sample as delivered** ติ๊กไว้ให้ (KOL โพสต์แล้วแปลว่าได้ของแล้ว · เอาออกได้)
- ปล่อยที่ **"Drop to cancel"** → Cancel dialog (§3.6) · ใช้ได้จากทุก stage ก่อน Post

### 3.4 Sample shipment — Ship by
- เพิ่มช่อง **Ship by \*** (NPD / Warehouse) · **Buy by** (KOL buys own · optional) ใต้ Method
- **ไม่มีค่าเริ่ม** (ว่าง · บังคับ) · ปุ่มลัด `+3d` `+5d` `+7d` (นับจาก Date ที่ Move) · hint เทา "Suggested: 18/10 (7 days before the post due)" คลิกเพื่อใส่เอง
- **เลิกใช้ ship by ที่คำนวณ (CR-10) เป็น due:** Overdue / Due in next 7 days / ไอคอนแดง คิดจาก `ship_by_date` ที่คนกรอกเท่านั้น · shipment ที่ยังไม่มี ship_by_date แสดง "Ship by not set" (เทา · ไม่ Overdue) + ลิงก์ `Set`
- shipment เดิม (ก่อน CR นี้): ไม่ย้ายค่าคำนวณมาใส่ให้ · ขึ้นในหน้า Shipments แถบเทา "n shipments have no ship-by date · Set dates"
- ห้ามก่อนวันที่ Move · หลัง Expected Draft 1 → เตือนส้ม "After the Draft 1 due — the KOL may not have the product in time" (ไม่บล็อก)
- บันทึกที่ `sample_shipments.ship_by_date`
- ใช้เป็น due: Shipments (เรียง · Overdue สีแดง) · ไอคอนกล่องบนการ์ด Pipeline (แดงเมื่อเลย) · Dashboard › Due in next 7 days · บรรทัดสรุป shipment ใน dialog / Deal modal "NPD · Test 1 ×1 · Ship by 12/10"
- แก้ภายหลังได้ใน Deal modal › Shipments & posts และหน้า Shipments
- New deal Start at = Confirm QT: Ship by อยู่ในแถบหัว (ใช้กับทุกแถว)

### 3.5 Post due / Post date นอกช่วง Campaign
- ช่อง Post due (ทุกที่: Move stage · New deal · Deal modal) และ Post date: ถ้าไม่อยู่ในช่วงของ Phase ใดของ Campaign → เตือนส้มใต้ช่องทันที "25/10 is before this campaign starts (01/11)" / "…after this campaign ends (31/12)" / "…falls between phases" (ไม่บล็อก)
- แถบเตือนใน Deal modal ใช้ข้อความเดียวกัน แทน "the date is not in exactly one phase — pick the phase of this post" · มีปุ่ม `Change date` · `Pick phase`
- เตือนเรื่อง phase เฉพาะโพสต์ที่มี Post date จริงแล้ว · Post due (ยังไม่โพสต์) ใช้ข้อความ "Post due …" ไม่ใช่ "Post 1 …"
- Phase ของ deal ที่ Auto by post date และ Post due อยู่นอกช่วง → ใช้ Phase แรก (ก่อนเริ่ม) / Phase สุดท้าย (หลังจบ) + เตือนตามข้างบน

### 3.6 Cancel — dialog + เหตุผล
- เปิดจาก: ลากไป drop zone "Drop to cancel" · ลากไป Cancelled section · Move stage › Cancel · ⋯ › Cancel deal
- ช่อง: **Reason \*** (dropdown จาก `lookups.cancel_reasons`) · **Detail** (ข้อความ · บังคับเมื่อเลือก Other) · Date (default วันนี้)
- ค่าเริ่ม `lookups.cancel_reasons` (แก้ได้ที่ Settings › Lists): KOL declined · Price not agreed · No response from KOL · Schedule doesn't fit · Content not approved · Brand / campaign change · Other
- ผลกระทบที่แสดงใน dialog ก่อนยืนยัน:
  - "Releases ฿x from the campaign budget" (ถ้าผ่าน Confirm QT แล้ว)
  - shipment ที่ยัง To ship → ☑ "Also cancel the sample shipment" (ติ๊กไว้ให้) · Shipped / Delivered → แสดงเฉยๆ ไม่ยกเลิก
  - Package → "Returns 1 use to the package"
  - มีการจ่ายเงินแล้ว (Sent / Paid) → เตือนส้ม "Payment already sent / paid — follow up with accounting" (ไม่บล็อก)
- บันทึก: `cancel_reason_key` + ข้อความเดิมของช่อง reason → Detail · stage ตอนยกเลิก (จาก log) · toast Undo
- deal ที่ยกเลิกก่อน CR นี้: reason_key ว่าง → แสดงเป็น "Other" + ข้อความเดิม

### 3.7 Cancelled deals (Dashboard › By campaign)
- การ์ดเต็มความกว้าง ต่อจาก Products given · ใช้ตัวกรอง Campaign / Phase ของหน้า
- บรรทัดบน: "n cancelled · ฿x released" + chip นับต่อเหตุผล (เรียงมาก → น้อย · คลิก chip = กรองตาราง)
- **ตาราง:** KOL (รูป + ชื่อ) · Deal ID · Cancelled at (stage ตอนยกเลิก) · Cancelled on · **Reason** · **Detail** · Value (Total cost ตอนยกเลิก · "—" ถ้ายังไม่ถึง Confirm QT) · Assigned to
- เรียง Cancelled on ใหม่ → เก่า · คลิกแถว = Deal modal · Detail ยาวตัด 1 บรรทัด + tooltip
- ไม่มี → "No cancelled deals in this campaign"
- Export Dashboard: + sheet `Cancelled` (คอลัมน์เดียวกัน · ไม่มี PII)
- คำนวณที่ `rules.cancelledReport(deals, log, {campaignId, phaseId})` ตัวเดียว

### 3.8 แก้บั๊ก Deal modal (จาก CR-22 §3.6)
1. **ไม่มีแถบ tabs** (เห็นแค่ Overview / Shipments + Posts) → ใส่ tab bar ใต้ Journey: Overview · Costs & payment · Timeline & content · Shipments & posts · History
2. แถบเตือนบนสุดถูก header (sticky) บัง → เว้นระยะใต้ header · เปิด modal ที่บนสุดเสมอ
3. Deal › Products "—" ทั้งที่ shipment มีสินค้า → ตอน Move ไป Confirm QT ถ้า deal ยังไม่มี Products ให้บันทึกจากสินค้าใน shipment · deal เดิมที่ว่าง = ลิงก์ `Use shipment products`
4. สรุป shipment ไม่ตรงกัน (Next ไม่บอก Ship by แต่แถบใต้ Journey บอก) → ใช้ฟังก์ชันสรุป shipment ตัวเดียวทุกที่ · ตาราง Shipments ใน modal แสดงชื่อสินค้า "Test 1 ×1" ไม่ใช่รหัส "11001×1"
5. Next › Due "—" → "No due date" สีเทา
6. การ์ด Money / Next ไม่มีทางไปรายละเอียด → ลิงก์ "View costs ›" / "View timeline ›" ไป tab นั้น · การ์ด 3 ใบสูงเท่ากัน
7. ข้อความเตือนภาษาไทย "ติ๊กจ่ายเงินแล้ว แต่ยังไม่ได้ติ๊กทำเอกสาร" → "Marked as paid, but documents aren't checked yet" (ค้นข้อความไทยที่เหลือในแถบเตือนทั้งหมดด้วย)
