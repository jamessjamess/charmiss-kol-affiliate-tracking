**Date presets** — `rules.dateRangePreset(name, today)`

| Preset | ช่วง (today = 06/10/2026) |
|---|---|
| **This year** (default) | 01/01/2026 – 31/12/2026 |
| This quarter | 01/10/2026 – 31/12/2026 |
| This month | 01/10/2026 – 31/10/2026 |
| Last month | 01/09/2026 – 30/09/2026 |
| Custom | popover Start / End + **Apply** / Cancel (กติกา CR-05) |

- ใช้ช่วงปฏิทินเต็ม (ไม่ใช่ถึงวันนี้) เพื่อให้ Activity เห็นโพสต์ที่วางแผนไว้ในอนาคตของช่วงนั้น · KPI Posts / Views นับเฉพาะโพสต์ที่มี post_date ในช่วง

**Campaign portfolio**
- ตัดคอลัมน์ **Pillar mix**

> **หมายเหตุ (CR-09, 06/10/2026):** KPI เป็น 5 cards (Campaigns · Deals · Committed vs Budget · Paid · KOLs engaged — ไม่มี Posts / Views) + การ์ด **KOL tier mix** (Spend / Deals) ข้าง Activity by campaign · แกนเวลาแถวเดียวตามความยาวช่วง · Portfolio มีคอลัมน์ Days left (เรียงได้ทุกคอลัมน์) · Export ต่อการ์ด (.xlsx / CSV) และทั้ง tab → CR-09 §4.1–4.3, §4.5

### 4.4 Deals — Clear all filters (+ ใช้ component เดียวกันที่ KOL Master)

**นิยาม** — `rules.activeFilters(state)` คืนรายการ filter ที่ต่างจาก "สถานะว่าง"

| ส่วน | สถานะว่าง | นับเป็น filter? |

| Search | ว่าง | นับ |
| View · Group by · State tab · Sort | — | ไม่นับ · Clear all ไม่แตะ |

**UI**
- ปุ่ม text **"Clear all filters"** (ไอคอน ✕) ท้ายแถว chip · แสดงเมื่อ `activeFilters().length ≥ 1` · ซ่อนเมื่อไม่มี
- ปุ่ม Filters แสดงจำนวน เช่น "Filters · 2" (นับเฉพาะค่าใน panel)
- กดแล้ว `rules.clearFilters(state)` → reset ทุกส่วนที่นับในตารางเป็นสถานะว่างใน**ครั้งเดียว** (render ครั้งเดียว) · จำค่าใหม่ต่อ user (reload แล้วยังเป็น All PICs)
- Empty state: "No deals match these filters" + รายการ filter ที่ใช้อยู่ + ปุ่ม Clear all filters (handler เดียวกัน)

**PIC single source of truth**
- dropdown PIC · chip PIC · ค่าใน panel Filters อ่าน/เขียน state เดียว (`filters.pic`) — ห้ามมีค่าแยกกัน
- โหลดค่าที่จำไว้แล้วไม่พบ PIC นั้น (inactive / ถูกลบ) → ใช้ default ตาม CR-06 (Me ถ้าเป็น PIC, ไม่งั้น All PICs)

**KOL Master** — ใช้ component เดียวกันกับแถว filter (Search · Platform · Tier · Type · Category · PIC · Status · Last worked · Performance) · กติกาเหมือนกัน (ไม่มี Campaign)

### 4.5 Cost entry — ใส่ราคาเอง + Price reference
**ใช้ที่:** KOL Master › Add to campaign · Deals › New deal · Deal drawer › Costs (โหมด ✎) · KOL drawer › Rates (แสดงอย่างเดียว)
- **ไม่ prefill** ช่องค่าใช้จ่าย · ลบกล่อง "Costs filled from the latest rate" · ช่องว่างแสดง placeholder "0"
- ข้างช่องกรอก (หรือใต้ช่องกรอกเมื่อ modal แคบกว่า 640px) มีกล่อง **Price reference** 2 คอลัมน์

**Price reference** — `rules.costReference(kolId, store)` (pure function · unit test)

| แถว | Latest rate | Average of past deals |
|---|---|---|
| Rate card · Gencode · Basket fee · Asset fee · Expediting fee | ค่าจาก quote ล่าสุด | ค่าเฉลี่ยรายช่อง |
| **Total** | รวม | รวม |

- ซ่อนแถวที่ทั้ง 2 คอลัมน์เป็น 0 / ว่าง (Rate card และ Total แสดงเสมอ)
- **Latest rate** = quote ล่าสุดที่มี `rate_card` เป็นตัวเลข (กติกา CR-01 §4: quoted_at ล่าสุด, null อยู่ท้าย, เท่ากันใช้ quote_id มากสุด · รวม quote ที่สร้างจาก deal ตอน Confirm QT)
  - บรรทัดเทาใต้หัว: source · วันที่ (dd/mm/yyyy หรือ "Date not recorded")
  - ไม่มี quote ตัวเลข → "No rate on file"
  - มี quote ที่ใหม่กว่า (หรือมีแต่) แบบไม่มีตัวเลข → บรรทัดเทา "Note: <note>" เช่น "Note: Ratecard: รออัพเดต"
- **Average of past deals** = deal ของ KOL นี้ที่
  1. ไม่ Cancel และอยู่ขั้น **Confirm QT ขึ้นไป** (ราคาตกลงแล้ว · Shortlist / Contacted ไม่นับ)
  2. ไม่ใช่งานฟรี: `payment_term ≠ free` **และ** Total > 0
  - เฉลี่ยรายช่อง (ช่องว่าง = 0) ปัดเป็นบาท · บรรทัดเทาใต้หัว: "n deals" และถ้ามีงานฟรีถูกตัด "· k free jobs excluded"

### 4.7 KOL drawer — กว้าง 50% ของหน้าจอ
**ความกว้าง** — `ui.kolDrawerWidth(viewport, menuWidth)`
- default = `clamp(680px, 50% ของ viewport, 1100px)`
- ถ้า (พื้นที่เนื้อหา − drawer) < 320px → drawer เต็มพื้นที่เนื้อหา (พื้นที่เนื้อหา = viewport − menu 240 / rail 64 / 0 บนมือถือ)
- ตัวอย่าง: 1920 → 960 · 1440 → 720 · 1280 (menu ขยาย) → 680 · 1024 (rail) → เต็ม · 390 → เต็ม
- **Resize:** ลากขอบซ้ายของ drawer (พื้นที่จับ 6px, cursor col-resize) · ต่ำสุด 560px · สูงสุด พื้นที่เนื้อหา − 320px · จำค่าใน localStorage `ui.kolDrawerWidth` (try/catch) · double-click ขอบ = กลับเป็น 50%
- ตาราง KOL ด้านซ้ายยังใช้งานได้: คลิก KOL แถวอื่นขณะ drawer เปิด → เปลี่ยนเนื้อหา drawer ทันที (ไม่ปิด/เปิดใหม่ · ความกว้างคงเดิม) · แถวที่เปิดอยู่ highlight

**Layout ภายใน** (เมื่อ drawer ≥ 680px · แคบกว่านั้นเป็นคอลัมน์เดียวตามเดิม)

### 4.9 Deals — Journey timeline (แบบ SLA)
**ที่อยู่:** Deal drawer › section **Journey** บนสุด (แทน stepper เดิม) · ด้านล่างยังเป็น Content plan (`Drafts` / `Script`) และปุ่ม Move stage ตาม CR-02

**ขั้นที่แสดง** = แผนของ deal (CR-02 §4.2): [Shortlist] → [Contacted] → Confirm QT → Brief → [Approve Script] → Approve Draft 1 … {draft_rounds} → Post
- Shortlist / Contacted แสดงเฉพาะเมื่อเคยผ่าน (มีใน log) หรือเป็นขั้นปัจจุบัน
- Label สั้น: Shortlist · Contacted · Confirm QT · Brief · Script · Draft 1 · Draft 2 · Draft 3 · Post

**ข้อมูลต่อขั้น** — `rules.dealTimeline(deal, statusLog, posts, today)` → `[{ step, state, date, expected, days, late_days }]`
- `date` (วันที่ผ่าน) = `effective_date` ล่าสุดของขั้นนั้นใน `deal_status_log` → ถ้าไม่มีใช้ date field (Brief = brief_date · Draft n = approved_draft{n}_date · Post = post_date ล่าสุดของโพสต์ในแผน) → ไม่มีเลย = "Date not recorded"
- `expected` = expected_draft{n}_date (Draft n) · expected_post_date (Post) · ขั้นอื่นไม่มี
- `days` = จำนวนวันจากขั้นก่อนหน้าที่**มีวันที่** ถึงขั้นนี้ (หน่วยวัน เพราะข้อมูลเป็นวันที่ ไม่มีเวลา)

| state | เงื่อนไข | แสดง |
|---|---|---|
| Done | ผ่านแล้ว และ (ไม่มี expected หรือ date ≤ expected) | วงกลมเขียว ✓ · วันที่ dd/mm · ⏱ n d |
| Done late | ผ่านแล้ว และ date > expected | วงกลมเขียว ✓ · วันที่ · ป้ายแดง "+n d late" |
| Done (no date) | ผ่านแล้วแต่ไม่มีวันที่ | วงกลมเขียวจาง ✓ · "Date not recorded" · ไม่มี ⏱ |
| Current | ขั้นถัดไปของ deal (ขั้นที่กำลังทำ) | วงกลมส้ม ⏳ + วงแหวน · "Waiting n d" (today − วันที่ของขั้นก่อนหน้า) · ถ้ามี expected แสดง "Due dd/mm" |
| Overdue | Current หรือ Upcoming ที่ today > expected | ขอบ/ข้อความแดง "Due dd/mm · n d overdue" |
| Upcoming | ยังไม่ถึง | วงกลมเทาว่าง · "Due dd/mm" ถ้ามี expected · ไม่งั้น "–" |
| Cancelled | deal Cancel | เส้นหยุดที่ขั้นที่ไปถึง + วงกลมแดง ✕ "Cancelled dd/mm" + reason (tooltip) · ขั้นหลังจากนั้นซ่อน |

- เส้นเชื่อม: ช่วงที่ผ่านแล้ว = เขียวทึบ · ช่วงหลังขั้นปัจจุบัน = เทาจาง (ไม่ใช้สีชมพู) · ความหนา 4px มุมเหลี่ยม
- สถานะต้องมีข้อความหรือไอคอนกำกับเสมอ (ไม่ใช้สีอย่างเดียว) · ผ่าน Light / Dark
- บรรทัดสรุปขวาบนของ section: "Brief → Post: n d" เมื่อ Complete · ระหว่างทาง "In progress n d since Brief" · ยังไม่ถึง Brief ไม่แสดง
- คลิกวงกลม → popover: ชื่อขั้นเต็ม · วันที่ · expected · ใครบันทึก (changed_by) · note จาก log

**Payment track** — `rules.paymentTimeline(deal, today)` (ใต้ timeline หลัก · ขนาดเล็กกว่า)
- ขั้นตาม term (CR-02 §4.3): prepaid = Docs → Paid · split_50 = Docs → Deposit 50% → Paid · postpaid = Docs → Paid · null = Docs → 50% → Paid · free = แสดงแค่ chip "Free"
- วันที่ = docs_done_date / paid_50_date / paid_full_date · กำหนดตาม term: prepaid / split_50 ต้องจ่าย (Paid / Deposit) "Before Brief" · postpaid / split_50 Paid "After Post"
- สีตาม payment_state เดิม (Overdue แดง · Due เหลือง · Paid เขียว) + label term ด้านซ้าย เช่น "50/50"

**Layout / Responsive**
- แนวนอนเมื่อความกว้าง section ≥ จำนวนขั้น × 76px · แคบกว่านั้น (เช่นมี 8 ขั้นใน drawer 560px หรือมือถือ) เปลี่ยนเป็น**แนวตั้ง** (เส้นด้านซ้าย ข้อมูลอยู่ขวาของวงกลม) · ห้าม horizontal scroll
- Deals table › Stage tooltip ใช้ข้อมูลชุดเดียวกัน (ขั้น · วันที่ · ⏱ n d · late / overdue) แบบรายการ
- ประวัติสถานะ (log) ใน section History ยังอยู่ตามเดิม
