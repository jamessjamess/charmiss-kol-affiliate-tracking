## 3. Data model
Rate ที่กรอก = `rate_card` ของ deal · Post due = `expected_post_date` (Phase คิดจากวันที่นี้ตาม Auto by post date)

**schema 18 → 19 (migration ครั้งเดียวตอนโหลด · ไม่แตะ seed file):**
| ที่ | เปลี่ยน |
|---|---|
| store ใหม่ `kol_packages` | `package_id` (PKG000001…) · `kol_id` · `name` · `units_total` (จำนวนครั้ง ≥1) · `price_total` (฿) · `start_date` · `valid_until` (null ได้) · `payee_id` (null ได้ · CR-16) · `payment_status` `to_pay` / `sent` / `paid` · `paid_date` · `note` · `archived` · `created_by` · `created_at` · `updated_at` |
| `deals` | + `package_id` (null) · + `package_units` (default 1) |
| `lookups.payment_terms` | + `Package` (ท้ายรายการ) |
| `deals` (v1.2) | + `script_link` (null) · ใช้ฟิลด์ cost เดิม `rate_card` · `gencode_expense` · `gencode_period` (วัน) · `asset_fee` · `expediting_fee` · `basket_fee` (เดิม · ไม่แสดงใน dialog) |
| store ใหม่ `step_notes` (v1.2) | key = `deal_id` + `step_key` (draft_1 / draft_2 / draft_3) · `note` (ข้อความ) · `links` (array https) · `image_ids` (array) · `updated_by` · `updated_at` |
| IndexedDB (CR-16) object store ใหม่ `step_images` | `image_id` · `deal_id` · `step_key` · blob WebP · `w` · `h` · `bytes` · `created_at` — ไม่อยู่ใน localStorage |
| ค่าคำนวณ (ไม่เก็บ) | `unit_price = price_total / units_total` · `used = Σ package_units ของ deal ที่ Confirm QT ขึ้นไปและไม่ Cancel` · `remaining = units_total − used` |

- Backup / Restore รวม `kol_packages` · `step_notes` · รูปใน `step_images` ไปกับ Backup เมื่อติ๊ก "Include photos" (CR-16 · เปลี่ยน label เป็น "Include photos & draft images") · log: `step_note_updated` · `package_created` · `package_updated` · `package_archived` · `package_paid`

## 4. Implementation details

### 4.1 แถบหัวร่วม (ทั้ง 2 tabs · ค่าคงอยู่เมื่อสลับ tab)
| ช่อง | รายละเอียด |
|---|---|
| **Campaign \*** | combobox เดิม (Campaign ที่ยังไม่อนุมัติเลือกไม่ได้ CR-17) · chip สถานะ + "Days left" เล็กๆ ข้างช่อง |
| Phase | Auto by post date (default) / เลือกเอง |
| **Assign to \*** | คนดูแล deal นี้ · default **Me (Pang)** · helper เทา "Owner of the new deals" |
| Pillar | ตามเดิม (prefill จาก Default pillar ของ Phase) |
| Start at | Shortlist (default) · Contacted · Confirm QT |
| Products | ตาม Campaign (สินค้าเดียวเลือกให้ · CR-11) |

- **ตัดบรรทัด "Adding to Charming Iconic Glow"** · ชื่อ Campaign อยู่ที่ช่อง Campaign ที่เดียว
- คำว่า **PIC** ในหน้านี้ไม่ใช้แล้ว: คนดูแล deal = `Assign to` · คนดูแล KOL ใน Master = `KOL owner` (ตัวกรอง · คอลัมน์ · การ์ด KOL) · tooltip ที่ KOL owner: "The PIC who looks after this KOL in KOL Master"

### 4.2 Tab `From KOL Master` (default) — เลือก 1 หรือหลาย KOL · กรอกน้อย
**ซ้าย: ค้นหา + ตัวกรอง + ตาราง** (เหมือน Bulk shortlist เดิม)
- ตัวกรอง: Search · Platform · Tier · Type · Category · **KOL owner** · Status · Last worked · Performance · **Worked in** (§4.3) · ☑ Not in this campaign yet · Clear all filters
- คอลัมน์: ☐ · KOL (รูป + ชื่อ) · Platform · Followers · Tier · Type · **Last campaign** (CR-14) · Performance · **KOL owner** · Latest rate
- คลิกชื่อ = เพิ่ม / เอาออก (เหมือนติ๊ก) · `Select all matching` (สูงสุด 200)

**ขวา: แผง Selected (n)** — 1 แถวต่อ KOL ที่เลือก กรอกได้ทันที
| คอลัมน์ | รายละเอียด |
|---|---|
| KOL | ชื่อ · tier · ✕ เอาออก |
| **Rate (฿)** | prefill = Latest rate (CR-07) · ใต้ช่องเทา "Avg ฿x" · แก้ได้ · ว่างได้ |
| **Post due** | date picker (ว่างได้) · Phase ที่ได้แสดงเล็กใต้ช่อง "→ Phase 2" (Auto by post date) |
| Payment term | แสดงเมื่อ Start at = Contacted (optional) หรือ Confirm QT (บังคับ) · prefill จาก KOL · เลือก `Package` ได้ → dropdown package ของ KOL นั้นในแถว (§4.8) |

- เครื่องมือบนแผง: `Set post due for all` · `Use latest rates` · `Clear rates`
- ท้ายแผง: **งบ Campaign** "Remaining ฿x → after adding ฿y" (แดงเมื่อติดลบ + ข้อความภาษาอังกฤษ) · "Will add n · Skip m (already in campaign / blacklisted)" · "n without post due" (เทา · ไม่บล็อก)
- ปุ่มหลัก: **`Add n deals`** (n = 1 ก็ได้) · ปุ่มรอง `Add & open first` (เปิด Deal modal ของ deal แรกไว้กรอกต่อ)
- หลังสร้าง: toast "n deals added · Undo" (กติกาเดิม CR-10)
- เปิดจาก KOL Master / KOL profile (`Add to campaign`) → เข้า tab นี้พร้อม KOL ที่เลือกอยู่ในแผงแล้ว

### 4.3 ตัวกรอง `Worked in` — ดึง KOL จาก Campaign อื่น
- multi-select Campaign (ทุก Campaign ยกเว้นที่กำลังเพิ่มเข้า) + ☐ `Posted only` (เฉพาะ KOL ที่โพสต์จบใน Campaign นั้นแล้ว)
- ผล = KOL ที่มี deal (ไม่ Cancel) ใน Campaign ที่เลือก**อย่างน้อย 1 อัน** · ใช้ร่วมกับตัวกรองอื่นแบบ AND (เช่น + Not in this campaign yet = "คนที่เคยทำ Kiss Signal แต่ยังไม่อยู่ใน Charming")
- นับใน Clear all filters

### 4.7 Move stage — ช่องที่ต้องกรอกตามปลายทาง
กติกาเดียว `rules.stageRequirements(deal, target)` (คืนรายการช่อง required / optional ที่ยังขาด):

| ปลายทาง | บังคับ | Optional |
|---|---|---|
| Contacted | Date | **Rate (฿)** · **Payment term** (+ Package) · Note |

- **Rate card (฿)** = `rate_card` ของ deal (ส่วน Costs ดู §4.11) · prefill: ค่าเดิมของ deal → ถ้าว่าง Latest rate ของ KOL (CR-07) · helper เทา "Latest ฿x · Avg ฿y" · ถ้า deal มีค่าใช้จ่ายอื่น (Gencode / Basket / Asset / Expediting) แสดง "Total ฿x" ใต้ช่อง · `0` ได้ (helper "฿0 = no fee, product only") · ว่าง ≠ 0
- **Payment term** prefill: ค่าเดิมของ deal → default ของ KOL (เดิม) · **Post due** แสดง "→ Phase 2" ใต้ช่อง
- ช่องที่ deal มีค่าอยู่แล้วแสดงค่า (แก้ได้) · บันทึกพร้อมการ Move ใน transaction เดียว (Undo ย้อนทั้งหมด)
- Deal ที่อยู่เลย Confirm QT แล้วแต่ข้อมูลขาด (เช่น legacy) → ขยับไปข้างหน้าต้องกรอกให้ครบก่อน · ขยับถอยหลังไม่บังคับ (Note บังคับตามเดิม)
- **Error:** แสดงหลังกด Move เท่านั้น (ไม่ขึ้นแดงตั้งแต่เปิด) · กรอบแดงที่ช่อง + กล่องสรุป 1 กล่อง · ปุ่ม Move กดได้เสมอ (ไม่ใช้สถานะจาง)
  - "Choose a pillar to move to Confirm QT or later" (แทนข้อความไทย) · "Choose a payment term to move to Confirm QT or later" · "Enter the rate card to move to Confirm QT or later" · "Enter how many days the Gencode runs" · "Add the posted link to move to Post" · "Enter the expected Draft 1 date" · "Expected date can't be before the move date"
- **งบ:** เมื่อ deal ข้ามจากก่อน Confirm QT ไป Confirm QT ขึ้นไป แสดง "Campaign remaining ฿x → ฿y after this move" (แดงเมื่อติดลบ · เตือน ไม่บล็อก)

### 4.8 Payment term `Package` — เหมาจ่ายหลายครั้ง ตัดยอดคงเหลือ
**สร้าง / จัดการ** — KOL modal (CR-16) › tab **Rates** › ส่วน **Packages**
- ตาราง: Name · Posts · Price · Unit price · Used · **Remaining** · Valid until · Payment · Status · `+ Add package` · Edit · Archive
- ฟอร์ม Add package: Name (default "10 posts · ฿30,000") · **Posts \*** (จำนวนเต็ม ≥1) · **Total price (฿) \*** · Unit price (คำนวณ · อ่านอย่างเดียว) · Start date (default วันนี้) · Valid until (optional) · Payee (เลือกจาก payee_profiles · optional) · Note
- แก้ Posts ให้ต่ำกว่า Used ไม่ได้ · Status: **Active** · **Used up** (remaining 0) · **Expired** (เลย Valid until · แสดง "n unused") · **Archived** — เลือกใช้ได้เฉพาะ Active
- Package เป็นของ KOL ใช้ข้าม Campaign ได้

**ใช้ใน deal** — Move stage dialog · การ์ด Payment ใน Deal modal · New deal (§4.10)
- เลือก Payment term = `Package` → ช่อง **Package \*** (dropdown package Active ของ KOL นั้น "10 posts · ฿30,000 — 7 left") + `+ New package` (ฟอร์มย่อ inline) · ช่อง **Uses** (default 1 · deal ที่มีหลายชิ้นงานใส่ 2 ได้)
- Rate ล็อก = Unit price × Uses · helper "From package" (ไม่ให้แก้ · ถ้าต้องการราคาอื่นให้เลือก term อื่น)
- **ตัดยอด:** นับเมื่อ deal ถึง Confirm QT ขึ้นไปและไม่ Cancel · ก่อน Confirm QT แสดง "Will use 1 · 7 left" (ยังไม่ตัด) · Cancel deal / เปลี่ยน term / เปลี่ยน package → คืนยอดอัตโนมัติ
- คงเหลือไม่พอ → บล็อก "Not enough left in this package (0 left) — choose another payment term or add a package"
- แสดงคงเหลือ: Move stage dialog · การ์ด Payment "Package · 10 posts ฿30,000 · Used 4 · 6 left" · header KOL modal chip "Package · 6 left" · การ์ด Pipeline badge เล็ก `PKG`

**เงิน (ต่อจาก CR-05 · CR-17)**
- ต้นทุน deal (Committed ของ Campaign) = Unit price × Uses → งบ Campaign คิดตามครั้งที่ใช้จริง
- การจ่าย = ระดับ package: Payments แสดง package เป็น **1 แถว** "Package · <KOL> · 10 posts" ยอดเต็ม · ปุ่ม Simple mode เดิม (Mark paid · Export for accounting → Sent · Mark unpaid) · deal ที่ใช้ package **ไม่สร้างแถวจ่ายของตัวเอง** · การ์ด Payment ของ deal แสดง "Paid via package" / "Package not paid yet"
- Dashboard: deal ที่ใช้ package นับเป็น **Paid** เมื่อ package จ่ายแล้ว · ไม่งั้นนับเป็น **Pending**
- มูลค่าที่จ่ายแล้วแต่ยังไม่ได้ใช้: แสดงที่หัวหน้า Payments "Prepaid package balance ฿x" (ไม่นับใน Campaign ใด)
- Export: sheet `Packages` (KOL display name · Name · Posts · Price · Unit price · Used · Remaining · Status · Payment) — ไม่มี PII

### 4.9 ลากข้ามหลาย stage
- ลากไปข้างหน้า **1 ขั้น** และไม่มีช่องบังคับที่ขาด → ย้ายทันที (Date = วันนี้) + toast Undo (เดิม)
- ลากข้าม **มากกว่า 1 ขั้น** หรือ 1 ขั้นแต่ขาดช่องบังคับ → เปิด Move stage dialog โดยเลือกปลายทางไว้แล้ว · ต้องกรอกตาม §4.7 ให้ครบจึงย้ายได้
- ส่วน **"Steps completed by this move"** ใน dialog: รายการขั้นที่ข้าม (ไม่รวม Contacted ที่เป็น optional และ Draft ที่ไม่อยู่ในแผน) พร้อมวันที่ · default = Date ที่เลือก · แก้รายขั้นได้ · ต้องเรียงตามลำดับ (ไม่ก่อนขั้นก่อนหน้า · ไม่เป็นวันในอนาคต) · Contacted แสดง ☐ `Also mark Contacted` (ไม่ติ๊กไว้)
- ปลายทาง Post → dialog เดียวกันเพิ่มส่วน Post (แทน Move to Post dialog แยกของ CR-15 §4.6 · ช่องเดิม)
- ลากถอยหลัง → dialog พร้อม Note บังคับ (เดิม) · กด Cancel ใน dialog → การ์ดกลับที่เดิม

### 4.10 New deal ใช้กติกาเดียวกัน
- Start at = Contacted → แผง Selected มีคอลัมน์ Payment term (optional) · Rate (optional)
- Start at = Confirm QT → ใช้ `stageRequirements(…, 'Confirm QT')`: Pillar (แถบหัว) · Payment term · Rate บังคับ · Post due optional · Package ได้ (ตัดยอดทันทีเมื่อสร้าง)
- ตัวตรวจในแผงแสดงจำนวนแถวที่ยังขาด "2 rows need a rate" · ปุ่ม Add กดได้ → เลื่อนไปแถวแรกที่ขาด + กรอบแดง
- แผง Selected กรอกแค่ Rate card (= ช่อง Rate) · Gencode / Asset / Expediting กรอกภายหลังใน Deal modal › Costs (optional ตาม §4.11)

### 4.11 Costs ตอน Confirm QT
ส่วน **Costs** ใน Move stage dialog (แสดงเมื่อปลายทาง ≥ Confirm QT และ deal ยังไม่ผ่าน Confirm QT · หรือขาด Rate card) — ช่องเดียวกับการ์ด Costs ใน Deal modal

| ช่อง | กติกา |
|---|---|
| **Rate card (฿) \*** | บังคับ · 0 ได้ (no fee) · prefill + helper Latest / Avg ตาม §4.7 · Package → ล็อกจาก package |
| Gencode cost (฿) | optional · ถ้า > 0 → แสดง **Gencode days \*** (บังคับ · จำนวนเต็ม ≥1) + Gencode start (optional · default = Post due ถ้ามี) |
| Asset fee (฿) | optional |
| Expediting fee (฿) | optional |
| **Total cost** | อ่านอย่างเดียว · = Rate card + Gencode + Asset + Expediting (+ Basket fee เดิมถ้า deal มีค่า แสดงบรรทัดเทา "Includes basket fee ฿x") · อัปเดตทันทีที่พิมพ์ |

- ช่องเงินทุกช่อง: ตัวเลข ≥0 · แสดงคั่นหลักพัน · ว่าง = 0 (ยกเว้น Rate card ที่ว่างไม่ได้)
- บรรทัดงบ (§4.7) ใช้ **Total cost** · Committed ของ Campaign = Total cost (นิยามเดิม CR-05)
- Package: Rate card ล็อกจาก package · Gencode / Asset / Expediting เป็นค่าใช้จ่ายเพิ่มนอก package → จ่ายผ่านแถวจ่ายของ deal เอง (เฉพาะยอดส่วนเพิ่ม) · การ์ด Payment แสดง "Package ฿2,000 + extras ฿500"

### 4.12 Brief link · Script link
- ปลายทาง **Brief** (หรือข้ามผ่าน Brief): ช่อง **Brief link** (optional · https) → `deals.brief_link`
- ปลายทาง **Script** (หรือข้ามผ่าน Script): ช่อง **Script link** (optional · https) → `deals.script_link` (ใหม่)
- prefill ค่าเดิม · แก้ได้ภายหลังในการ์ด Deal (Deal modal) · Journey ที่ขั้น Brief / Script แสดงไอคอน 🔗 คลิกเปิดแท็บใหม่
- URL ไม่ขึ้นต้น https → กรอบแดง "Use a link that starts with https://" (ไม่บล็อกถ้าเว้นว่าง)

### 4.13 Draft 1 / 2 / 3 — Note + Links + รูป
- ปลายทาง **Draft n**: ส่วน **"Draft n notes"** ใน dialog — Note (ข้อความหลายบรรทัด) · **Links** (เพิ่มได้หลายอัน · https) · **Images** (เลือกไฟล์ · ลากวาง · วางจาก clipboard Ctrl/⌘+V)
- รูป: สูงสุด 6 รูปต่อ Draft · ย่อด้านยาวไม่เกิน 1600px · WebP q0.8 · เก็บใน IndexedDB `step_images` (ไม่อยู่ใน localStorage / state) · ไฟล์ที่ไม่ใช่รูปปฏิเสธ
- คำเตือนใต้ช่องรูป (เทา): "Content screenshots only — no ID cards, bank details or personal documents" (กติกาเดียวกับรูปโปรไฟล์ CR-16)
- **แก้ภายหลัง:** Deal modal › Journey คลิกขั้น Draft n → แผงเล็ก "Draft 1 · 12/10/2026" แสดง Note · Links · thumbnail (คลิกดูรูปใหญ่ · ‹ › เลื่อนรูป) · `Edit` · ลบรูปได้ (ยืนยันก่อน)
- Journey แสดงตัวนับใต้ขั้น เช่น "📎 2 · 🖼 3" · ขั้นที่ไม่มีโน้ตไม่แสดง
- ถอยกลับจาก Draft n → โน้ตของ Draft นั้นยังอยู่ (ไม่ลบ)
- Export / Dashboard ไม่ส่งรูปออก (Export มีแค่จำนวน links / images ต่อ Draft)

### 4.14 Draft 1 / 2 / 3 → Post ได้เลย
- จาก Draft n ย้าย (เมนู หรือลากไป Posted lane) ไป **Post** ได้ใน dialog เดียว — ต้องกรอกรายละเอียดครบ:

| ส่วน | บังคับ |
|---|---|
| Costs / Payment term / Pillar | ครบตาม Confirm QT (§4.7 · §4.11) ถ้ายังขาด |
| Draft ที่อยู่ในแผนแต่ยังไม่ทำ (เช่น แผน 3 Drafts อยู่ Draft 1) | เลือกต่อขั้น: `Done on <date>` หรือ **`Not needed`** (default) → ลดจำนวน Drafts ใน Content plan ให้เท่าที่ทำจริง |
| **Approve** | วันที่ Approve (default = Post date · ไม่ก่อน Draft ล่าสุด) |
| **Post** | **Posted link** อย่างน้อย 1 (https · เพิ่มได้หลายโพสต์) · **Post date** (ไม่ก่อน Approve · ไม่เป็นวันในอนาคต) |
| Optional | Mark sample as delivered · Note ของ Draft ปัจจุบัน (§4.13) |

- กด Move แล้วไม่ครบ → กรอบแดง + กล่องสรุป (§4.7) · ครบ → บันทึกทุกขั้นในครั้งเดียว · Undo ย้อนทั้งหมด (รวม Content plan ที่ลดลง)
- ใช้ได้จากทุกขั้นก่อน Post (กติกา §4.9) — CR นี้เน้นจาก Draft เพราะเป็นกรณีใช้บ่อย

### 4.15 Expected date ของขั้นถัดไป — ถามตอน Move
หลักการ: ชื่อ stage = งานที่ทำเสร็จแล้ว (CR-15) → ตอน Move ให้บันทึก**วันที่คาดว่า KOL จะส่งงานขั้นถัดไป** · ใช้ฟิลด์เดิมของ CR-15 (ไม่เพิ่ม schema) · ส่วน **"Next expected"** อยู่ใต้ Date ใน Move stage dialog

| Move ไป | ช่อง Next expected | บังคับ | ฟิลด์ |
|---|---|---|---|
| Brief | **Expected Draft 1 date** + Expected script date (ถ้า KOL ต้องส่ง Script ก่อน) | Draft 1 ✓ · Script — | `expected_draft1_date` · `expected_script_date` |
| Script | **Expected Draft 1 date** | ✓ | `expected_draft1_date` |
| Draft 1 | แผนมี Draft 2 → **Expected Draft 2 date** · แผนจบที่ Draft 1 → **Expected approve date** + ลิงก์ `+ Add Draft 2 round` | — | `expected_draft2_date` / `expected_approve_date` |
| Draft 2 | แผนมี Draft 3 → **Expected Draft 3 date** · ไม่มี → Expected approve date + `+ Add Draft 3 round` | — | `expected_draft3_date` / `expected_approve_date` |
| Draft 3 | Expected approve date | — | `expected_approve_date` |
| Approve | Post due | — | `expected_post_date` |

- `+ Add Draft k round` = เพิ่ม Draft ใน Content plan (สูงสุด 3) แล้วเปลี่ยนช่องเป็น Expected Draft k date · กลับได้ด้วย `Remove` · บันทึกพร้อม Move (Undo ย้อนแผนด้วย)
- prefill ค่าเดิมของ deal · ปุ่มลัดข้างช่อง `+3d` `+5d` `+7d` (นับจาก Date ที่ Move)
- ตรวจ: วันที่คาด**ก่อน Date ที่ Move ไม่ได้** (แดง · บล็อก) · หลัง Post due → เตือนส้ม "After the post due (20/10)" (ไม่บล็อก)
- ข้ามหลายขั้น (§4.9): ถามเฉพาะ Next expected ของ**ปลายทาง** (ขั้นที่ข้ามไม่ต้องมีวันคาด) · ปลายทาง Post ไม่มีส่วนนี้
- ลาก 1 ขั้นที่ข้อมูลครบแต่ Expected Draft 1 ว่าง (ไป Brief / Script) → เปิด dialog (ตามกติกา §4.9) · Draft 2 / 3 / approve ว่างได้ → ย้ายทันที
- ผลต่อหน้าอื่น: `rules.dueDate` (CR-15 §4.3) ใช้ค่าที่กรอก → การ์ด Pipeline แสดง Due · Overdue · Due in next 7 days · Shipments `ship_by` (อิง Expected Draft 1) อัปเดตตาม
- ถอยหลัง: ไม่ถาม Next expected · ค่าเดิมไม่ลบ

1. **TC-06 vs §4.10:** spec TC-06 บอก "ไม่กรอก = ปุ่ม Add กดไม่ได้" แต่ §4.10 / TC-30 / §9 #14 บอก "ปุ่ม Add กดได้ → เลื่อนไปแถวแรกที่ขาด + กรอบแดง" — ใช้แบบ §4.10 (ปุ่มกดได้เสมอ ไม่สร้างจนครบ)
2. **lookups.payment_terms ไม่มีในข้อมูล** (payment term อยู่ใน code `R.PAYMENT_TERMS`) → เพิ่ม `package` ที่ `R.PAYMENT_TERMS` · Default payment term ของ KOL / Set details ไม่มี Package (`R.BASIC_TERMS`)
3. **Free:** Rate card ไม่บังคับ (ว่าง = ฿0) — Free = ไม่มีค่าจ้าง
4. **ค่าใช้จ่ายเพิ่มของ deal Package** ถึงกำหนดตอน Confirm QT (แบบ prepaid) — milestone ชื่อ Extras
5. **Prepaid package balance** = package ที่จ่ายแล้วและไม่ Archived × ครั้งที่ยังไม่ใช้ (Expired นับรวม)
6. **Deal เลย Confirm QT ที่ข้อมูลขาด** (รวม deal นำเข้า · Gencode มีค่าแต่ไม่มีวัน) → ขยับไปข้างหน้าต้องกรอกครบ (ลากจะเปิด dialog · Move to… หลาย deal จะ Blocked พร้อมเหตุผล)
7. **ลากไปขั้น optional ถัดไป** (Shortlist → Contacted) ย้ายทันทีเมื่อไม่มีช่องบังคับ · warning (เช่นวันที่คาดหลัง Post due ที่ deal มีอยู่แล้ว) ไม่ทำให้ต้องเปิด dialog
8. **Expected date ก่อนวัน Move** ตรวจเฉพาะค่าที่กรอกหรือแก้ใน dialog (ค่าเก่าของ deal ที่แสดงไว้เฉยๆ เช่น Post due เดือนก่อน ไม่บล็อก)
9. **Script ไม่มีวันคาดของตัวเอง** → Due ของการ์ด = Expected Draft 1 (TC-41 "การ์ดแสดง Due 15/10") — เฉพาะ deal ที่สร้างในแอป · deal นำเข้า (มี legacy_job_ids) ยังใช้กติกา CR-15 "Script ไม่มี due = ไม่มี due" เพื่อไม่ให้ Draft 1 due เก่าของ 6 deal ที่ Brief กลายเป็น Overdue (Overdue ของ seed คง 5)
10. **New KOL + Package:** สร้าง package ใหม่ให้ KOL ใหม่ในฟอร์มเดียว (Posts · Total price · Uses) · Default payment term ของ KOL ใหม่ = term ของ deal (ถ้าไม่ใช่ Package)
11. **Rate prefill** = Rate card ของ deal → ถ้าว่าง Latest rate ของ KOL (ทำให้ TC-18 ช่อง Rate ไม่แดงถ้า KOL มี quote — ใน check ล้างช่องก่อน)
12. **Rate quote** ตอนข้าม Confirm QT (ไม่ใช่แค่ปลายทาง Confirm QT) · ไม่บันทึก quote ของ deal Package
13. **Draft notes ตอนข้ามไป Post** ไม่มีส่วน Note ของ Draft ปัจจุบันใน dialog (แก้ได้จาก Journey) · Mark sample as delivered มีเมื่อ deal มี shipment ที่ยังไม่ Delivered
14. `node build.mjs` ไม่มีในโปรเจกต์นี้ (เปิด index.html ตรง ตามที่ตกลงไว้ตั้งแต่ CR-01)
