# CR-33 — Payee · Documents · Payment rounds · Accounting · Print · Actual spend

ใช้กติกาถาวรใน CLAUDE.md · ข้อมูลส่วนตัว / บัญชี / ไฟล์เอกสาร เก็บใน vault (เข้ารหัส CR-16) เท่านั้น · ห้ามใช้ข้อมูลจริงใน test / seed
ลำดับทำงานที่แนะนำ: §3.1–3.3 (Payee / เอกสาร) → migration v24 → §3.4–3.8 (Payments) → §3.9 (Dashboard)

## 1. หลักการ
- บัญชีจ่ายเงิน **นอกระบบ** · ระบบไม่ถือว่า "Paid" เป็นตัวเลขหลัก
- **Dashboard** ดูต้นทุนจากงาน: Committed (ตกลงราคา) · **Actual** (โพสต์แล้ว · ตาม Post date)
- **Payments** ดูว่า Staff **วางบิลให้บัญชีครบหรือยัง** · หน่วยงานคือ **รอบ PR**
- **Accounting** เข้ามาตรวจเอกสาร (Verify / Return) · Print / Export · ยืนยันจ่ายระดับรอบ (ไม่บังคับ) · โครงข้อมูลพร้อมเชื่อมระบบเปิดเอกสารจ่ายภายหลัง

## 2. เดิม → ใหม่
- Payee details: บังคับแค่บางช่อง · ข้อมูลบัญชีกับข้อมูลส่วนตัวปนกัน → ช่องบังคับ + ส่วน **Personal data** (§3.1)
- เอกสารเก็บเป็นวันที่ · ซ้ำ 2 ที่ (Payee + Payment line) → **ไฟล์ (เข้ารหัส) หรือลิงก์** · ID / Bank book อยู่ที่ Payee · Post proof อยู่ที่รอบจ่าย (§3.2)
- Payments › Pay to: ฟอร์มย่อ · เลือก payee ให้เอง → ฟอร์มเดียวกับ KOL Master · ต้องเลือก / ยืนยันเอง (§3.3)
- tabs To pay · Sent · Paid · ส่ง / Mark paid ทีละแถว → **To submit · Submitted · Paid (confirmed)** · วางบิลเป็น **รอบ PR** · ยืนยันจ่ายทีละรอบ (§3.4–3.6)
- ไม่มีคนฝั่งบัญชี → **role Accounting** ตรวจเอกสาร (§3.7)
- "Print (สำหรับดรีม)" เป็น checkbox ใน Excel → **Print PDF รวมเอกสาร** (§3.8)
- KPI "Paid" + Portfolio คอลัมน์ Paid → **Actual (posted)** (§3.9)
- แถบบน Payments: Due now · Sent, not yet paid · Paid this month · Prepaid package balance → **To submit · Submitted, not confirmed · Confirmed this month · Prepaid package balance**

## 3. Spec

### 3.1 Payee details (KOL Master › Payee & shipping · และใช้ที่ Payments)
ฟอร์มเดียว component เดียว `payeeForm` · 3 ส่วน

| ส่วน | ช่อง | บังคับ |
|---|---|---|
| **Tax & terms** | Payee type (Individual / Company) | ✓ |
| | Default WHT rate | ✓ |
| | Price basis (Gross / Net) | ✓ |
| | VAT registered | — |
| **Bank details** 🔒 | Account holder name | ✓ |
| | Bank (dropdown จาก `lookups.banks` · ไม่ใช่พิมพ์เอง) | ✓ |
| | Account number (ตัวเลข / ขีด · 10–15 หลัก) | ✓ |
| **Personal data** 🔒 (ส่วนใหม่ แยกกรอบ) | Full name (as on ID) · Company: ชื่อนิติบุคคล | ✓ |
| | ID-card address · Company: ที่อยู่จดทะเบียน | ✓ |
| | Phone · Email / address for WHT certificate | — |
| | Tax ID | Company ✓ · Individual — (เก็บใน vault · แสดง ••• 4 ตัวท้าย) |

- ปุ่ม Save กดได้เสมอ · กดแล้วช่องที่ขาดแดง + กล่องสรุป (แบบเดิม)
- payee เดิมที่ขาดช่องบังคับ: การ์ด payee แสดง "Incomplete · 2 missing" + ปุ่ม Complete · ใช้จ่ายได้แต่ Payment ขึ้น Missing (CR-32 §2.5)
- ข้อความ vault ใน Payments: "Locked — unlock the payee vault to add a shipping address or a bank account" → **"Locked — unlock the vault to add payee details"**

### 3.2 Documents เป็นไฟล์หรือลิงก์
**ระดับ Payee (ใช้ซ้ำทุกรอบ):** ID copy · Bank book · Company certificate (Company) · VAT certificate ภ.พ.20 (VAT registered)
**ระดับ Payment line (ต่อรอบจ่าย):** Post proof (+ Posted on) · เอกสารอื่น (`+ Add document`)

แต่ละรายการ: `[Upload file]` **หรือ** `[Link]` (เลือกอย่างใดอย่างหนึ่ง)
- **Upload:** PDF / JPG / PNG / WEBP · ≤ 5 MB ต่อไฟล์ · รูปย่อด้านยาว ≤ 2000px · **เข้ารหัสด้วย vault แล้วเก็บใน IndexedDB** (ไม่อยู่ใน localStorage / state / log) · แสดงเป็นชื่อไฟล์ + 👁 Preview (ต้องปลด vault) · Replace · Remove
- **Link:** https เท่านั้น · แสดงเป็น "Google Drive ↗"
- Received date บันทึกอัตโนมัติ = วันที่อัปโหลด / ใส่ลิงก์ (แก้ได้ · ไม่ใช่ช่องหลักอีกต่อไป)
- Docs folder (ลิงก์โฟลเดอร์รวม) คงไว้เป็นช่อง optional
- Payment details › Documents: แสดงเอกสารระดับ Payee เป็น ✓ "From payee" (อ่านอย่างเดียว · ลิงก์ไปแก้) + Post proof · **All documents in one file** (CR-32) ยังใช้ได้ (ไฟล์หรือลิงก์)
- Backup: ไฟล์เอกสาร **ไม่รวม** โดย default · ติ๊ก "Include payee documents (encrypted)" ได้ · ขนาดแสดงใน Settings › Data
- คำเตือนเดิม "Content screenshots only…" ไม่ใช้กับส่วนนี้ (ส่วนนี้ตั้งใจเก็บเอกสารส่วนตัว — จึงต้องเข้ารหัส)

### 3.3 Payments › Pay to
- ยังไม่มี payee → ปุ่ม `Add payee` เปิด **payeeForm เดียวกับ KOL Master** (modal ซ้อน) · บันทึกแล้วผูกกับแถวจ่าย
- มี payee แล้ว:
  - **1 รายการ** → แสดง payee นั้น + ปุ่ม `Confirm payee` (ต้องกดยืนยันครั้งแรกของแต่ละแถว)
  - **มากกว่า 1** → dropdown **ว่าง** "Choose payee" (ห้ามเลือกให้ · แม้มี Default) · แสดง label "Primary · KBank ••• 7489 · Individual"
  - มีปุ่ม `+ Add new payee` เสมอ
- แถวที่ยังไม่ยืนยัน payee = Missing "Payee not confirmed"
- Create round: แถวที่ยังไม่ยืนยัน payee ถูกข้าม + แจ้งจำนวน

### 3.4 Tab To submit (Staff)
- แถวที่ **ถึงเวลาวางบิล** ตาม term: Pay after post = โพสต์แล้ว · Prepaid = ถึง Confirm QT · 50/50 = แต่ละงวดถึงเงื่อนไข · Package = package
- กลุ่มตามช่วงยอด (PR bands) · chip Ready / Missing n (CR-32 §2.5)
- การ์ดบน: **Posted but not submitted** (ยอด + จำนวน · แดงถ้าค้าง > 7 วันหลังโพสต์) · Missing details · Not due yet · On hold
- เลือกหลายแถว → **`Create round`** (เฉพาะแถว Ready · แถวไม่ Ready ข้ามพร้อมแจ้ง)
- Mark paid รายแถว: ซ่อนใน ⋯ (กรณีจ่ายด่วนนอกรอบ · ต้องใส่เหตุผล)

### 3.5 Create round
- dialog: ชื่อรอบ auto `PR-2026-10-09` (แก้ได้ · เช่น "(รอบดรีม) PR-2026-10-09") · วันจ่ายที่คาด · แถวที่เลือก (แยกตามช่วงยอด) · ยอดรวม Gross / WHT / Net
- กด Create → รอบสถานะ **Submitted** · แถวย้ายไป tab Submitted
- ปุ่มในรอบ: `Export for accounting` (ไฟล์ PR · CR-32 §2.5 · 1 sheet ต่อช่วงยอด) · `Print` (PDF รวม · §3.8) · `Add lines` · `Remove line` (กลับไป To submit)

### 3.6 Tab Submitted / Paid (confirmed)
- **Submitted**: จัดกลุ่มตาม **รอบ** (หัวรอบ: ชื่อ · วันส่ง · ผู้ส่ง · จำนวนแถว · Net · Verified n/m · อายุรอบ "7 d" เหลืองเมื่อ > 7 วัน) · กางดูแถว
  - ปุ่มระดับรอบ: `Confirm paid` (วันที่จ่าย · Ref · ทั้งรอบ) · ยกเว้นบางแถวได้ ("Not paid in this round" → กลับ To submit)
- **Paid (confirmed)**: รอบที่ยืนยันแล้ว · แก้เอกสารได้ (เช่น 50 ทวิ) · `Undo confirm` (เหตุผล)
- ไม่บังคับต้องยืนยัน · รอบที่ไม่ยืนยันยังนับใน "Submitted for payment"

### 3.7 Role Accounting
- tab ชื่อ **Submitted by staff** (Staff เห็น "Sent to accounting") · เห็นรอบเดียวกัน
- ต่อแถว: **`Verify`** (เอกสารถูกต้อง → ✓ Verified · ชื่อ / วันที่) · **`Return`** (เหตุผลบังคับ → แถวออกจากรอบ กลับไป To submit ของผู้ส่ง + chip Returned)
- ระดับรอบ: `Print` · `Export` · `Confirm paid`
- Accounting ไม่แก้ยอด / deal (อ่าน + verify / return เท่านั้น)
- เตรียมเชื่อมระบบในอนาคต: แต่ละรอบ / แถวมี `external_ref` (null) · `voucher_status` (null) · ปุ่ม "Open payment voucher" ยังไม่ทำ (นอกขอบเขต) · Export มีคอลัมน์ Round ID · Line ID ให้ระบบอื่นอ้างอิง

### 3.8 Print เอกสารรวม (PDF)
- ปุ่ม **Print** ที่หัวรอบ (ทั้งรอบ) · ต่อแถวใน Submitted · ใน Payment details
- กด Print → ต้องปลด vault → สร้าง **PDF 1 ไฟล์ต่อแถว** (bulk = 1 ไฟล์รวมทุกแถว คั่นหน้าใหม่ต่อแถว) ดาวน์โหลดเลย ไม่เก็บในแอป
- ลำดับหน้าใน PDF:
  1. **Payment summary** — Project (สินค้า) · Account · Type · Full name · ID-card address · Bank · Account number · Gross · VAT · WHT · Net · PIC · PR round · Deal ID · Post link + Posted on
  2. **หลักฐานบัญชี / ตัวตน** — ID copy → Bank book → (Company certificate · VAT certificate)
  3. **หลักฐานการทำงาน** — Post proof → เอกสารอื่น
- ไฟล์ที่อัปโหลด: ใส่ในหน้า PDF ตามลำดับ (รูป = 1 หน้า พอดีขนาด A4 · PDF = ต่อหน้าเดิม)
- เอกสารที่เป็น **ลิงก์**: ดึงเข้า PDF ไม่ได้ (Google Drive ต้อง login) → หน้าสรุปแสดงรายการ "Linked — not included" พร้อมลิงก์คลิกได้ + แถบเตือนก่อนดาวน์โหลด "2 documents are links — open and print them separately"
- All documents in one file (ไฟล์) → แทรกทั้งไฟล์ต่อจากหน้าสรุป
- บันทึก `printed_at` / `printed_by` · คอลัมน์ Print แสดง "Printed 09/10 · Dream" (แทน checkbox "Print (สำหรับดรีม)")
- สร้าง PDF ในเบราว์เซอร์ด้วย **pdf-lib** (MIT) ฝังใน build (ไม่โหลดจาก CDN · ใช้ offline / file:// ได้) · ฟอนต์ไทยฝัง (Sarabun / Noto Sans Thai · OFL) เฉพาะ subset
- log: "printed PR-… · n lines" (ไม่เก็บเนื้อหา)

### 3.9 Dashboard (นิยามเงินใหม่ · แก้ CR-05)
| ตัวเลข | นิยาม |
|---|---|
| Committed | เดิม (Confirm QT ขึ้นไป · ไม่ Cancel) |
| **Actual (posted)** | Σ Total cost ของ committed deal ที่ **Post date แรก** อยู่ในช่วงตัวกรอง (≤ วันนี้) |
| Not yet posted | Committed − Actual |
| Submitted for payment | Σ ยอดของแถวจ่ายที่อยู่ในรอบสถานะ Submitted / Paid |
| Paid (confirmed) | Σ ยอดในรอบที่ยืนยันจ่ายแล้ว (แสดงเฉพาะ tooltip / Payments) |

- การ์ด KPI ใบที่ 3 (CR-29): ชื่อ **Actual (posted)** · ค่าหลัก ฿ · bar = % of committed · caption "฿x submitted for payment · ฿y not submitted" 
- Campaign portfolio คอลัมน์ "Paid" → **Actual** · Budget vs Actual (CR-26) ใช้นิยามนี้อยู่แล้ว (ไม่เปลี่ยน)
- Prepaid / Package: Actual ยังนับตาม Post date (ไม่ใช่วันจ่าย)

## 4. Data — schema 24
- `payee_profiles` + `price_basis` · `full_name_enc` · `id_address_enc` · `phone_enc` · `wht_contact_enc` · `tax_id_enc` (เข้ารหัส) · `docs` [{ `key`, `kind: file|link`, `file_id?`, `url?`, `received_at` }]
- IndexedDB store ใหม่ `doc_files` (encrypted blob · `file_id` · `owner` payee / payment · `mime` · `bytes` · `name`)
- store ใหม่ `payment_rounds`: `round_id` (PR-yyyy-mm-dd[-n]) · `name` · `status` (`submitted | paid`) · `submitted_by` · `submitted_at` · `expected_pay_date` · `paid_at` · `paid_ref` · `confirmed_by` · `external_ref` · `voucher_status`
- `payment_lines` + `round_id` · `payee_confirmed_at` · `verified_at` · `verified_by` · `returned_reason` · `printed_at` · `printed_by` · docs ระดับ payment = Post proof / อื่นๆ
- roles + `accounting`
- **Migration v24 (ครั้งเดียว):**
  - payee docs ที่เป็นวันที่ → `kind: link` ว่าง + `received_at` = วันที่เดิม ("Received dd/mm · file not attached") · ID copy / Bank book ระดับ payment (CR-32) ย้ายขึ้นไประดับ payee
  - แถวจ่ายที่ผูก payee อยู่แล้ว → `payee_confirmed_at` = วันที่ migrate
  - แถว Sent → รวมเป็นรอบตามวันที่ส่ง (`PR-<sent date>`) สถานะ submitted · แถว Paid → รอบตามวันที่จ่าย สถานะ paid
  - Committed เดิม · Paid เดิมคงเป็น "Paid (confirmed)"

### การตัดสินใจ (ตาม §6 หรือที่ spec ไม่ระบุ)
1. **PDF ไม่ได้ใช้ pdf-lib + ฟอนต์ Sarabun ฝัง** (§3.8 ขอไว้) — กติกาถาวร "ไม่ใช้ npm / CDN" และ "ดาวน์โหลดไฟล์ต้องขออนุญาตก่อน" จึงเขียนตัวสร้าง / อ่าน PDF เอง (`src/pdf.js` · ไม่มี dependency · ใช้ offline / file:// ได้) · หน้าสรุปวาดด้วยเบราว์เซอร์ (ฟอนต์ไทยในเครื่อง: Sarabun / Noto Sans Thai / Leelawadee UI / Tahoma) เป็นภาพ — สระ / วรรณยุกต์ถูกต้อง · ลิงก์ยังคลิกได้ (annotation) · ข้อจำกัด: ข้อความในหน้าสรุปเลือก / ค้นหาไม่ได้ · ถ้าต้องการ pdf-lib + Sarabun subset ให้อนุญาตดาวน์โหลด แล้วเปลี่ยนเฉพาะ `screen-print.js`
