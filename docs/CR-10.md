- Deals › View tabs: `Table · Pipeline · **Performance**` (จำค่าล่าสุดตามกติกาเดิม)
- Scope bar เหมือน Table: `Campaign` (single) · `Phase` · `PIC` · Search (KOL / @handle / deal ID / post link) · `Filters` · Clear all filters (CR-07 §4.4)

### 4.3 สูตร — `rules.postMetrics(posts, deals)` (ฟังก์ชันกลาง)

> **หมายเหตุ (CR-11, 06/10/2026):** สถานะ metrics **Updated / Stale (14 วัน) ถูกแทนด้วยรอบ D+7** — `rules.metricsStatus(post, today, checkpoints, goLive)`: Due · Waiting · Collected · Not posted · Not tracked · Imported (`lookups.metrics_checkpoints` = [7] · `metrics_stale_days` ไม่ใช้แล้ว) · ลิงก์โพสต์ที่ซ้ำกันนับใน Views / ER ครั้งเดียว · ดู `docs/CR-11.md` §4.12 / §4.13 #7
- **Posted** = นิยาม §4.1
- **With metrics** = โพสต์ที่ `views` ไม่เป็น null
- **Engagement** = likes + comments + shares + saves (null = 0 ในการรวม)
- **ER** = Σ engagement ÷ Σ views ของโพสต์ที่ views > 0
- **Cost (ต่อโพสต์)** = `postShare(deal, post)` = total cost ของ deal ÷ จำนวนโพสต์ของ deal (CR-03)
- **CPV** = Σ cost ของโพสต์ที่ views > 0 ÷ Σ views ของโพสต์เดียวกัน
- **CPE** = Σ cost ÷ Σ engagement ของโพสต์ที่ engagement > 0
- **Metrics status** — `rules.metricsStatus(post, today, staleDays)`:

| Status | เงื่อนไข |
|---|---|
| No metrics | views = null |
| Imported | มี metrics · `metrics_source = 'legacy'` |
| Updated | `metrics_updated_at` ภายใน staleDays วัน |
| Stale | `metrics_updated_at` เก่ากว่า staleDays วัน |

- Dashboard › By campaign › Engagement (CR-07) และ "Metrics on n of m posts" ต้องเรียกฟังก์ชันนี้

### 4.4 Group by

### 4.5 แก้ metrics แบบ inline
- สิทธิ์: Admin · KOL Manager · Staff (deal ที่ตัวเองเป็น PIC) · Viewer / Accounting อ่านอย่างเดียว
- คลิก cell Views / Likes / Comments / Shares / Saves → input ตัวเลข · **Enter** = บันทึกแล้วลงแถวถัดไป (คอลัมน์เดิม) · **Tab** = บันทึกแล้วไปคอลัมน์ขวา · **Esc** = ยกเลิก
- `rules.parseCount(text)` รับ: `1300000` · `1,300,000` · `1.3M` · `33.4K` · `1.2k` · ช่องว่าง = null (ลบค่า) · ติดลบ / ข้อความอื่น = Error "Enter a whole number, e.g. 12,500 or 12.5K"
- บันทึก: `metrics_updated_at = today` · `metrics_updated_by = user` · `metrics_source = 'manual'` · `deal_events` type `metrics` (from → to)
- Validation (Warning · บันทึกได้):
  - likes / comments / shares / saves > views → "Engagement is higher than views — check the numbers"

- Deal drawer › Posts ใช้ parseCount + validation ชุดเดียวกัน

### 4.6 Paste metrics (อัปเดตหลายโพสต์ทีเดียว)
- ปุ่ม `Paste metrics` (สิทธิ์เดียวกับ §4.5) → dialog กว้าง

- **Preview** ก่อนบันทึก: ตาราง KOL · Platform · ค่าเดิม → ค่าใหม่ (ช่องที่เปลี่ยนตัวหนา) · สรุป `Matched n · Not found n · No change n · Errors n` · แถว Not found / Errors แสดงพร้อมเหตุผล
- Staff: แถวที่ไม่ใช่ deal ของตัวเองแสดงเป็น "Not your deal" และไม่บันทึก

> **หมายเหตุ (CR-11, 06/10/2026):** drawer 60% ใช้กับ **ดู / แก้ของที่มีอยู่แล้ว** เท่านั้น · การสร้างใหม่ทุกอย่างใช้ create modal (S / M / L) · Phase Planner ไม่ใช่ drawer แล้ว (modal L) — ดู `docs/CR-11.md` §4.1 และ `docs/UI_PATTERNS.md`
**ปัญหาจาก screenshot:** Deal drawer แคบ (~1/3 ของจอ) → Journey ที่มี 3 drafts ถูกเปลี่ยนเป็นแนวตั้งยาว ต้องเลื่อนมาก

**กติกาเดียวทุก drawer** (Deal · KOL · Campaign · Phase Planner · Payee dialog · Stage popup ไม่นับเพราะเป็น modal)
- default `clamp(720px, 60% ของ viewport, 1200px)` · Phase Planner ขั้นต่ำ 880px
- พื้นที่เนื้อหาที่เหลือ < 320px → drawer เต็มพื้นที่เนื้อหา · มือถือเต็มจอ
- resize ลากขอบซ้าย + จำค่าแยกตามชนิด drawer (`ui.drawerWidth.deal` / `.kol` / `.campaign` / `.planner`) · double-click ขอบ = 60%
- ภายใน ≥ 720px ใช้ layout 2 คอลัมน์ (CR-07 §4.7 · CR-09 §4.12) · ส่วน Journey / Samples / History เต็มความกว้าง
- ตัวอย่าง: 1920 → 1152 · 1440 → 864 · 1280 (menu ขยาย) → 768 · 1024 (rail) → เต็มพื้นที่
- ไม่เปลี่ยนความกว้างของ **side menu ซ้าย** (navigation) — กติกานี้คือ panel รายละเอียดที่เปิดจากขวา

**Journey layout** (CR-07 §4.9)
- แนวนอนเมื่อความกว้าง section ≥ จำนวนขั้น × 64px (ระยะต่อขั้นยืดเต็มความกว้าง) · drawer 60% จึงเป็นแนวนอนเสมอ แม้แผน Script + 3 drafts (สูงสุด 9 ขั้น)
- แนวตั้งเฉพาะเมื่อแคบกว่านั้น (มือถือ)
- ชื่อขั้นในแนวนอนขึ้น 2 บรรทัดได้ ไม่ตัด

### 4.14 Samples — ส่งสินค้าตัวอย่างให้ KOL รีวิว

> **หมายเหตุ (CR-11, 06/10/2026):** Deals › Samples ย้ายไปเป็นหน้า **Shipments** ใน side menu (`#shipments/to-ship · in-transit · delivered` · pick list · New shipment ที่ไม่ผูก deal · Staff ทุกคน Mark shipped ได้) · `#deals/samples` redirect ไป Shipments › To ship · drawer section ชื่อ "Shipments" · collection ยังชื่อ `sample_shipments` · ดู `docs/CR-11.md` §4.10
เป้าหมาย: รู้ว่า**ต้องส่งของให้ใคร เมื่อไร** ส่งแล้วหรือยัง ถึงมือหรือยัง — ก่อน KOL ต้องเริ่มทำ content

**Shipment เกิดเมื่อไร**
- **อัตโนมัติ:** deal ขยับถึง **Confirm QT** (ตกลงงานแล้ว) และยังไม่มี shipment ที่ไม่ใช่ Not required → สร้าง shipment `To ship` · items = Products ของ deal (CR-06 deal_products · ว่าง = chip "No products selected")
- **เอง:** `+ Add shipment` ใน Deal drawer › Samples ได้ทุกขั้น (เช่นส่งของก่อนตัดสินใจ / ส่งเพิ่ม / ส่งใหม่เพราะของเสีย)
- deal ที่ไม่ต้องส่งของ (KOL มีสินค้าแล้ว ฯลฯ) → `Mark as not required` + เหตุผล
- deal ถูก Cancel → shipment `To ship` เปลี่ยนเป็น Not required (reason "Deal cancelled") · ที่ส่งแล้วคงไว้

**Ship by** — `rules.shipBy(deal, settings)` (วันที่ควรส่งออกช้าสุด)
- = (`expected_draft1_date` ถ้ามี · ไม่งั้น `expected_post_date`) − `lead_days` (default 7)
- ไม่มีทั้ง 2 วัน → ship_by ว่าง + chip "Set ship-by date"
- แก้เองได้ (`ship_by_overridden = true` → ไม่คำนวณใหม่เมื่อวันที่ของ deal เปลี่ยน · มีปุ่ม Reset to auto)
- วันที่ของ deal เปลี่ยน และไม่ได้ override → ship_by คำนวณใหม่

**สถานะ** — `rules.sampleStatus(shipment, today)`

| Status | เงื่อนไข | สี |
|---|---|---|
| To ship | ยังไม่ส่ง · ship_by ≥ today + 8 วัน หรือว่าง | เทา |
| Ship this week | ยังไม่ส่ง · ship_by ภายใน 7 วัน | เหลือง |
| Overdue | ยังไม่ส่ง · ship_by < today | แดง |
| Shipped | มี shipped_date ยังไม่ delivered | น้ำเงิน |
| Delivered | มี delivered_date | เขียว |
| Problem | ตีกลับ / หาย / เสีย (มีเหตุผล) | แดงจาง |
| Not required | ไม่ต้องส่ง | เทาขอบ |

- รายการ shipment: Items (tr_code × qty) · Ship by · Status chip · Carrier · Tracking (ลิงก์ถ้ามี template) · Shipped · Delivered · ⋯ (Edit · Mark shipped · Mark delivered · Report problem · Mark as not required · Delete ได้เฉพาะ manual ที่ยัง To ship)

**Deals › tab `Samples`** (View tabs: `Table · Pipeline · Samples · Performance`)
