### 4.2 Pillar mix (ใหม่) — เงินลงไปที่ Pillar ไหน
- **Skeleton เหมือน KOL tier mix ทุกอย่าง** (หัว card · ปุ่ม table / download / expand · toggle `Spend · Deals` default Spend · donut + ยอดรวมกลาง · legend เป็นตารางเล็ก) เพื่อให้ 2 card อ่านแบบเดียวกัน
- Scope = เดียวกับ KPI (Campaign ที่ทับช่วงวันที่ · ไม่นับ Cancel) · นับเฉพาะ deal ขั้น Confirm QT ขึ้นไป (= Committed) · `rules.pillarMix(deals, scope)`
- ลำดับ slice: Awareness → Consideration → Conversion → **Not set** (สุดท้ายเสมอ) · สีตาม CR-03 §4.7 (`#2a78d6` · `#e87ba4` · `#eda100` · Not set `#B4B2A9` + texture / dark `#3987e5` · `#d55181` · `#c98500` · `#5F5E5A` + texture) · ช่องว่าง 2px ระหว่าง slice
- **Legend table:** Pillar · Spend (หรือ Deals) · % of total · **Target** · **Δ** 
  - Target ของ portfolio = ค่าเฉลี่ยถ่วงด้วย Budget ของ `pillar_target` ของแต่ละ Campaign ใน scope (null = ค่า default จาก Settings 10 / 20 / 70)
  - % ที่ใช้เทียบ target และ Δ = สัดส่วน**ในกลุ่มที่ตั้ง Pillar แล้ว** (สูตรเดียวกับ Allocation vs target ใน By campaign — เรียกฟังก์ชันเดียวกัน) · Δ ใช้ formatter pp เดิม (สีตามทิศ: เกิน target ไม่ใช่ "ดี/แย่" → ใช้หมึกรอง ไม่ใช้เขียว/แดง)
  - แถว Not set: แสดง ฿ และ % of total · Target / Δ = "—"
- **Not set > 50% ของ spend** → บรรทัดใต้ donut: "87.8% of spend has no pillar · `Set default pillar per phase`" (ลิงก์ไป Campaign & Phase › Plan phases ตาม CR-11 §4.11) — ให้รู้ว่ากราฟนี้ยังเชื่อไม่ได้และแก้ที่ไหน
- Tooltip ต่อ slice: Pillar · ฿ · n deals · % of total · (ถ้ามี) % of set + Target

### 4.3 สี Phase ชุดเดียว — `ui.phaseColor()`
**ปัญหา:** สี Phase เดิม (CR-03) Phase 1 = น้ำเงิน · Phase 2 = ส้ม ซ้ำกับ Macro / Micro (และ Awareness) → ถ้า band ใช้สีนี้ ผู้ใช้จะอ่านว่าแถบน้ำเงิน = Macro · CR-09 จึงทำ band เป็นเทาเดียว ซึ่งทำให้ไม่ตรงกับจุดสีใน Phase budget

**แก้:** Phase เป็นของที่มีลำดับเวลา → ใช้ **ordinal ramp สีเทา (hue เดียว)** ไล่ความเข้มตามลำดับ Phase · ไม่ชนกับสีข้อมูล (Tier / Pillar / Campaign) · ตัวระบุ Phase จริงคือ**ชื่อ**ที่อยู่บน band / ข้างจุดเสมอ

| Step | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Light | `#a3a19a` | `#8a8881` | `#72716b` | `#5b5a55` | `#4a4945` | `#3a3936` |
| Dark | `#5f5e58` | `#75736d` | `#8b8982` | `#a2a098` | `#bbb9b1` | `#d6d4cc` |

- Phase ลำดับแรก (start_date เร็วสุดใน Campaign) = อ่อนสุดเทียบพื้น · Phase หลัง = เด่นขึ้น
- จำนวน Phase n → เลือก step = `round(linspace(1, 6, n))`: n = 1 → [4] · 2 → [1, 6] · 3 → [1, 4, 6] · 4 → [1, 3, 4, 6] · 5 → [1, 2, 4, 5, 6] · 6 → ทั้งหมด · n > 6 → ใช้ 6 step แรก และ Phase ที่ 7+ ใช้ step 6 (ชื่อเป็นตัวแยก)
- สีผูกกับ Phase ใน Campaign (ไม่เปลี่ยนเมื่อ filter Phase)
- Validator: `--ordinal` ผ่านทั้ง light (surface `#fcfcfb` · light end 2.52:1) และ dark (surface `#1a1a19` · 2.68:1) ทั้งชุด 4 และ 6 step

**ใช้ที่** (จุดเดียวกันต้องได้สีเดียวกัน)

| จุด | การใช้ |
|---|---|
| By campaign › Activity by date › **Phase band** | แต่ละช่วงเป็นสี Phase นั้น · สูง 6px · เว้น 2px ระหว่างช่วง · ช่วงทับกันเป็นลายทแยง (CR-03) · ชื่อ Phase เหนือ band ใช้**หมึกรอง** (ไม่ใช่สี Phase) + จุดสี 8px หน้าชื่อ · เส้นประแนวตั้งเดิม |
| By campaign › **Phase budget** | จุดหน้าชื่อ Phase |
| By campaign › Allocation vs target | จุดหน้าชื่อแถว Phase |
| Phase Planner (CR-11 modal) | Budget bar · Timeline preview · จุดในตาราง Phase |
| Campaign & Phase › Table | จุดหน้าแถว Phase |
| Campaign & Phase › Timeline | **ไม่เปลี่ยน** — แท่ง Timeline ใช้สีสถานะ (Complete / On going / Planned) ตามเดิม |
| All campaigns › Activity by campaign | **ไม่เปลี่ยน** — สีต่อ Campaign ตาม categorical เดิม |

### 4.4 Deals — State tabs ตรงกับ Pipeline
| Tab | เนื้อหา | สีจุด / เส้นใต้ tab (= กลุ่มใน Pipeline CR-09 §4.10) |
|---|---|---|
| **All** (ซ้ายสุด · default) | ทุก deal ใน scope | — |
| **List** | Shortlist · Contacted · Confirm QT | เทา |
| **In process** | Brief · Approve Script · Approve Draft 1–3 | น้ำเงิน |
| **Complete** | Post | เขียว |
| **Cancelled** | Cancel | แดง |

- ตัวเลขบน tab นับตาม Scope (Campaign · Phase · PIC · Filters · Search) · tab ที่เป็น 0 ยังแสดง (เทาจาง) เพื่อให้ตำแหน่งไม่ขยับ
- Group by = Stage + tab List / In process → เห็นเฉพาะขั้นของกลุ่มนั้น · tab All → ทุกขั้นตามลำดับ Pipeline (Cancelled ท้ายสุด)
- จำ tab ล่าสุดต่อ user (key ใหม่ `deals.stateTab.v2` · ค่าเดิม `open` / `needs_action` → ไม่ใช้ เริ่มที่ All)
- Pipeline ไม่มี state tabs (CR-09 เดิม) · Performance ไม่เกี่ยว
- route / deep link เดิมที่ชี้ `?tab=open` → เปิด tab All + chip ไม่มี · `?tab=needs_action` → tab All + chip Overdue

### 4.5 Attention chips (แทน tab Needs action)
**ปัญหา:** Needs action 65 ของ Charming Iconic Glow = Overdue 3 + Unpaid after posting 62 → เกือบทั้งหมดเป็น deal ที่โพสต์จบแล้ว (Complete) เพราะ "ยังไม่จ่าย" ถูกนับเป็นงานของ deal · หลัง CR-11 การจ่ายเงินเป็นงานของ Payments (งวดขึ้น To pay เอง · PIC แค่เติมเอกสาร) จึงไม่ใช่ "ต้องทำอะไรกับ deal"

- แถว chip ใต้ tabs (แสดงเฉพาะ chip ที่ > 0 · นับภายใน tab ที่เลือก · คลิก = filter เพิ่ม · คลิกซ้ำ = เอาออก · นับใน Clear all filters ตาม CR-07):

| Chip | นิยาม | ปกติอยู่ใน tab |
|---|---|---|
| `Overdue n` | ขั้นถัดไปเลยวันที่คาดไว้ (CR-02 due) | List / In process |
| `Needs phase n` | โพสต์ที่ resolve Phase ไม่ได้ (CR-03) | ทุก tab |
| `Shipment overdue n` | shipment ของ deal เลย Ship by (CR-11 §4.10) | List / In process |
| `Metrics due n` | โพสต์ถึง D+7 แต่ยังไม่มีตัวเลข (CR-11 §4.12 — แสดงเมื่อ R5 ของ CR-11 เสร็จ) | Complete |
| `Docs to collect n` | deal ที่มีงวดจ่ายสถานะ Missing docs (นับ deal) · คลิกขวาสุดของ chip มีลิงก์ `Open in Payments` | Complete (ส่วนใหญ่) |

- **ตัด** `Unpaid after posting` และ `Payment overdue` ออกจาก Deals ทั้งหมด (chip · ⚠ column · Workload by PIC ใน By campaign เปลี่ยนคอลัมน์ "Unpaid after posting" → **"Docs to collect"**)
- คอลัมน์ ⚠ ในตาราง: ตัวเลข = จำนวนเหตุผลจาก chip ข้างบนเท่านั้น · hover = รายการเหตุผล (เช่น "Metrics due · 1 post") · ไม่มีเหตุผล = ว่าง
- ชื่อ chip ใช้ชื่อเดียวกับ Dashboard › Operations › To do (CR-11 §4.8) เพื่อให้คนเห็นคำเดียวกันทุกที่
