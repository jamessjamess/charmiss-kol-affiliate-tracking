# CR-26 — Dashboard: Budget vs Actual · KPI · Team workload

ใช้กติกาถาวรใน CLAUDE.md · หลัง CR นี้ถือว่า **module Dashboard ครบ** (แก้ต่อเฉพาะบั๊ก)

## 1. เป้าหมาย
- เห็นว่าแต่ละเดือนใช้งบได้ตามแผนไหม: **เกิน** (ใช้งบเกิน) หรือ **ขาด** (โพสต์ไม่ทัน = Engagement ที่คาดไว้ก็ไม่ทัน)
- KPI อ่านแล้วไม่สับสนเรื่องจำนวน deal
- By campaign สรุปงานรายคนได้ในตารางเดียว

## 2. เดิม → ใหม่
- All campaigns ไม่มีกราฟงบตามเวลา → + **Budget vs Actual by month** (§3.2)
- KPI 5 ใบ (Campaigns · Deals · Committed · Paid · KOLs engaged) → **4 ใบ: Campaigns · Committed · Paid · KOL & Affiliate engaged** (§3.1)
- "401 deals" กับ "278 committed deals" ดูขัดกัน → แยกนิยามให้เห็นในการ์ดเดียว (§3.1)
- By campaign › Workload by PIC (Open · Overdue · Docs · Committed) → **Team workload** สรุปงานรายคน (§3.4)
- Operations: แถว Pay KOL ไม่มีปุ่ม · แถว Ship samples ไม่มี Set date → แก้ (§3.5)

### 3.2 Budget vs Actual by month
**ตำแหน่ง:** All campaigns ต่อจาก KPI (เต็มความกว้าง) · By campaign ต่อจาก Phase budget (กรองเฉพาะ Campaign / Phase ที่เลือก)

**การคำนวณ** — `rules.budgetVsActualByMonth(state, {range, statuses, campaignId?, phaseId?})` ตัวเดียว (กราฟ + table view + Export)
| ค่า | นิยาม |
|---|---|
| **Budget** (แผน) | งบของแต่ละ Phase เกลี่ยตามจำนวนวันของ Phase ที่ตกในเดือนนั้น (Phase ไม่มีงบ → ใช้งบ Campaign ที่ยังไม่แบ่ง เกลี่ยตามช่วง Campaign) · เฉพาะ Campaign ที่ Approved และผ่านตัวกรอง Status |
| **Posted** (Actual) | Total cost ของ committed deal ที่ **Post date แรก** อยู่ในเดือนนั้น |
| **Upcoming** | committed deal ที่ยังไม่โพสต์ → เดือนของ Post due · ถ้า Post due ผ่านไปแล้ว = **Late** (อยู่เดือนเดิม · แสดงลายเฉียง) |
| No post date | committed deal ที่ไม่มีทั้ง Post date และ Post due → ไม่อยู่ในกราฟ · บรรทัดใต้กราฟ "฿x committed has no post date · Set dates" |
| **Variance** | เดือนที่ผ่านแล้ว: Posted − Budget · เดือนนี้และอนาคต: (Posted + Upcoming) − Budget |
- ไม่ใช้วันจ่ายเงิน · ใช้ช่วงวันที่จากตัวกรองด้านบน (This year = ม.ค.–ธ.ค.)

**การแสดงผล**
- toggle **Monthly** (default) / **Cumulative**
  - Monthly: แท่งต่อเดือน = Posted (ทึบ) + Upcoming (สีเดียวกัน จาง) + Late (ลายเฉียง) ซ้อนกัน · **Budget = เส้นขีดแนวนอนสีเข้มบนแต่ละเดือน** (ไม่ใช้แท่งคู่)
  - Cumulative: เส้นสะสม Budget (สีเข้ม) เทียบพื้นที่สะสม Posted + เส้นประ Posted + Upcoming · เห็นว่าตามแผนหรือช้า
- ใต้ชื่อเดือนแสดงสถานะสั้น: **Over ฿x** (แดง · เกิน 105% ของ Budget) · **Behind ฿x** (ส้ม · เดือนที่ผ่านแล้ว < 85%) · ระหว่างนั้นไม่แสดง
- บรรทัดสรุปบนกราฟ: "To date: Posted ฿x of ฿y planned (z%) · Behind ฿a" (หรือ Over) · "Rest of year: ฿b committed upcoming vs ฿c planned"
- tooltip ต่อเดือน: Budget · Posted · Upcoming · Late · Variance · 3 Campaign ที่ใช้มากสุด
- ปุ่มเหมือนการ์ดอื่น: table view (Month · Budget · Posted · Upcoming · Late · Variance · %) · download · expand
- สีใช้ token เดิมของแอป (น้ำเงิน On going สำหรับ Posted / Upcoming · ink เข้มสำหรับ Budget) · แดง / ส้ม ใช้เฉพาะข้อความสถานะ · ผ่าน Light / Dark

### 3.4 By campaign
- + **Budget vs Actual by month** (ตาม §3.2 กรอง Campaign / Phase) ต่อจาก Phase budget
- Phase budget แถว **Unscheduled ฿98,500**: + ข้อความ "n deals have no post date · Set dates" (ลิงก์ไป Deals กรองไว้)
- **Team workload** (แทน Workload by PIC) — ตารางต่อคน:
  | Assigned to | Partners | Open deals | Posted | Post overdue | No post due | Cancelled | Committed | Docs to collect |
  |---|---|---|---|---|---|---|---|---|
  - Partners = จำนวน KOL / Affiliate (ไม่ซ้ำ) ใน Campaign นี้ · Open = ยังไม่ Posted / Cancel · **Post overdue** = Post due < วันนี้ และยังไม่โพสต์ · No post due = Open ที่ไม่มี Post due
  - แถว "No PIC" → **"Not assigned"** + ลิงก์ `Assign` (ไป Deals กรอง deal ที่ไม่มีคนดูแล)
  - คลิกแถว = Deals กรองตามคน + Campaign · แถว Total ท้ายตาราง · เรียง Open deals มาก → น้อย
  - Operations › Team load (CR-24) ใช้ฟังก์ชันนับเดียวกัน (`rules.teamWorkload`)

### การตัดสินใจ (ตาม §6 หรือที่ spec ไม่ระบุ)
1. ไม่มีไฟล์ CLAUDE.md → ใช้กติกาถาวรเดิม
2. Anchor ใน spec มาจากข้อมูลจริงของผู้ใช้ (8 campaigns) · seed (This year · All except cancelled): Committed ฿1,783,579 of ฿2,748,400 · Paid ฿774,579 · 300 deals = List 37 + In process 33 + Complete 230 · committed 263 · Avg ฿6,782 · ยังไม่ commit 37 · KOL & Affiliate engaged **237** — ตัวเลข "KOLs engaged" เดิม (241 ในภาพ) นับจาก **committed deal อยู่แล้ว** ไม่ได้นับจาก deal ทั้งหมด
3. แผน (Budget): งบ Phase เกลี่ยตามวัน · งบ Campaign ที่ไม่ได้แบ่งให้ Phase (ทั้งก้อนถ้าไม่มี Phase ไหนมีงบ) เกลี่ยตามช่วง Campaign · เลือก Phase = งบ Phase นั้นอย่างเดียว · Campaign ที่ไม่มี Phase มีวันที่ = ไม่มีเส้นแผน
4. Posted ใช้ Total cost ทั้ง deal ในเดือนของ Post date แรก (ไม่แบ่งตามโพสต์) · Post due = วันคาดของโพสต์แรกที่ยังไม่โพสต์ ไม่มีจึงใช้ Post due ของ deal
5. Variance เดือนนี้และอนาคต = Posted + Upcoming + **Late** − Budget (Late ยังไม่โพสต์แต่ยังต้องจ่าย)
6. Over ใช้ได้ทุกเดือน (รวมเดือนอนาคตที่จองเกิน) · Behind เฉพาะเดือนที่ผ่านแล้ว · เดือนที่ไม่มีแผนแต่มีเงิน = Over
7. "To date" = แผนถึงวันนี้ (นับรายวัน) เทียบ Posted ถึงวันนี้ · ป้าย Rest of year (This year) · Rest of period (preset อื่น) · Rest of campaign (By campaign)
8. By campaign: เดือนของ Campaign / Phase ขยายไปถึงเดือนที่ deal อยู่ได้ไม่เกิน 3 เดือนแต่ละข้าง · ไกลกว่านั้นนับในบรรทัด "posted or due outside these months" (seed มี ฿4,400 · 3 deals ปี 2024)
9. เลือก Phase: deal = deal ที่โพสต์แรกอยู่ใน Phase นั้น
10. "Set dates" ใต้กราฟ → Deals ตัวกรองใหม่ "Committed · no post date" (ตรงกับยอดใต้กราฟทุกบาท · All campaigns → ทุก Campaign) เพราะตัวกรอง Unscheduled เดิมไม่จับ deal ที่เลือก Phase เอง · แถว Unscheduled ของ Phase budget → Deals › Unscheduled เหมือนเดิม · ลิงก์เหล่านี้ตั้ง PIC = All
11. Team workload: Partners นับจาก deal ที่ไม่ Cancel · Committed = เงิน committed ทั้งหมดของคนนั้น (ไม่ใช่เฉพาะ open) → Total = Committed ของ Campaign · Post overdue / No post due นับเฉพาะ open · Not assigned อยู่หลังคนที่ open เท่ากัน · คลิกแถว = Deals ของ Campaign (+ Phase) + คนนั้น
12. Operations › Team load: คอลัมน์ Open deals มาจาก `R.teamWorkload` · คอลัมน์อื่น (Overdue · Due this week · No due date · Stuck · Waiting on us) ยังมาจาก Work queue
13. Mark paid ในแถว Pay KOL: ใช้สิทธิ์เดียวกับหน้า Payments (Simple: Admin · KOL Manager · Accounting · Staff ที่เป็น PIC ของ deal · Full: payment.paid) — เดิมเช็ก payment.paid อย่างเดียว Staff (เช่น Pang) จึงไม่เห็นปุ่ม
14. Set date ของ Ship samples: โค้ดเดิมแสดงเมื่อไม่มี Ship by และผู้ดูแก้ shipment ได้ — seed ไม่มี shipment รอส่งของ Pang จึงทดสอบด้วย shipment สมมติ: เห็นทั้ง Admin และ Pang · Set date แล้วบันทึก ship_by_date
15. "since post n d" ใช้กับ Pay KOL / Enter metrics ที่โพสต์แล้ว · Pay KOL ก่อนโพสต์ (มัดจำ) แสดงวันเหมือนเดิม
16. Monthly / Cumulative และ table view ไม่จำข้ามการเปิดหน้า (เริ่ม Monthly ทุกครั้ง)
