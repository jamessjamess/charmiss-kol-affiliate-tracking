# CR-28 — Deal modal: tab bar เสมอ

ใช้กติกาถาวรใน CLAUDE.md

## 1. ปัญหา (จากภาพ)
- D000331 เซเว่นเกิร์ล (เปิดจาก Pipeline): มี tab bar Overview · Costs & payment · Timeline & content · Shipments & posts · History ✓
- D000376 aaahcna: **ไม่มี tab bar** · เห็นแค่การ์ด Timeline + Content plan ใต้ Journey · modal กว้างกว่าและเลื่อนเลยหัวการ์ด Journey
- สาเหตุที่น่าจะเป็น: การเปิดแบบเจาะจงส่วน (เช่น ลิงก์ View timeline · Set date ใน Operations · ลิงก์จาก Payments / Shipments / Dashboard) ใช้ทาง render แยกที่แสดงเฉพาะ section นั้น หรือยังเหลือ render แบบเก่าจาก CR-20

### 1.1 บั๊ก UI ที่เจอเพิ่ม (D000377 bam.bss · ทำก่อนข้ออื่น)
- tab bar **ถูก render แล้ว** แต่เห็นแค่ครึ่งบนของตัวอักษร (บรรทัดจางๆ ใต้ Journey) · การ์ด Timeline ทับอยู่ → **กด tab ไม่ได้**
- deal ที่ไม่มีแถบเตือน (D000331 เซเว่นเกิร์ล) tab bar ปกติ · deal ที่มี **2 แถบเตือน** (Missing: Rate card + Post due 25/10 is before this campaign starts) ผิด → น่าจะเกิดจากความสูงส่วนบนเพิ่มขึ้น แล้ว tab bar (sticky) คำนวณ `top` / ความสูงจากค่าตายตัว หรือมี `overflow: hidden` / `height` คงที่ ทำให้ถูกตัด และ z-index ต่ำกว่าเนื้อหา tab
- ภาพที่ 1 ของ CR นี้ (aaahcna ที่ดูเหมือน "ไม่มี tab") อาจเป็นบั๊กเดียวกัน — ให้ตรวจก่อนแล้วจดใน report ว่าเป็นสาเหตุเดียวกันหรือไม่

## 2. เดิม → ใหม่
- มีหลายทางเปิด Deal modal · บางทางไม่มี tab → **ทางเปิดเดียว `openDealModal(dealId, { tab, focus, source })`** ใช้ทุกที่
- การเปิดแบบเจาะจงส่วน = **เลือก tab นั้น** (tab bar ยังอยู่) ไม่ใช่ render แค่ section

## 3. Spec
- `openDealModal(dealId, { tab = last used | 'overview', focus?, source })`
  - `tab`: `overview | costs | timeline | shipments | history`
  - `focus`: ช่องที่จะเลื่อนไป + highlight 1.5 วินาที (เช่น `post_due` · `ship_by` · `rate_card`)
  - `source`: หน้าที่เปิดมา (ใช้กับ ‹ › และการกลับหน้าเดิม CR-27 §3.3)
- **ทุกจุดที่เปิด deal ต้องเรียกฟังก์ชันนี้** — ให้ค้นในโค้ดทั้งหมด (Pipeline · Table · Operations ทุกปุ่ม/ลิงก์ · Dashboard · Payments · Payment details · Shipments · KOL modal › Deals & history · New deal `Add & open first` · Data to fix `Fix` · การ์ด View costs / View timeline) แล้ว **ลบ render ทางอื่นที่เหลือ**
- โครงสร้างคงที่ทุกครั้ง: Header (sticky) → แถบ Missing (ถ้ามี) → Journey + payment strip → **tab bar (sticky ใต้ header เมื่อเลื่อน)** → เนื้อหา tab
- **แก้ layout tab bar (§1.1):**
  - tab bar เป็นแถวปกติใน flow (ไม่มี height ตายตัว · ไม่มี overflow: hidden ที่ตัดตัวอักษร · min-height 44px)
  - sticky ใช้ `top` = ความสูงจริงของ header (วัดด้วย ResizeObserver หรือใช้ CSS variable ที่อัปเดตเมื่อ header เปลี่ยน) · **ไม่อิงความสูงของแถบเตือน**
  - z-index สูงกว่าเนื้อหา tab และต่ำกว่า header · พื้นหลังทึบ (ไม่โปร่ง) + เส้นล่าง
  - แถบเตือน (Missing · Post due warning) อยู่ **ใน flow เหนือ Journey** ไม่ใช่ absolute / sticky · มีกี่แถบก็ดันเนื้อหาลงตามจริง
  - ทดสอบ: 0 / 1 / 2 / 3 แถบเตือน · หน้าจอ 1024 / 1440 · ก่อน / หลังเลื่อน · ทุก tab คลิกได้และเห็นตัวอักษรครบ
- ขนาดคงที่ `min(1400px, 94vw)` · เปิดแล้ว scroll อยู่บนสุด (ถ้ามี `focus` ให้เลื่อนไปช่องนั้นหลังเลือก tab)
- ‹ › เปลี่ยน deal: คง tab ปัจจุบัน
- mapping ลิงก์เดิม → tab: View timeline / Set date / Post due → `timeline` · View costs / Rate card / Pay KOL → `costs` · Ship by / Mark shipped / Add products → `shipments` · Fix (Missing: CTA · Pillar) → `overview`

## 6. Decisions (แก้ได้)

## หมายเหตุการ implement (09/10/2026)
- **สาเหตุ (§1.1 · ตรวจแล้ว):** tab bar (`.dm-tabs`) เลื่อนข้างได้ (`overflow-x:auto`) จึงเป็น scroll container อยู่ใน body ที่เป็น flex column · flex item ที่เป็น scroll container หดได้เกือบ 0 · เมื่อเนื้อหายาวกว่า modal (มีแถบ Missing / คำเตือน) tab bar ถูกบีบเหลือ **7–10px** (วัดจริง: deal ไม่มีแถบเตือน = 46px · มี 1 แถบ = 10px · 3–5 แถบ = 7px) → เห็นครึ่งบนของตัวอักษร การ์ดถัดไปทับ กดไม่ได้ · ภาพ aaahcna ที่ "ไม่มี tab" = **บั๊กเดียวกัน** (บีบจนแทบมองไม่เห็น) ไม่ใช่ทาง render แยก — Deal modal มีทาง render เดียวอยู่แล้ว (`viewHTML` วาด tab bar ทุกครั้ง)
- **แก้ CSS:** ทุกส่วนใน body ไม่หด (`flex-shrink:0`) · tab bar min-height 44px (จริง 49px) · `overflow-y:hidden` (ไม่ตัดตัวอักษร) · พื้นทึบ + เส้นล่าง · z-index เหนือเนื้อหา tab ใต้ header · sticky ที่ขอบบนของส่วนที่เลื่อน ซึ่งเริ่มใต้ header พอดี (header ไม่อยู่ในส่วนที่เลื่อน จึงไม่ต้องวัดความสูง header และไม่อิงแถบเตือน) · แถบ Missing / คำเตือนอยู่ใน flow เหนือ Journey · modal ขนาดคงที่ `min(1400px, 94vw)` × `92vh` (≥ 768px · มือถือเต็มจอเหมือนเดิม)
- **`KT.screens.deals.openDealModal(id, { tab, focus, source, nav, after, backKol, missing, postfix })`** = ทางเปิดเดียว · tab: overview · costs · timeline · shipments · history (ไม่ส่ง = tab ล่าสุด) · focus: เลื่อนไปช่อง + highlight 1.5 วินาที (post_due · ship_by · rate_card · expected_… — แถวใน Timeline มี `data-fk`) · ชื่อเดิม `openOver` ในตัวส่งออก = ฟังก์ชันเดียวกัน
- **ทุกจุดเรียก `openDealModal`:** Shipments · Payments (Open deal · Post evidence) · Payment details (Deal ID) · Operations (แถวงาน · Data to fix › Fix) · Dashboard (Cancelled deals) · KOL modal (Deals & history · ← Back to deal) · Settings › Data issues · Move stage › Edit shipment · ภายในหน้า Deals (Pipeline · Table · Performance · New deal › Add & open first) ใช้ `select` → `renderPanel` → `viewHTML` เดียวกัน
- **mapping:** แถวงานใน Operations: Ship samples / metrics → Shipments & posts (ไม่มี Ship by → focus ช่องนั้น) · Pay KOL → Costs & payment · งานของ deal ที่มีวันที่ (Set date · Post due) → Timeline & content + focus ช่องวันนั้น · Fix (Missing: CTA · Pillar · …) → Overview (ฟอร์มเปิดที่ช่องนั้นตาม CR-24) · Payments → Costs & payment · Shipments → Shipments & posts · Move stage › Edit shipment → Shipments & posts + Ship by

### การตัดสินใจ (ตาม §6 หรือที่ spec ไม่ระบุ)
1. ไม่มีไฟล์ CLAUDE.md → ใช้กติกาถาวรเดิม
2. deal ในภาพ (D000331 · D000376 · D000377) เป็นข้อมูลจริงของผู้ใช้ ไม่มีใน seed → ทดสอบด้วยข้อมูลสมมติ D900376 (aaahcna · Brief · prepaid · shipment ไม่มี Ship by · ไม่มี CTA) และ D900377 (bam.bss · Confirm QT · ไม่มี Rate card · Post due 25/10 ก่อน Campaign เริ่ม 01/11 = แถบ Missing + 2 คำเตือน) + deal ใน seed ที่มีแถบ 0 / 1 / 5
3. `top` ของ sticky ไม่ใช้ ResizeObserver: header อยู่นอกส่วนที่เลื่อน tab bar จึงติดใต้ header เสมอ (วัดแล้ว: ขอบบน tab bar = ขอบล่าง header ทุกกรณี)
4. ความสูง modal คงที่ 92vh (spec ระบุความกว้าง) เพื่อให้ "ขนาดเท่ากัน" ทุกครั้งที่เปิดและไม่กระตุกเมื่อสลับ tab
5. ‹ › คง tab ปัจจุบัน (tab ล่าสุดถูกจำ CR-22) — ทดสอบแล้ว
